# Gate 4 · A-47 执行提示词：让 flip 同时写 stride，解锁零拷贝

> A-46 已把 bootArm 六步跑通（`boot_steps=123` 含 64，`gIopXeFlip=1`/`gIopXeDefer=1` 读回都是 1），
> 唯一挡住零拷贝的是**一个等号**：
>
> ```
> if (qr == kIOReturnSuccess && q.kva && q.pitch == P && …)   // nvrm-accel.cpp:2477
>                              ↑ 12480        ↑ 12544
> ```
>
> CA 的 IOSurface 行距 **12544**（3120×4=12480 按 256 字节对齐补到 12544），scanout 行距 **12480**。
> 面板是 3120 宽 ⇒ 12480 不是 256 的整数倍 ⇒ 上游"pitch 天然相等"的假设在我们这块屏上不成立
> （他们的面板 2560×4 = 10240 = 256×40，正好相等）。
>
> **本关改一处：flip 的时候把 `PLANE_STRIDE` 一起写掉。**

---

## 0. 依据（四条，全部已在现场核实）

### 0.1 单位：stride 寄存器 = 行字节数 / 64

我们自己的代码就是这么用的（`11-native/xenative.cpp`，A-10/A-11 那轮已经跑通过）：

```c
#define PLANE_STRIDE_1_A     0x70188
fStrideBefore = fReg[PLANE_STRIDE_1_A / 4];
fReg[PLANE_STRIDE_1_A / 4] = NAT_ROW / 64;      /* 写入：行字节/64 */
…
fReg[PLANE_STRIDE_1_A / 4] = fStrideBefore;     /* 还原 */
```

`NMIntelFB` 的读法与之互证：`fRowBytes = stride * 64;  // linear planes count the stride in 64-byte units`

⇒ 12480/64 = **195**（当前），12544/64 = **196**（需要）。

### 0.2 三个平面寄存器的偏移（同一寄存器块）

```c
PLANE_CTL(0) 0x70180   PLANE_STRIDE(0) 0x70188   PLANE_SIZE(0) 0x70190   PLANE_SURF(0) 0x7019C
```

accel 已有 `NV_PLANE_SURF_A 0x7019cu`；本关新增 `#define NV_PLANE_STRIDE_A 0x70188u`。

### 0.3 只改一处：`nvAccelXeFlipArm`（`:1707`）

我们的帧走的是 `performTransaction → defer worker → nvAccelXeFlipArm`。
**不要**动 `nvAccelXePresent`（`:2065-2145`，`gCntPresentPhysWrites`）—— 那是 KMS 适配器的 present 路径，
本机 `phase=%00` 下不在场，动它只会增加风险面。

### 0.4 为什么现在才需要改

上游的面板 2560 宽，`q.pitch == P` 天然成立，所以 flip 从来不用管 stride。
我们的 3120 宽打破了这个假设。这是**上游没有覆盖的场景**，改动自负、但可回滚。

## 2. 改动（一处函数，四处小改）

文件：`~/src/NvGfx-5a19a73f36249efb99c44c3f9cb34603ef0c0eb8/kexts/NVRM/accel/nvrm-accel.cpp`
（**注意是这棵树，不是 `NvGfx-xe-2.6.2`** —— A-45 已证后者不是装机来源）

### 2.1 加一个常量（放在 `#define NV_PLANE_SURF_A 0x7019cu` 附近）

```c
#define NV_PLANE_STRIDE_A 0x70188u		/* PLANE_STRIDE_1_A: row bytes / 64, 11 bits */
```

### 2.2 `nvAccelXeFlipArm` 里：arm 之前写 stride，失败时一并还原

现有关键三行（`:1766-1779` 附近）：

```c
    const uint32_t f0 = gDispMmio[NV_DISP_FRAME_COUNTER / 4];
    const uint32_t previousSurf = gDispMmio[NV_PLANE_SURF_A / 4];
    gDispMmio[NV_PLANE_SURF_A / 4] = (uint32_t)gXeFlipGgtt[slot];	/* the arming write */
    …
        gDispMmio[NV_PLANE_SURF_A / 4] = previousSurf;
        (void)gDispMmio[NV_PLANE_SURF_A / 4];
```

改成：

```c
    /*
     * The plane has its own stride and it has to agree with the surface we arm.
     * CoreAnimation allocates its IOSurface rows 256-byte aligned, so a 3120-wide
     * panel gets pitch 12544 while the firmware console scans 12480 -- and the
     * deferred flip in performTransaction() refuses to run unless q.pitch == P.
     * Programming the stride with the surface makes the two equal, which is what
     * this panel needs; on the 2560-wide panels upstream tested the values already
     * matched and this write is a no-op.  Restored with the surf on every exit.
     */
    const uint32_t strideReg = (pitch % 64u == 0u && (pitch / 64u) <= 0x7FFu) ? (pitch / 64u) : 0u;
    const uint32_t f0 = gDispMmio[NV_DISP_FRAME_COUNTER / 4];
    const uint32_t previousSurf = gDispMmio[NV_PLANE_SURF_A / 4];
    const uint32_t previousStride = gDispMmio[NV_PLANE_STRIDE_A / 4];
    if (strideReg) gDispMmio[NV_PLANE_STRIDE_A / 4] = strideReg;
    gDispMmio[NV_PLANE_SURF_A / 4] = (uint32_t)gXeFlipGgtt[slot];	/* the arming write */
    …
        if (strideReg) gDispMmio[NV_PLANE_STRIDE_A / 4] = previousStride;
        gDispMmio[NV_PLANE_SURF_A / 4] = previousSurf;
        (void)gDispMmio[NV_PLANE_SURF_A / 4];
```

**要点**：还原顺序是**先 stride 后 surf**（先把行距放回旧值，再把旧画面放回来，中间不会出现"新行距 + 旧缓冲"的瞬间组合）。
若 `strideReg` 为 0（pitch 不是 64 倍数或超 11 位），**不写 stride、行为与改动前完全一致**。

自检：

```bash

grep -n "NV_PLANE_STRIDE_A" $F            # 期望 4 处：1 个 define + 写 + 两次读
grep -c "previousStride" $F               # 期望 2
grep -n "gXeFlipUncertain = s" $F         # 失败分支仍在（不要动它）
```

**门 2：`NV_PLANE_STRIDE_A` 恰好 4 处、`previousStride` 2 处、`gXeFlipUncertain` 分支未动。**

> 若 `nvAccelXeFlipArm` 里还有**第二条**早退/失败路径（`nvAccelXeFlipWaitIdle` 失败、`mapRc` 失败），
> 检查它们是否发生在 arm **之前**：arm 之前就返回的，不需要还原 stride（那时还没写）。
> 只有 arm 之后、确认锁存之前的失败路径才需要，**只有一处**（`if (!latched)`）。

## 4. 判决：flip 有没有真的接管

```bash
L=~/xegfx-log/A-47
for i in $(seq 1 40); do grep -qE "OK: frames are reaching the panel" /var/log/xegfx-bringup.log 2>/dev/null && break; sleep 6; done
sudo tail -5 /var/log/xegfx-bringup.log

# 若 iop_ok 没动，手工 kickstart 一次（A-44 结论 6）
pgrep -x WindowServer >/dev/null && [ "$(sudo sysctl -n debug.xegfxaccel_iop_ok)" = "0" ] && \
  sudo launchctl kickstart -k system/com.apple.WindowServer && sleep 20

echo "=== 平面寄存器（改动后）==="
sudo log show --last 30m --predicate 'eventMessage CONTAINS "PLANE ctl="' 2>/dev/null | tail -2

echo "=== 计数器（关键）==="
for k in iop_ok iop_flip iop_flips iop_xe_flips iop_xe_flip_miss iop_xe_flip_fail iop_xe_defer_queued iop_xe_defer_dropped iop_copy_sum_us; do
  printf "%-22s %s\n" "$k" "$(sudo sysctl -n debug.xegfxaccel_$k 2>/dev/null)"
done | tee $L/counters.txt

echo "=== 10 秒帧数 / 拷贝是否还在长 ==="
a=$(sudo sysctl -n debug.xegfxaccel_iop_ok); c=$(sudo sysctl -n debug.xegfxaccel_iop_copy_sum_us)
sleep 10
b=$(sudo sysctl -n debug.xegfxaccel_iop_ok); d=$(sudo sysctl -n debug.xegfxaccel_iop_copy_sum_us)
echo "fps=$(( (b-a)/10 ))   copy_sum_us delta=$((d-c))"
```

判读：

| 现象 | 结论 |
| --- | --- |
| `iop_xe_flips` / `defer_queued` 增长、`copy_sum_us` **停止增长**、画面正常 | **零拷贝成立** |
| 计数增长但**画面斜切/错位** | stride 值或顺序不对 → **立即回滚** |
| `copy_sum_us` 仍在长、`xe_flips` 为 0 | flip 仍被别的条件挡（贴 `counters.txt` + K6 行） |
| 黑屏 | 立即回滚 |

**画面必须由用户目视确认**（`screencapture` 在 SSH 下不可用）。

## 8. 铁律

1. **只改 `nvAccelXeFlipArm`**；不动 present 路径（`:2065-2145`）、不动拷贝路径、不动 bootArm。
2. stride 必须在 arm **之前**写；还原顺序 **先 stride 后 surf**。
3. `pitch % 64 != 0` 或 `pitch/64 > 0x7FF` 时**不写 stride**（保持旧行为）。
4. 画面一斜切立即回滚（一条命令 + 重启）。
5. 构建必须在 `NvGfx-5a19a73f…` 树 + `OGKM=open-gpu-615.78.08`。
6. 判据以用户目视为准。
