## 3. 两处偏差（都已查清，均未自行处置）

### 偏差 A：`xattr -cr /Library/GPUBundles` 回 `Operation not permitted`（第 4.3 步最后一条）

```
xattr: [Errno 1] Operation not permitted: '/Library/GPUBundles'
```

根因：目录本身带 SIP 保护标记
```
com.apple.rootless: KernelExtensionManagement   （ls -ldeO 显示 restricted）
```
这是 kext 安装路径的系统级标记，**不可也不该去掉**。关键点是它对内容没有影响：

```
$ sudo xattr -lr /Library/GPUBundles
/Library/GPUBundles: com.apple.rootless: KernelExtensionManagement     ← 只有这一行
```

即所有子项（11 个文件 + bundle 内全部内容）**零扩展属性**，没有任何 quarantine。
处置：不动，继续（提示词第 5 节停机条件里没有这一项，属计划外但无风险）。

### 偏差 B：`codesign -v NVMTLDriver.bundle` 报 `a sealed resource is missing or invalid`

```
a sealed resource is missing or invalid
file added: /Library/GPUBundles/NVMTLDriver.bundle/Contents/MacOS/air-runtime/libLLVM.dylib
```

**对源目录跑同一条命令，报的是一模一样的错**：

```
$ codesign -vvv ~/_xegfx-old-20261030/GPUBundles/NVMTLDriver.bundle
a sealed resource is missing or invalid
file added: .../Contents/MacOS/air-runtime/libLLVM.dylib
```

即这是**源产物自带的历史状态**：`libLLVM.dylib`（150 MB）是在 bundle 签名之后才被放进
`air-runtime/` 的，未进封条（`Sealed Resources … files=0`）。拷贝逐字节一致，不是本次引入。

主体签名本身是好的：
```
Identifier=com.nullmoth.NVMTLDriver
Signature=adhoc（flags=0x4000002 adhoc）
CDHash=4fd05a0e2981c8bead982482ce3413e8dadc2592
Executable=…/Contents/MacOS/NVMTLDriver  Format=bundle with Mach-O thin (x86_64)
```

提示词铁律「不重签」，且这是 Metal 侧（本关不判定）的变量，故**未处置**。留作 Gate 4 的待办：
若到时 NVMTLDriver 因封条校验被 dyld 拒绝加载，需要 `codesign -f -s -` 对整个 bundle 重签一次
（把 `air-runtime/libLLVM.dylib` 纳入封条），那是一次明确的变量变更，应在 Gate 4 的基线里先声明。

## 4. 交付问题：没有加速器 kext 时，`MTLCopyAllDevices` 返回几个设备？

**返回 0 个。**

```
$ ~/xegfx-probes/mtlprobe
MTLCopyAllDevices count = 0
no device
```

`log show --last 5m | grep -i nvmtl` → **空输出**（5 分钟内系统日志里没有任何 `nvmtl` / `NVMTL` 字样，
连一条插件加载尝试记录都没有）。`log show --last 10m | grep -i mtlprobe` 同样为空。

配套证据：
- `ioreg -rc IOAccelerator` → **零个实例**（整机没有任何 IOAccelerator 对象），
  所以不是"accelerator 在但插件没匹配上"，而是加速器服务根本不存在。
- `ioreg -l | grep MetalPluginName` 有 2 处命中，但**都不是本 GPU**：它出现在一块
  `vendor-id=02100000`(`0x10de` NVIDIA) / `device-id=10680000` 的 PCI 设备上的
  `IOCompatibilityProperties` 里，值是 `"IOGLBundleName"="AppleMetalGLRenderer"`,
  `"MetalPluginName"="AGXMetalA12"` —— 是注入的兼容性属性描述（预期会被发布的形态），
  不是真实的加速器实例，与 8086:7D51 无关，**不能**当 Metal 可用的证据。
- `system_profiler SPDisplaysDataType` 仍无 `Metal:` 行（与 before 一致）。

**对 Gate 4 的含义**：设备枚举确实完全取决于 accel kext 发布的 `MetalPluginName`。
当前 `XeGfxAccel`（IOClass=`NMXAccel`）未装，`MTLCopyAllDevices` 就是 0，且系统连"用户态的
NVMTLDriver 在不在"都不会看一眼 —— 也就意味着**这一关无法提前验证 NVMTLDriver 的封条问题会不会
在 Gate 4 咬人**，必须在 Gate 4 首次加载时第一时间抓 dyld 报错。
