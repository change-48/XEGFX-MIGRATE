# Gate 4 · A-39 执行提示词：补上上游要求的 `gfxrst=4`，再按上游顺序复跑

> 依据：上游 Arrow Lake 面板跟踪（NvGfx issue #12）把 `IGPUConsoleRange` **和 `gfxrst=4`** 并列为
> 拿到内建面板桌面的两个前提。我们有前者，**缺后者**，而 WhateverGreen 正在加载，
> 我们的 `XeGfxIntelFramebuffer : IONDRVFramebuffer` 正好在它 `initFB` hook 的范围内。
>
> **本关只加一个 boot-arg**（EFI 一处），然后按上游顺序复跑并采样。

---

## 0. 依据（两条，都是原文）

### 0.1 上游 issue #12（Arrow Lake 面板）

> "**#14 根因确认**：Apple's IONDRV only accepts a boot console that lies inside a PCI BAR;
> on Meteor/Arrow Lake the GOP framebuffer is in stolen memory." → 新增 `IGPUConsoleRange`。
>
> "**红队发现 WhateverGreen 是共犯**：It hooks `IOFramebuffer::initFB` and, unless boot-arg `gfxrst=4` is set,
> **copies the saved boot console into each new framebuffer on first open**." → 加 `gfxrst=4`。
>
> "**N-201: first desktop on the Intel iGPU** — Apple 原生 IONDRVFramebuffer + IGPUConsoleRange + **gfxrst=4**。"

### 0.2 WhateverGreen 官方 README（`gfxrst` 在 "2nd Boot stage" 一节）

| Boot argument | 说明 |
| --- | --- |
| `gfxrst=1` | Prefer drawing Apple logo at 2nd boot stage instead of framebuffer copying |
| **`gfxrst=4`** | **Disable framebuffer init interaction during 2nd boot stage** |

### 0.3 我们的现状（22:55 实测）

```
nvram boot-args = -v keepsyms=1 -vi2c-force-polling -amfipassbeta amfi_get_out_of_my_way=0x1
                  amfi=0x80 ipc_control_port_options=0 itlwm_cc=CN
grep -c "gfxrst=4" → 0            ← 缺
WhateverGreen 已加载              ← hook 生效中
XeGfxIntelFramebuffer : IONDRVFramebuffer   ← 正是 initFB hook 的目标类
```

**这条链的后果**：WhateverGreen 会在我们 FB 首次 open 时把"保存的开机控制台"拷进新 framebuffer。
这既可能污染内容，也可能让 SkyLight 认为这块显示是"控制台级"的 —— 与上游 N-280 那个
"why SkyLight picks CompositorSW" 的疑问方向一致。

### 0.4 A-38 已经打通的部分（本关不要重做）

```
AGDC state=1、fbmap n=1 [0]id 0x10000051f
IOP: agdc 0x1000007e8 / accel 0x1000007a9 / fb0:0 0x10000051f
Unable to create IOAccelDisplayPipe = 0；newDisplayPipe/initFramebufferResource 都在
surfaceCount 0 → 308
```
**这些保留。** 本关只加 boot-arg，其它变量不动。

## 1. 改 EFI（唯一改动）：给 boot-args 追加 `gfxrst=4`

> `boot-args` 由 OpenCore 的 `NVRAM → Add` 每次开机覆写（本项目已核实），所以必须改 `config.plist`。

```bash
# 1.1 挂载内置 ESP
sudo diskutil mount disk0s1 >/dev/null 2>&1
P="/Volumes/NO NAME/EFI/OC/config.plist"
ls -l "$P"

# 1.2 备份（带时间戳）
sudo cp -p "$P" "$P.bak-before-gfxrst-$(date +%Y%m%d-%H%M%S)"
ls -l "/Volumes/NO NAME/EFI/OC/" | grep config

# 1.3 看当前 NVRAM 里的 boot-args 条目（两处：Delete 与 Add）
plutil -convert xml1 -o - "$P" | grep -n "boot-args" | head
```

**门 1：能看到 `boot-args` 的 Add 条目。** 结构应与 Gate 0 记录一致（xml 约 1361 行 = Add，1396 = Delete）。

```bash
# 1.4 读出当前值（用 plutil 精确定位，不要手抄）
plutil -convert json -o - "$P" | python3 -c "
import json,sys
d=json.load(sys.stdin)
arr=d['NVRAM']['Add']['7C436110-AB2A-4BBB-A880-FE41995C9F82']
for e in arr:
    if e.get('Name')=='boot-args': print('CURRENT:', e.get('Value'))
"
```

把 `gfxrst=4` 追加到该 `Value` 末尾（用 python 改，保留其余全部条目）：

```bash
sudo python3 - <<'PY'
import json, plistlib, shutil
P="/Volumes/NO NAME/EFI/OC/config.plist"
with open(P,'rb') as f: d=plistlib.load(f)
key="7C436110-AB2A-4BBB-A880-FE41995C9F82"
arr=d['NVRAM']['Add'][key]
hit=False
for e in arr:
    if e.get('Name')=='boot-args':
        v=e.get('Value','')
        if 'gfxrst=4' not in v:
            e['Value']=(v.rstrip()+' gfxrst=4').strip()
        hit=True
        print("NEW:", e['Value'])
if not hit:
    raise SystemExit("boot-args entry NOT FOUND -- stop and report")
with open(P,'wb') as f: plistlib.dump(d,f, fmt=plistlib.FMT_XML)
print("written")
PY

# 1.5 校验：语法 + 只多了这一个词
plutil -lint "$P"
plutil -convert json -o - "$P" | python3 -c "
import json,sys; d=json.load(sys.stdin)
k='7C436110-AB2A-4BBB-A880-FE41995C9F82'
print([e['Value'] for e in d['NVRAM']['Add'][k] if e.get('Name')=='boot-args'])
"
```

**门 2：`plutil -lint` OK，且新值 = 旧值 + ` gfxrst=4`，其余词一个不少（`-v keepsyms=1 … itlwm_cc=CN` 全在）。**
不满足 → 从备份恢复，**停手**。

```bash
sudo diskutil unmount disk0s1
sudo reboot
```

```bash
L=~/xegfx-log/A-39; mkdir -p $L

```

**门 3：`gfxrst=4` 在、屏幕正常。** 屏幕不正常 → 回滚 config，重启。

## 3. 按上游顺序复跑（与 A-38 相同，不引入新变量）

```bash
( sudo log stream --predicate 'eventMessage CONTAINS "XEGFX" OR eventMessage CONTAINS "NMXAccel" OR eventMessage CONTAINS "AGDC" OR eventMessage CONTAINS "IOPresentment" OR process == "WindowServer"' > $L/stream.log 2>&1 & )
sleep 2

sudo /usr/bin/kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60 >/dev/null
sudo sysctl -w debug.xegfx_stage=7 >/dev/null
sleep 22
sudo sysctl -b debug.xegfx_results | od -A n -t d4 | tee $L/results.txt    # 期望 0 1 1 1 1 1 1 1

sudo /usr/bin/kmutil load -b org.watchthelight.XeGfxAccel; echo "accel rc=$?"
sleep 3
sudo sysctl -w debug.xegfxaccelfb=3        # 写 3 才会让 gNvScanout=1（A-38 实测，源码 how>=3）
sleep 4

# 四条形态（回归）
sudo log show --last 5m --predicate 'eventMessage CONTAINS "NMXAccel"' 2>/dev/null | grep -E "accepted as head 4|CPU copy target|initFramebufferResource|heads published" | tail -4 | tee $L/shape.txt

# AGDC（开机时已自己起来，这里只确认）
sudo sysctl debug.xegfx_agdc; sudo sysctl debug.xegfx_agdc_fbmap | tee -a $L/agdc.txt
```

**门 4：`results` 全 1 + 四条形态 + AGDC `state=1`/`fbmap n=1`。**

## 4. 判决：重启 WS 后 CA 还崩不崩

**顺序很重要（A-38 的教训）**：`kickstart WS` 会连带结束控制台会话，所以**先 kickstart，再登录，再采样**。

```bash
sudo launchctl kickstart -k system/com.apple.WindowServer
sleep 25

echo "=== A) WS 是否活着、实例数 ==="
pgrep -x WindowServer | wc -l; ps -o etime=,pid= -p "$(pgrep -x WindowServer)" 2>/dev/null

echo "=== B) 有没有 COREANIMATION / half 崩溃 ==="
ls -t /Library/Logs/DiagnosticReports/WindowServer*.ips 2>/dev/null | head -3
sudo log show --last 5m --predicate 'process == "WindowServer"' 2>/dev/null | grep -cE "COREANIMATION|SIGABRT|fixed_frag"

echo "=== C) IOP 双句柄 ==="
grep -oE "agdc 0x[0-9a-f]+|accel 0x[0-9a-f]+" $L/stream.log | tail -4

echo "=== D) 加速器统计 ==="
sudo ioreg -l -w0 -r -c NMXAccel 2>/dev/null | grep -oE '"(surfaceCount|bufferSwapCount|bufferFlipCount|contextGLCount|AccelCaps)"=[0-9]+' | tee $L/perfstats.txt

echo "=== E) 合成栈（活过 25 s 才有意义）==="
sudo sample $(pgrep -x WindowServer) 2 -file $L/ws.txt >/dev/null 2>&1
echo "MTL=$(grep -c 'CA::MTL' $L/ws.txt)  SW=$(grep -cE 'CA::OGL::SW|scanline|draw_polygon' $L/ws.txt)  CompSW=$(grep -c 'CompositorSW::CompositeLayersToDestination' $L/ws.txt)"
```

判读：

| 结果 | 结论 | 下一步 |
| --- | --- | --- |
| WS 活着 + `MTL > 0` + `CompSW = 0` | **GPU 合成成立**（Gate 4 第 3 条）；`gfxrst=4` 是关键 | 记录并收尾 |
| WS 活着但 `CompSW > 0`、`MTL = 0` | 仍软合成；`gfxrst=4` 不是那个杠杆 | 记录，下一关按上游 N-280 的"why CompositorSW"继续 |
| WS 又崩在 `COREANIMATION code 7 / fixed_frag` | CA 已走 Metal，但发射器崩（A-38 同一签名） | 记录；下一步查 plugin 的 `supportsFamily`/half 声明 |
| WS 反复重启 | 立即按 §5 停机 | |

## 5. 停机与回滚

```bash
# 屏幕异常 / WS 反复重启 / 彩噪：
sudo ioreg -l -w0 > $L/ioreg-final.txt
sudo log show --last 5m --predicate 'process == "WindowServer" OR eventMessage CONTAINS "XEGFX"' > $L/log-final.txt 2>/dev/null
sudo nvram xegfx-disp-phase=%00 xegfx-disp-trial=%00 xegfx-disp-expose=%00 xegfx-disp-fail=%01
sudo rm -f /var/db/xegfx/armed
sudo shutdown -r now
```

**回滚 boot-arg**（把备份拷回即可，BootKernelCollections 不用动）：

```bash
sudo diskutil mount disk0s1
sudo cp -p "/Volumes/NO NAME/EFI/OC/config.plist.bak-before-gfxrst-<时间戳>" "/Volumes/NO NAME/EFI/OC/config.plist"
sudo diskutil unmount disk0s1
sudo reboot
```

## 7. 铁律

1. 本关**只改 boot-args**，不改代码、不重编、不动 AGDC/plist。
2. 改 EFI 前必备份、必 `plutil -lint`、必回读确认只多一个词。
3. `kickstart WS` 会结束控制台会话 → 先 kickstart 再登录再采样。
4. `debug.xegfxaccelfb` 必须写 **3**（写 1 时 scanout 门是关的）。
5. 一次一个变量；`armed` 后 120 s 内不重启。
