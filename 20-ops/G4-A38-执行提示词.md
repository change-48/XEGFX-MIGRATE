# Gate 4 · A-38 执行提示词：把 `AGDC_FB_CLASS` 改回上游值，让 AGDC 在这条路上真的起来

> 一句话：A-29 为 S3 那个 KMS 类把 `AGDC_FB_CLASS` 改成了 `"XeGfxFramebuffer"`，
> 而**上游是 `"IONDRVFramebuffer"`**。这条路上 framebuffer 就是 `XeGfxIntelFramebuffer`（IONDRV 子类），
> 所以 AGDC 匹配不到 → `pci 0x0 fb 0x0` → 没有 AGDC → IOP 找不到 display pipe → 软件合成。
>
> **本关只做这一处回退**（恢复上游值），然后验证 AGDC / IOP / 合成三件事。

---

## 0. 上游原文（本关的唯一依据）

`https://raw.githubusercontent.com/watchthelight-labs/NvGfx/xe/kexts/NVRMAGDC/nvrm-agdc.cpp`

```c
#ifdef NMX_XEGFX
// the same AGDC for the Intel GPU over XeGfx (branch xe): IOPresentment pairs a framebuffer with its display pipe only
// through an AGDC service on the GPU, so without one WindowServer finds no pipe for the boot framebuffer (N-249).
// Own class, bundle and sysctl names, because NVRMAGDC loads on the same machine.
extern "C" { KMOD_EXPLICIT_DECL(org.watchthelight.XeGfxAGDC, "0.1", _start, _stop) }
#define NVDADeviceControl XeGfxDeviceControl
#define NVDAGDCLoader     XeGfxAGDCLoader
#define AGDC_FB_CLASS     "IONDRVFramebuffer"      /* ← 上游值 */
#define AGDC_VENDOR       "Intel"
#define AGDC_VENDOR_ID    0x8086
```

关键那句注释：**"IOPresentment pairs a framebuffer with its display pipe only through an AGDC service
on the GPU, so without one WindowServer finds no pipe for the boot framebuffer"** ——
即 AGDC 是 IOP 找 pipe 的**入口**。

### 0.1 我们和它的差别（一处）

| | 值 |
| --- | --- |
| 上游 | `"IONDRVFramebuffer"` |
| 我们的本地树 / 已装二进制 | `"XeGfxFramebuffer"`（A-29 为了 S3 的 `XeGfxIntelKMSFramebuffer` 改的） |

而本关这条路上，framebuffer 是 `XeGfxIntelFramebuffer : IONDRVFramebuffer`（**不是** `XeGfxFramebuffer`）。
所以 A-37 里 `debug.xegfx_agdc` 十次全是 `-1`、`AGDC: no PCI device or no framebuffer yet (pci 0x0 fb 0x0)`、
`fbmap = never scanned` —— **这就是那个偏移的直接后果**。

### 0.2 这也解释了 A-37 的 `surfaceCount = 0`

```
AGDC 起不来 → IOP 找不到这张 FB 的 display pipe → CA 没有可用的呈现目标
           → 继续 CompositorSW 在 CPU 上合成 → 加速器只当"拷贝目标"，不接 surface
```
`AccelCaps = 0`、`surfaceCount = 0`、`bufferSwapCount = 0`、`CA::MTL = 0` 都是同一条链的下游。

## 5. 本关的判决点 1：AGDC 到底起没起来

```bash
for i in $(seq 1 10); do
  sudo sysctl -w debug.xegfx_agdc=1 >/dev/null 2>&1; sleep 1
  s=$(sudo sysctl -n debug.xegfx_agdc 2>/dev/null); echo "agdc $i -> $s"; [ "$s" = "1" ] && break
done
echo "--- fbmap ---"; sudo sysctl debug.xegfx_agdc_fbmap
echo "--- cmds  ---"; sudo sysctl debug.xegfx_agdc_cmds
echo "--- 日志   ---"; sudo log show --last 3m --predicate 'eventMessage CONTAINS "AGDC"' 2>/dev/null | grep -E "AGDC: (UP|slot table|no PCI)" | tail -4 | tee $L/agdc.txt
```

**门 4（本关成败）：`state=1` 且 `AGDC: UP on IGPU — N framebuffer slot(s)`，`fbmap` 形如 `n=1 [0]id 0x…`。**

| 结果 | 含义 | 动作 |
| --- | --- | --- |
| `state=1` + `UP` | 回退正确，AGDC 认到了 `XeGfxIntelFramebuffer` | 进 §6 |
| 仍 `-1` + `no PCI device or no framebuffer yet (pci 0x0 fb 0x0)` | 还有别的匹配障碍 | **停手**，贴 `ioreg -l -w0 -c XeGfxIntelFramebuffer \| grep -E "IOFBDependentID\|vendor-id"` 与日志原文 |
| `-4`/`-5` | attach/start 失败 | 停手，贴原文 |

## 6. 判决点 2：IOP 有没有拿到 pipe（这才是 A-37 缺的那一环）

WS 是在启动时才向 IOP 要 pipe，所以必须重启 WS：

```bash
sudo launchctl kickstart -k system/com.apple.WindowServer
sleep 20

echo "=== A) IOP 设备表：agdc 与 accel 两个句柄 ==="
grep -oE "agdc 0x[0-9a-f]+|accel 0x[0-9a-f]+|fb[0-9]:-?[0-9]+ 0x[0-9a-f]+" $L/stream.log | tail -8 | tee $L/iop.txt

echo "=== B) 失败链（期望归零）==="
grep -c "Unable to create IOAccelDisplayPipe" $L/stream.log
grep -c "Unable to find display pipe for IOFB service" $L/stream.log

echo "=== C) 进去了没有 ==="
sudo log show --last 3m --predicate 'eventMessage CONTAINS "NMXAccel"' 2>/dev/null | grep -E "newDisplayPipe|initFramebufferResource|API armed|XeGfxAccelPresent" | tail -6

echo "=== D) 加速器统计 ==="
sudo ioreg -l -w0 -r -c NMXAccel 2>/dev/null | grep -A12 "PerformanceStatistics" | grep -E "surfaceCount|bufferSwapCount|contextGLCount|AccelCaps" | tee $L/perfstats.txt

echo "=== E) 合成栈 ==="
sudo sample $(pgrep -x WindowServer) 2 -file $L/ws.txt >/dev/null 2>&1
echo "MTL = $(grep -c 'CA::MTL' $L/ws.txt)   SW = $(grep -cE 'CA::OGL::SW|scanline|draw_polygon' $L/ws.txt)"
grep -cE "CompositorSW::CompositeLayersToDestination|CompositorMetal" $L/ws.txt

echo "=== F) WS ==="
ps -o etime=,pid= -p "$(pgrep -x WindowServer)"
```

判读：

| A/B/C 的结果 | 结论 |
| --- | --- |
| `agdc 0x…` 与 `accel 0x…` 都非 0，且 `Unable to create IOAccelDisplayPipe` = 0 | **IOP 拿到了 pipe** → 看 E 的 `MTL` 是否 > 0 |
| AGDC 起来了但 `Unable to create IOAccelDisplayPipe` 仍 > 0 | IOP 仍拒 → 停手，贴 `iop.txt` 与 `0x…` 错误码 |
| AGDC 起来、pipe 起来、`MTL` 仍 0 | CA 仍选软合成 → 这是**第三个独立问题**（合成器选择），照实记录 |
