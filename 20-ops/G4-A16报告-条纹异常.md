## 2. 两个与提示词不符的现场事实（重要）

1. **加速器 personality 真实键名是 `XeGfxAccel`，不是 `NMXAccel`**。按提示词"用真实键名、不要新建"处理：
   `Set :IOKitPersonalities:XeGfxAccel:MetalPluginName`。`NMXAccel` 只是 `IOClass`，所以 `ioreg -c NMXAccel` 照常能查到。
2. **开机不会自动加载 XeGfx**。本次重启后 `debug.xegfx_*` 全部 `unknown oid`、`kmutil showloaded` 里没有 XeGfx，必须手动 `sudo kmutil load -b org.watchthelight.XeGfx` 才起来。这与"每次开机推 stage 即可"的既有认知不同，**A-18 提示词需要写明这一步**。

## 3. 关键新事实：WindowServer 第一次拿到了加速器句柄

推 stage 7 之后：

```
+-o NMXAccel  <class NMXAccel, id 0x100000b02, registered, matched, active>
  +-o IOAccelNMXCarrier
    +-o IOAccelXeGfxDRMClient  { "IOUserClientCreator" = "pid 201, WindowServer" }
```

DRM 客户端共 3 个：`pid 201 WindowServer`、`pid 500/603 iconservicesagent`。
**这是历史上第一次 WindowServer 主动打开 XeGfx 的 DRM 客户端**（此前只有 iconservicesagent，且会 panic）。
`idr_preload` 两处补丁起效：3 个客户端并发打开，**零 panic**（panic 计数 9 → 9）。

`debug.xegfx_results` = `0 1 1 1 -28 1 1 1`（stage 1–7 全绿，与基线一致）。
`/dev/dri/card0`、`/dev/dri/renderD128` 均出现。

## 4. 异常：屏幕横向彩噪条纹（用户报告，14:56 左右）

**现象**：屏幕约上 1/3 处一条横向黑底彩色噪点条纹。

**时间线（来自 kernel log）**

| 时间 | 事件 |
|---|---|
| 14:55:07 | 大量 `xegfx: ioctl 0xc0186473/0xc0106446/0x80104e42/0xc0186475 -> errno 22/19/2/1`，pid 555/583/603/567/706/702/500（各 App 抢着开 DRM 节点，全部失败） |
| 14:55:34 | `NMXAccel: getStampMemory(4096 stamps,16KB)`、`createUserGPUTask init=1` — **加速器开始真正跑 GPU task** |
| ~14:56 | 用户报告出现条纹 |
| 14:57:16 | `NMXAccel: stop` / `teardownDevice`，卸载被拒：`IOAccelNMXCarrier has 32 instances`、`NMXEventMachine 1`、`NMXAccel 1`（`0xdc008018`） |
| 14:58:43 | 重启，回软件合成 |

**判读**：`bufferSwapCount=0`、`bufferFlipCount=0` → 条纹**不是 flip 出来的**，而是 accel 一旦真正提交命令，
GPU 写入的地址区间与扫描输出（`IOFBMemorySize 25958400`、rowBytes 12480）重叠 / GGTT 映射未隔离，
把扫描中的那一段 fb 写花了。这正对应 A-18 要做的 **GGTT flip 栈**：当前驱动没有独立的 flip 缓冲与地址隔离，
"能 attach" ≠ "能呈现"。

即：**A-17 的答案其实已经提前出现 ——WindowServer 确实拿起了加速器，但呈现路径一用就花屏。**
`vmmap | grep -c nvmtl` 没来得及测，但比它更硬的证据（WindowServer 的 DRM 客户端 + 花屏）已经拿到。
