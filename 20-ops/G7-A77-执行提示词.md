# Gate 7 · A-77 执行提示词：阶段 2 第一击 · Tile4 扫描（把 GPU 合成从 13–15ms 往 5ms 压）

> 目标：**阶段 2 开工**。A-74/A-75 的数据显示 GPU 合成一帧 6.49MP 要 13–15ms（mark 段）；
> 前人（ArrowWhatever `docs/page-off-and-compression.md`）的答案是 **Tile4**：
> 「往线性 render target 画要花 Tile4 的 **8–13 倍** GPU 时间」「全屏 pass 画进 scanout
> 从 4.6ms 降到 **1.5–3.4ms**」。本关只做 **Tile4 扫描**这一件事（scanout surface 直接画成 Tile4、
> 平面按帧切布局），**page-off / Device Cache / selector 5–8 一律不碰**（那是 A-78，它依赖
> A-76 未验证的锁纪律改码，本关不带）。
>
> 顺手判一件事：Tile4 装好后帧率若明显涨 ⇒ 帧率瓶颈在 GPU 链；若不动但 mark 段大降 ⇒
> 瓶颈在 WS CPU——这个判定直接决定 A-78 打什么。
>
> 必读：`20-ops/G7-A76报告.md`（锁表、NMI 归因、a76new 勿用的警告）、`G7-A74/A75报告.md`、
> `AI-远程连接说明.md`、`AI-远程调试作业说明.md`。

## 0. 前人依据（照抄数字，不许自己估）

| 项 | 前人实测 | 出处 |
| --- | --- | --- |
| 线性 vs Tile4（ANV 上画 render target） | 线性 **8–13 倍** GPU 时间 | page-off-and-compression.md |
| Tile4 后全屏 pass 画进 scanout | 4.6ms → **1.5–3.4ms** | 同上 |
| 压缩 A/B（整套开齐后的翻页/秒） | 76 → 97–99（本关只做 Tile4，拿不到全部） | 同上 |
| Tile4 开关 | boot-arg `xegfxtile4=0`（从关开始）；`debug.xegfxaccel_iop_xe_tile4` 运行时切；**10s 内切换 >20 次自动关** | 同上 |
| 布局上报 | 插件经 **DRM client selector 2**（mark2 带 tile4 位）告知每个 WS surface 的布局；scanout 打开时直接画成 Tile4，开关时 GPU **原地重排**；平面按每一帧的布局切换 | 同上 |

**机制地图（0024/0026 里 Tile4 相关的 hunk）**：
- accel（0024）：平面布局切换（PLANE 寄存器按帧的 tile 位/步进切换）、GPU 原地重排
  （retile blit）、`iop_xe_tile4` sysctl + boot-arg + 自动关 + 布局切换计数；
- 插件（0026）：**selector 2**（`nvmtl_vk_surface_gpu_mark2(sid, pending, tile4)`，pending=2
  是"仅记录布局"）、扫描 surface 的纹理按 Tile4（optimal tiling）创建、布局变化时通知 accel。

## 1. 铁律（本关新增两条）

1. 通用铁律照 A-76（使用者在场、备份三件套、kill 开关先行、SYSCTL 注册坑、stage 5 偶发 -71）。
2. **源码基线：accel 回到 A-75 快照**（`~/xegfx-log/A-75/nvrm-accel.cpp.a75`——装机版 `fd0bbdc1`
   对应的源码）。**绝不用 `XeGfxAccel.a76new`**（A-76 §6.2：未验证、冻结嫌疑未洗清）。
   5a19 树当前工作区里 A-76 的改码先 stash/revert，落袋为安。
3. **NMI 偶发窗口协议（A-76 归因的新结论，替代"panic 一次即停"）**：
   - 装机后前 3 分钟内，若 panic 形态为 `mp_kdp_enter()` NMI 无应答**且**当时新路径
     （tile4/marks/flip）尚未活跃或全部关闭 → 记录在案、重启重试**一次**；
   - 连续两次、或形态不同（页错误/preemption）、或发生在 3 分钟后 → 停手回滚，如实报告。
4. Tile4 的逃生门三层：sysctl 运行时关 → boot-arg `xegfxtile4=0` → 装回备份件。
   **布局错配的最典型症状是花屏/斜屏（stride 与 tile 模式不符）——用户目视判据放第一位。**

## 2. Part 0 · 零代码：判当前瓶颈在谁身上（30 分钟）

1. **重析 A-74 的 `~/xegfx-log/A-74/sample-p3.txt`**（5328 个主线程样本，不用重跑）：
   按三分类聚合——busy（CA/libvulkan/NVMTL/objc 等用户态执行）、wait
   （psynch/ulock/`isTransactionComplete` 一类内核等待，**分调用者列出前五**）、
   idle（runloop 等定时器/displaylink 节奏）。
   产出：一帧 38.5ms 里 busy/wait/idle 各占多少 ms。
2. 读 A-75 源码快照确认基线（selector 1 / markonly / 计数器都在，`gIopXeMarkOnly` 默认 0）。

**用途**：busy 占大头 ⇒ 本关之后主攻还是 WS CPU（A-78 = Device Cache/描述符）；
wait/idle 占大头（等 GPU 链或 vblank 节奏）⇒ Tile4 收益会直接体现在 fps 上。

## 3. Part 1 · accel 侧 Tile4（0024 的 Tile4 hunk）

按 §0 机制地图，在 A-75 基线源码上：

1. 平面按帧布局切换：defer worker 写 `PLANE_SURF/STRIDE` 时按本帧布局（linear vs Tile4）
   切 tile 位（Xe-LPG 平面 CTL 的 tile 字段 + Tile4 步进语义——**以 0024 的写法为准**，
   我们面板是 pipe A 单平面，比他们双管简单）；
2. 布局切换时的 GPU 原地重排（retile）：照 0024 的 blit 序列；
3. `xegfxtile4` boot-arg（默认开）、`debug.xegfxaccel_iop_xe_tile4` sysctl、
   10s/20 次自动关、布局切换计数（`tile4_switches`、`tile4_auto_off`）；
4. 计数器注册：**本树 SYSCTL 必须显式改名宏 + 注册**（A-76 第一装的坑），
   且 SYSCTL_PROC 型在本树有过不注册的未解之谜（A-76 §2.3）——**新计数器尽量用
   QUAD/INT 型**（A-75 的 markonly 三兄弟是注册成功的先例，照它们的形态写）。

**门 1**：编译通过、装机（NMI 协议护航）、tile4=0 时安全模式无回归
（= A-75 末态：`iop_ok` 增长、flip 正常、fps 26–37）。

## 4. Part 2 · 插件侧 Tile4（0026 的 Tile4 hunk + A-75 插件复活）

1. **重装 A-75 插件**（`~/xegfx-log/A-75/NVMTLDriver.a75new`）：XGDR 连接 + selector 1 marks。
   依据：A-76 已证明 panic 与 marks 无关（marks 死亡周期照样 NMI）；残帧只在 `markonly=1`
   出现，而 markonly **保持默认 0**。marks 通道只是 selector 2 的载体，本关不启用其等待语义。
2. 在 A-75 插件源码上加 0026 的 Tile4 半边：
   - `nvmtl_vk_surface_gpu_mark2`（selector 2：sid + pending + tile4 位，pending=2 仅记录布局）；
   - WS 扫描 surface 的纹理按 **optimal tiling（Tile4）** 创建；布局变化时经 selector 2 通知；
   - 布局开关照前人：`/private/tmp/xemtl-no-*` 一类哨兵风格可以不做（我们用 accel 侧
     sysctl 总开关即可），**但插件创建纹理的布局必须跟 accel 的 tile4 开关联动**
     （开关切换时纹理重建/重排路径要闭环——照 0026）。

**门 2**：`surface_gpu_marks` 增长（selector 2 也在走）；`tile4_switches` 随开关动作变化；
开机默认 tile4=0 的安全模式无回归。

## 5. Part 3 · A/B 测量（本关的判决）

```bash
# tile4 关（基线）→ 开（实验），各 3 轮拖动 25s，同一会话交替
sudo sysctl -w debug.xegfxaccel_iop_xe_tile4=0   # 基线 3 轮
~/xegfx-log/A-74/fps-probe2.sh 25
sudo sysctl -w debug.xegfxaccel_iop_xe_tile4=1   # 实验 3 轮
~/xegfx-log/A-74/fps-probe2.sh 25
sudo sysctl -n debug.xegfxaccel_iop_tl | tail -200        # mark/arm/latch 各段
sudo sysctl -a | grep -E 'tile4|surface_gpu|iop_xe'
```

**门 3（本关成功线）**：

| # | 检查 | 期望 |
| --- | --- | --- |
| 1 | 画面 | Tile4 开时用户目视正常（无花屏/斜屏/残帧）——**一票否决项** |
| 2 | GPU 合成段 | mark 段 p50 从 13–15ms 降到 **≤ 8ms**（前人 3× 改善的保守折算） |
| 3 | 帧率 | 拖动 3 轮中位 **≥ 35**（若 Part 0 判定 GPU 链是瓶颈，应显著更高；若 WS CPU 是瓶颈，可能只到 30 出头——**两者都算过，但要把 Part 0 的判定一起写进结论**） |
| 4 | 稳定性 | 3 轮 + 30 分钟日常使用：无冻结、无非 NMI 形态 panic、`flip_fail/dropped` 全 0、自动关未触发（`tile4_auto_off=0`） |
| 5 | A/B 留档 | tile4 on/off 六轮逐秒 + 各段计数器 |

**若门 2 过而门 3 不过**：这本身就是判决——瓶颈在 WS CPU，A-78 主攻 Device Cache/描述符
（并把 page-off + A-76 锁纪律一起带上）；如实写，不算失败。

## 6. 回滚（由轻到重）

1. `sudo sysctl -w debug.xegfxaccel_iop_xe_tile4=0`（运行时）。
2. boot-arg `xegfxtile4=0` + 重启（若运行时切换已引发画面问题）。
3. 插件回装 A-74 版（`~/xegfx-log/A-75/NVMTLDriver.before`）+ kickstart WS。
4. accel 回装 A-75 件（`~/xegfx-log/A-76/XeGfxAccel.before`）+ aux kc + 重启。
5. `sudo nvram xeintelfb-starts=%00`。
**报告写清当前可回滚点。**
