# Gate 4 · A-26 执行提示词（零拷贝 scanout：core 0011 + XeGfxDisplay 0015/0018）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **这是本项目最大的一次改动（新增一个 5000 行的 kext + 重编 core）。分 4 个 stage，每个 stage 有硬判据，不过就停。**
> 预计 2–4 小时。**宁可停在 stage 0，也不要带着半成品重启。**

---

## 0. 为什么要做这个

A-25 已用动画面发生器把第 3 条判据量死：**WindowServer 仍在软件合成**
（`CA::OGL::SW|scanline|draw_polygon` = 1256 vs Metal 符号 = 1；`IOAccelerator PerformanceStatistics` 全 0）。

机制：`debug.xegfxaccelfb=3` 给的是 **CPU copy target**，framebuffer 没有**可被 GPU 直接写的 scanout surface**
→ CoreAnimation 判定该 display 不可硬件合成 → 回落软件光栅再拷出去。

**解法是上游 `~/src/aw/patches/` 里那套 KMS 适配器**（ArrowWhatever 的设计，未应用到本机任何树）：

| 补丁 | 作用 |
| --- | --- |
| `0011-core-native-display-m0-m4a` | core 发布 **`XeGfxDisplayNub`**（KMS KAPI 地址 + VBT/child 捕获） |
| `0015-adapter-xegfxdisplay-kms` | 新增 `kexts/XeGfxDisplay`（5121 行）：`class XeGfxFramebuffer : public IOFramebuffer`，**`xgGetScanoutInfo` 的生产者**（v2 / 80 字节结构） |
| `0016-tools-native-display-bringup` | 构建脚本 |
| `0018-adapter-intel-class-name` | IOClass 换成 **`XeGfxIntelKMSFramebuffer`**（空子类，名字带 Intel）—— 同时满足"CoreDisplay 认厂商"与 `metaCast("XeGfxFramebuffer")` |

已核实的关系（很重要，别再重复今天的弯路）：
```
XeGfxFramebuffer  IOProviderClass = XeGfxDisplayNub   IOProbeScore = 10000
XeGfxFBClaim      （IOPCIDevice 上的认领类）          IOProbeScore = 20100
```
→ **它挂到 core 发布的 nub 上，不是去抢 IOPCIDevice**，所以与
`IGPUConsoleRange(65000) / XeGfxIntelFB(20001) / NMIntelFB(5000)` 这条链**不冲突**，不要改那三个分数。

**已安装的 `XeGfxAccel` 里已经有 `xgGetScanoutInfo` 的消费端**（A-22 已用 `strings` 证实），
所以本关**不需要**重建 accel。

## 1. 铁律

- **每个 stage 有硬判据，不过就停手报告**，不许"再试一下"。
- **stage 0 不通过（core 编不出来 / stage 1–7 不绿），后面全部作废** —— 不要装任何新 kext。
- 装 kext 一律 `kmutil create -z`；**绝不 `kickstart` `kernelmanagerd` / `syspolicyd`**。
- **不要在 boot 阶段推进 stage 7 / `accelfb=3`**（A-25 已证伪：WS 断言 + 登录回环）。
  本关所有加速动作都在**桌面稳定、WS 空闲 10 s 后**手动做。
- 重启前 `touch /var/db/xegfx/armed`；**armed 后 120 s 内不要再重启**。
- 保留 `/Library/Extensions` 里现有的 `IGPUConsoleRange` / `XeGfxIntelFB`（它们是兜底）。
- 每改一步之前备份：源码树 `git status` 若不可用，就 `cp` 到 `~/xegfx-log/A-26/`。

### 2.4 若 stage 5/6/7 不是 1（重建后补丁丢了）

新二进制的偏移和旧的不同，**不能照抄 `patch-xegfx.py` 的硬偏移**。按这个顺序处理：

1. 先看 `debug.xegfx_results` 是哪个槽位失败：
   - 5 或 6 失败 → 多半是 `pci_dev_put` 那三处没打（linuxkpi 的 pci_dev 被拆掉）
   - 只是"停在某一级、后面全 0" → 是 stage 循环的 `if (rc<0) break`
2. 用反汇编按**符号**定位，不要猜偏移：
   ```bash
   otool -tV /Library/Extensions/XeGfx.kext/Contents/MacOS/XeGfx > ~/xegfx-log/A-26/dis.txt
   grep -n "_linux_kobject_release" ~/xegfx-log/A-26/dis.txt | head
   grep -n "xg_i915_state\|xg_i915_exec\|xg_i915_store" ~/xegfx-log/A-26/dis.txt | head
   ```
   在 `xg_i915_state/exec/store` 三段里各找一处 `callq` → `_linux_kobject_release`，改成 5×`90`。
   再在 `xegfx_stage_sysctl` 里找 `testl %r13d,%r13d` 紧跟的 `js rel32`，改成 6×`90`。
3. 改完 `codesign --force --sign -` 重申，`xxd` 前后对照留证。
4. idr_preload 两处（若 stage 7 之后再崩）同样按 `xg_sched_pin/unpin` 符号定位，
   **jmp 尾字节必须是 `c3`**。

> 时间盒：这一步超过 **40 分钟**还没让 stage 全绿 → **停手**，把旧 core 装回
   （`/Library/XeGfx/backup-a26-core-*` 的 KC），报告"重建后补丁无法低成本恢复"，A-26 中止。

## 5. Stage 3：接 accel，看它走没走 KMS 零拷贝

**桌面稳定、WS 空闲 10 s 之后**才做（A-25 的教训：时机 = 结果）。

```bash
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60 ; sudo sysctl -w debug.xegfx_stage=7 ; sleep 20
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfxAccel
sleep 5
sudo sysctl -w debug.xegfxaccelfb=3
sleep 5
sudo log show --last 3m --predicate 'eventMessage CONTAINS "NMXAccel" OR eventMessage CONTAINS "xgGetScanoutInfo"' | tail -30
```
**关键读法**：出现 `nvXeKmsScanoutInfo` / `xgGetScanoutInfo` / `zero-copy flip` 之类 → 走的是 KMS 路；
仍出现 `describeBootFramebuffer … (CPU copy target)` → 还在兜底路（说明 nub 匹配没成）。

然后**用 A-25 那套动画面发生器**量第 3 条（不要用静止桌面）：
```bash
sudo launchctl asuser 501 sudo -u change48 /tmp/xegfx-anim &     # A-25 留下的
sleep 3
sudo sample "$(pgrep -x WindowServer)" 5 -file ~/xegfx-log/A-26/ws-moving.txt >/dev/null 2>&1
grep -cE "CA::OGL::SW|scanline|draw_polygon" ~/xegfx-log/A-26/ws-moving.txt          # 期望 ≈ 0（A-25 是 1256）
grep -cE "CA::MTL|MTLCommandBuffer|IOGPU|NVMTL|MetalContext" ~/xegfx-log/A-26/ws-moving.txt   # 期望 > 0
ioreg -r -c IOAccelerator -l -w0 | grep -E "context2DCount|bufferSwapCount|gartUsedBytes" | head -6
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null | grep -ci nvmtl
system_profiler SPDisplaysDataType | grep -i metal
ls -t /Library/Logs/DiagnosticReports/WindowServer*.ips 2>/dev/null | head -2
```

**Stage 3 判据（Gate 4 第 3 条）**
| 判据 | 期望 |
| --- | --- |
| `CA::OGL::SW\|scanline\|draw_polygon` | **从 1256 降到个位/几十** |
| Metal 符号 | 从 1 升到几十以上 |
| `PerformanceStatistics` 的 `context2DCount` 或 `bufferSwapCount` | **不再全 0** |
| 屏幕 | 干净、无彩噪、无 WS 崩溃 |
