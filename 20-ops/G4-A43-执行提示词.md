# Gate 4 · A-43 执行提示词：打开 `debug.xegfxaccel_iop`（帧拷贝的总闸）

> A-42 的现场已经把所有前置都摆好了：`scanout-backed display pipe ENABLED`、WS 活 5–8 分钟不崩、
> `CA::MTL>0`、`CompositorSW=0`、display mode 3120×2080 设成功。
> 但屏幕只有**开机遗留的启动文本**，`bufferFlipCount=0`、`surfaceCount` 冻在 81。
>
> 根因已定位到一行：**`gNvIop = 0`**。
> `performTransaction` 的第一行就是 `if (!gNvIop) return (IOReturn)0xe00002c7;`（**静默**返回，不打印），
> 所以帧从未被拷进 scanout。
>
> **本关只写一个 sysctl。**

---

## 2. 本关唯一动作

```bash
sudo sysctl -w debug.xegfxaccel_iop=1
echo "read-back: $(sudo sysctl -n debug.xegfxaccel_iop)"
sleep 3

echo "=== 门 2：能力已发布 + hooks 打开 ==="
sudo log show --last 2m --predicate 'eventMessage CONTAINS "NMXAccel"' 2>/dev/null \
  | grep -E "iop: debug.nvaccel_iop=1|capabilities published|transaction hooks OPEN" | tail -3 | tee $L/iop-on.txt
```

**门 2：日志出现 `iop: debug.nvaccel_iop=1 -- capabilities published, transaction hooks OPEN`。**
（若 sysctl 读回 1 但没这句日志：`NVAccel::gAccel` 为 NULL，说明 accel 没起来 —— 停手贴 `kmutil showloaded | grep -i accel`。）

> 说明：这一版源码里日志串写的是 `debug.nvaccel_iop=1`（NVIDIA 前缀），XeGfx 分支只是 sysctl 名字换了；
> 按上面 grep 两种前缀都覆盖。

## 3. 判决：屏幕应该立刻变

**这一步不需要重启 WS** —— 事务是由 CA 每次合成时发起的，钩子一开，下一帧就会走 `performTransaction`。

```bash
sleep 5
echo "=== A) IOP 计数（核心判据）==="
for k in iop_ok iop_fail iop_empty src_res src_surf; do
  printf "%-10s %s\n" "$k" "$(sudo sysctl -n debug.xegfxaccel_$k 2>/dev/null)"
done | tee $L/iop-counters.txt

echo "=== B) performTransaction 的 K6 采样日志 ==="
sudo log show --last 2m --predicate 'eventMessage CONTAINS "NMXAccel"' 2>/dev/null \
  | grep -E "iop: K6|no accelerator|not a surface buffer|performTransaction" | tail -6 | tee $L/k6.txt

echo "=== C) 加速器统计 ==="
sudo ioreg -l -w0 -r -c NMXAccel 2>/dev/null | grep -oE '"(surfaceCount|bufferSwapCount|bufferFlipCount)"=[0-9]+' | tee $L/perfstats.txt

echo "=== D) display / 屏幕 ==="
sudo log show --last 2m --predicate 'process == "WindowServer"' 2>/dev/null | grep -c "Invalid display"
system_profiler SPDisplaysDataType 2>/dev/null | grep -E "Resolution|Online|Main Display"
```

**同时请用户看屏幕**（这是最终判据）：

| 现象 | 结论 |
| --- | --- |
| `iop_ok` 开始增长、屏幕出现桌面/窗口（启动文本被覆盖） | **帧拷贝打通**，Gate 4 第 3 条达成 |
| `iop_ok` 增长但屏幕仍是旧文本 | 拷进去了但没显示 → 查 scanout 地址/stride 是否与面板扫描一致 |
| `iop_fail` 增长 | 停手，贴 `k6.txt` 与 `iop-counters.txt`（`performTransaction` 里有明确失败分支） |
| `iop_empty` 增长 | 事务里没有 plane 0 的 surface/resource → 贴 `k6.txt` 的 `plane 0: surface …` 一行 |
| 计数器全 0、也没有任何 K6 日志 | CA 还没发起事务 → 动一下鼠标/开个窗口再测一次 |

## 4. 若屏幕正常了，做一次"负载验证"（证明不是一帧静止）

```bash
# 让用户拖动窗口 / 打开一个 App，然后采两次
for i in 1 2; do
  sudo sysctl -n debug.xegfxaccel_iop_ok >> $L/iop-ok-seq.txt
  sudo ioreg -l -w0 -r -c NMXAccel 2>/dev/null | grep -oE '"surfaceCount"=[0-9]+' >> $L/iop-ok-seq.txt
  sleep 3
done
cat $L/iop-ok-seq.txt
```

**判据**：`iop_ok` 与 `surfaceCount` 在两次采样间都增长 → 真的在每帧拷贝。

## 7. 铁律

2. `debug.xegfxaccel_iop` 必须在 `accelfb=3`（scanout pipe 已开）之后再打开 —— 顺序反了没有意义。
3. `debug.xegfxaccelfb` 写 **3**（读回恒 1 属已知）。
4. 屏幕判据必须以**用户目视**为准：`screencapture` 在 SSH/登录窗下不可用。
5. 一次一个变量。
