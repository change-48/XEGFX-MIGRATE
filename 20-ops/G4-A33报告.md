## 1. 本关最重要的发现：提示词 §2.2 的写键位置是错的（若照抄会白跑一次）

§2.2 让写 `:IOCFPlugInTypes`（kext 顶层）。实测 Apple 原厂 kext 里，这个键**在 personality 字典内**，
与 `IOClass` 同级：

```
AppleIntelICLGraphics.kext/Contents/Info.plist 原文（含缩进）
			<key>IOAccelDisplayPipeCapabilities</key>
			<dict>
				<key>DisplayPipeSupported</key>
				<true/>
				<key>TransactionsSupported</key>
				<true/>
			</dict>
			<key>IOCFPlugInTypes</key>
			<dict>
				<key>ACCF0000-0000-0000-0000-000a2789904e</key>
				<string>IOAccelerator2D.plugin</string>
			</dict>
			<key>IOClass</key>
			<string>IntelAccelerator</string>
```

原因（机制层面）：服务节点上的属性来自**匹配到的 personality 字典**，kext 顶层的键不会成为
IORegistry 属性，而 `IOCreatePlugInInterfaceForService` 只读**服务节点的 `IOCFPlugInTypes` 属性**。
所以本关实际写入路径为：

```bash
PlistBuddy -c "Add :IOKitPersonalities:XeGfxAccel:IOCFPlugInTypes dict"
PlistBuddy -c "Add :IOKitPersonalities:XeGfxAccel:IOCFPlugInTypes:ACCF0000-0000-0000-0000-000a2789904e string IOAccelerator2D.plugin"
```

**这个判断是对的，并且已被实测闭环证实**：S3 期间注册表里该属性确实挂在 `NMXAccel` 上（见 §4.1）。

## 5. 本关得到的三条硬事实

1. **写键位置必须进 personality**：kext 顶层写 `IOCFPlugInTypes` 不会成为服务属性。
   本关按 personality 写、并已在 `NMXAccel` 节点上实测到该属性 —— 这一步是**对的且已完成**。
2. **`IOCFPlugInTypes` 不是唯一缺口**：属性到位后，`has no IOCFPlugInTypes` 仍有 4 次/实例，
   且 `0x2002` 逐字不变、`newDisplayPipe` 依旧 0 次调用。说明 IOPPresentment 在**别处**还查不到
   插件工厂，或者查到了工厂但插件侧拒绝了本服务。以现有脱敏日志无法区分是"另一个服务没键"
   还是"插件拒绝"。（A-32 §6 第 1 条"呈现链路已通、不要再查 present/open"在本次依旧成立：
   `newUserClient(type 4)` 每次都在 `0x2002` 之前成功。）
3. **A-32 的 WS 死亡模式完整复现**：7.1–12.1 s SIGABRT、`transient surface not found` 为其直接前导、
   任意时刻单实例、13 条 panic 里没有新增。
