### 1.2 A-79 的漏网：selector 5 从来不可能成功

首轮实测（14:50，lazy 生效、flip=0）：

```
page-off: the accelerator takes selector 5            ← 探针 id=0 成功（accel 对 id 0 直接 return success）
page-off: private copies after 3 s and 100 commits
page-off: surface 3 3120x2080 promoted to a private copy after 100 commits    ← 3 / 5 / 10 三个面
page-off: surface 3: the accelerator took no current mark -- copied out now   ← ×N
iop_xe_po: page-offs 0, attached 0, detached 0, refused while locked 0
```

根因（`nvrm-accel.cpp` `nvXePoCurrent`）：

```c
void *root = gNVSVRoot;                                    // 没有懒初始化
void *surf = root ? lookupSurface(root, id, task) : nullptr;
if (!surf) return 0;
```

`gNVSVRoot` **只在 `nvSurfGpuEscape`（NVK surface-dirty escape）里**被 `waitForMatchingService("IOSurfaceRoot")` 填上，
而本栈插件走 selector 1/2 打标、从不走那条 escape（`log show` 里 `surfvram dirty` 0 条，可证），于是 `root` 恒为 null，
每次 current 标记都走 `kIOReturnNotFound`。

修法（本关已装机）：

| 改动 | 内容 |
| --- | --- |
| 懒查找 | `nvXePoCurrent` 内 `if (!gNVSVRoot) waitForMatchingService("IOSurfaceRoot", 1 s)` |
| 两条失败分支可分辨 | 新增 `gCntPoNoSurf` / `gCntPoNoCache` + 各首 8 条 ALOG（`A-80: page-off: surface N: no IOSurface (root d)…` / `no device cache for our key`） |

修后（15:06）：

```
page-offs 18 (avg 6633 us, max 7674 us), timed out 0, no service 0,
for scan-out 0, attached 5→7, detached 3→5, refused while locked 0
```

## 8. 下一关的建议（只报事实，修法留给下一关）

   只留 A-79 件复测同一拖动，确认这个数是不是 A-79 就带来的。
3. **flip=1 与 page-off 在"scanout 面"上互斥**：flip 打开后 WindowServer 的主面全是 scanout，`nvmtl_po_want` 直接排除，
   page-off 只剩窗口 backing 面可做——本关 `attached 7 / page-offs 18` 就是这么来的。如果下一关想量化 page-off 收益，
   要么在 flip=0 的拷贝路径上比，要么把判据从"非 scanout"放宽到"非本帧 scanout"。
