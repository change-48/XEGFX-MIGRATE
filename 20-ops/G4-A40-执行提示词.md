# Gate 4 · A-40 执行提示词：先用上游自带的两个开关做 A/B（不整包同步）

> 结论先行：**不做插件整包同步。** 理由见 §0；本关改跑上游自带、默认关闭的两个 env 开关。
> **零代码、零重编、不改 kext、不改 EFI。** 只需要 `launchctl setenv` + 重启 WS。

---

## 0. 为什么放弃整包同步（先把判断摆清）

已用 `curl` 取到上游 `xe` 分支的插件源码并与本地逐行比对：

| 事实 | 结论 |
| --- | --- |
| 崩溃发生的那段代码（`NVMTLObjects.m` 的 `if (!spec) { … return nil; }`）**两边逐字相同** | 整包同步**不会**改变这个失败点 |
| 上游 CHANGELOG 全文无 `half` / `specializ` / `Core Animation` 相关修复条目 | 上游没有针对它的补丁 |
| `0005-plugin-xemtl-port` 对 `NVMTLObjects.m` 有 **225 个 hunk**、对 `NVMTLLibraryLoad.m` 有 83 个 | 覆盖上游后再重打，风险高、收益不确定 |
| `hasUnifiedMemory`：本地已实现，默认 **NO**（仅 `NVMTL_XE_UNIFIED=1` 时 YES）；上游恒 NO | 默认行为一致，**不是差异点** |

→ 所以本关不碰插件二进制，改跑**上游自己留下的两个实验开关**。

---

## 1. 本关依据：两个默认关闭的上游开关

### 1.1 `NVMTL_FBFETCH_WS`

A-39 现场日志（我们自己的 WS）：

```
NVMTL: vk: framebuffer fetch off in WindowServer (NVMTL_FBFETCH_WS=1 opts in)
```

上游 CHANGELOG（`xe` 分支）第 45 行：

> "Core Animation passes that read the colour attachment with **framebuffer fetch off** now read a defined image
> instead of an unbound descriptor, which could put garbage on screen inside WindowServer (PR #270)"

→ **CA 的片元 pass 与 framebuffer fetch 直接相关**，而我们的实现此刻是 **off**。
`fixed_frag_lph_cph` 正是 CA 的片元着色器之一 —— 这是目前最贴题的一个开关。

### 1.2 `NVMTL_XE_UNIFIED`

插件源码里的原注释（`NVMTLDevice.m` 的 `hasUnifiedMemory`）：

```objc
// the Intel GPU shares system RAM; NVMTL_XE_UNIFIED=1 (nvrm610.conf) says so,
// off until an xe-guard run proves it
```

Intel iGPU 物理上就是统一内存；插件默认对 CA 说 **NO**（离散显存模型）。
CA 会据此决定表面放在哪里、是否走读回路径 —— 与 `fixed_frag_lph_cph` 这类"读色彩附件"的 pass 相关。

## 2. 实验设计（两轮，一次一个变量）

| 轮次 | 开关 | 目的 |
| --- | --- | --- |
| **R1** | `NVMTL_FBFETCH_WS=1` | 让 CA 的 framebuffer-fetch pass 走有定义的图像（对准 CHANGELOG PR #270 那条） |
| **R2**（仅当 R1 无效） | 追加 `NVMTL_XE_UNIFIED=1` | 让插件对 CA 承认统一内存 |

两轮之间必须 `launchctl unsetenv` 清干净，避免叠加变量。

---

## 3. 每轮的固定流程

### 3.1 建现场（core / accel / AGDC）

```bash
L=~/xegfx-log/A-40; mkdir -p $L
( sudo log stream --predicate 'eventMessage CONTAINS "NVMTL" OR eventMessage CONTAINS "NMXAccel" OR eventMessage CONTAINS "AGDC" OR process == "WindowServer"' > $L/stream-R1.log 2>&1 & )
sleep 2

sudo /usr/bin/kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60 >/dev/null
sudo sysctl -w debug.xegfx_stage=7 >/dev/null
sleep 22
sudo sysctl -b debug.xegfx_results | od -A n -t d4 | tee $L/results.txt        # 期望 0 1 1 1 1 1 1 1

sudo /usr/bin/kmutil load -b org.watchthelight.XeGfxAccel; sleep 3
sudo sysctl -w debug.xegfxaccelfb=3; sleep 4

sudo sysctl debug.xegfx_agdc; sudo sysctl debug.xegfx_agdc_fbmap | tee $L/agdc.txt
```

**门 1：`results` 全 1、AGDC `state=1` + `fbmap n=1`。** 不过就停手。

### 3.2 R1：设开关 → 重启 WS → 观察

```bash
sudo launchctl setenv NVMTL_FBFETCH_WS 1
sudo launchctl getenv NVMTL_FBFETCH_WS          # 回读应为 1

sudo launchctl kickstart -k system/com.apple.WindowServer
sleep 30

echo "=== A) WS 存活 ==="; pgrep -x WindowServer | wc -l; ps -o etime=,pid= -p "$(pgrep -x WindowServer)" 2>/dev/null
echo "=== B) 崩溃签名 ==="
grep -c "OS_REASON_COREANIMATION" $L/stream-R1.log
grep -c "native emitter" $L/stream-R1.log
echo "=== C) 开关是否真的生效 ==="
grep -E "framebuffer fetch" $L/stream-R1.log | tail -3
echo "=== D) 合成栈（活过 30 s 才有意义）==="
sudo sample $(pgrep -x WindowServer) 2 -file $L/ws-R1.txt >/dev/null 2>&1
echo "MTL=$(grep -c 'CA::MTL' $L/ws-R1.txt) SW=$(grep -cE 'CA::OGL::SW|scanline|draw_polygon' $L/ws-R1.txt) CompSW=$(grep -c 'CompositorSW::CompositeLayersToDestination' $L/ws-R1.txt)"
```

判读：

| 结果 | 结论 |
| --- | --- |
| `native emitter` = 0 且 WS 活过 30 s | **R1 命中** → 进 §4 收尾 |
| 仍 `COREANIMATION` | R1 无效 → 清开关，做 R2 |
| 崩的签名变了 | **新信息**，贴原文，停手 |

### 3.3 R2（仅在 R1 无效时）

```bash
sudo launchctl unsetenv NVMTL_FBFETCH_WS
sudo launchctl setenv NVMTL_XE_UNIFIED 1
sudo launchctl getenv NVMTL_XE_UNIFIED           # 回读 1
sudo launchctl kickstart -k system/com.apple.WindowServer
sleep 30
# 同 §3.2 的 A~D 四组，日志写到 $L/stream-R2.log / ws-R2.txt
```

## 4. 若某轮命中（`native emitter` 归零、WS 稳定）

```bash
# 1) 坐实"真的在 GPU 合成"
sudo sample $(pgrep -x WindowServer) 2 -file $L/ws-stable.txt >/dev/null 2>&1
grep -c 'CA::MTL' $L/ws-stable.txt
grep -cE 'CompositorSW::CompositeLayersToDestination' $L/ws-stable.txt
sudo ioreg -l -w0 -r -c NMXAccel 2>/dev/null | grep -A12 "PerformanceStatistics" | tee $L/perfstats.txt
sudo powermetrics --samplers tasks -n 1 2>/dev/null | grep -E "WindowServer|CPU ms/s" | head -3 | tee $L/power.txt

# 2) 固化前先记录：这个开关是 session 级的，重启会丢
sudo launchctl getenv NVMTL_FBFETCH_WS
```

**固化方式留到 A-41**（写进 `nvrm610.conf` 或 WS 的 launchd 环境）。本关只负责"确认它是那个杠杆"。

---

## 5. 收尾（每轮结束都要做，避免把机器留在危险态）

```bash
sudo nvram xegfx-disp-phase=%00 xegfx-disp-trial=%00 xegfx-disp-expose=%00 xegfx-disp-fail=%01
sudo rm -f /var/db/xegfx/armed
sudo launchctl unsetenv NVMTL_FBFETCH_WS 2>/dev/null
sudo launchctl unsetenv NVMTL_XE_UNIFIED 2>/dev/null
sudo shutdown -r now          # WS 崩过就重启；WS 稳定则只需清 env + kickstart
```

## 7. 铁律

1. **不整包同步插件**（§0 已论证）；本关只跑 env 开关。
2. 一轮只加一个变量；换轮前必须 `unsetenv` 清干净。
3. `kickstart WS` 会结束控制台会话 → 先把 core/accel/AGDC 准备好。
4. `debug.xegfxaccelfb` 写 **3**。
5. 每轮结束清 nvram 门 + `rm armed`，不要把机器留在 S3 半态。
6. `launchctl setenv` 是 session 级的，重启即失效 —— 这不是缺陷，是本关需要的"可回退"。
