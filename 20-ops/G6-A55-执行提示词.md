# Gate 6 · A-55 执行提示词：让 CA 只画 1560×1040（pipe scaler 两阶段）

> 目标：**让 CoreAnimation 合成 1560×1040，由显示管道放大到 3120×2080**。
> 像素从 6.49 MP 降到 1.62 MP（**1/4**），CA 的渲染成本同比降到 1/4——这是通往 120fps 唯一还没试过的杠杆。
>
> 全部改动落在**我们自己的面板 kext**（`XeGfxIntelFB`）+ 显示寄存器；
> **加速器一行不动**，现有的拷贝路径照常工作（而且拷贝量也从 26MB 降到 6.66MB）。

---

## 0. 三个已核实的前提（决定这条路可行）

### 0.1 行距是整数

```
1560 × 4        = 6240 字节
CoreAnimation 按 256 对齐 → 6400 字节      （6240 → 6400）
6400 / 64       = 100  ✓  PLANE_STRIDE 的单位是 64 字节，能表达
```

⇒ **不用改宽度、不用凑数**，1560 就能用。（这是昨天差点被 6240/64=97.5 挡住的地方。）

### 0.2 不用新分配内存

现有 scanout 缓冲 25,958,400 B；1560×1040 @6400 = **6,656,000 B**。
⇒ 直接用这块缓冲的**开头 6.66 MB**，`PLANE_SURF` 不变，**只改 `PLANE_SIZE` / `PLANE_STRIDE`**。

### 0.3 FB 已有"加一个模式"的现成框架

`intelfb.cpp` 里已有一套：`getDisplayModeCount`/`getDisplayModes`/`getInformationForDisplayMode`/
`getPixelInformation`/`setDisplayMode` 全部被 override，并追加了 `XIFB_HIDPI_MODE_ID`
（1280×800 的 2× 桌面，**同一块 backing，不改寄存器**）。

⇒ 我们照抄这套结构，追加一个 **`XIFB_SCALE1X_MODE_ID`**，区别只有一处：
它的 `getPixelInformation` 返回 **1560×1040 / 6400 行距**（而不是原样返回 native 的）。

### 0.4 寄存器（`xenative.cpp` 已有定义，都是 pipe A）

```
PLANE_SURF_A    0x7019C     现值 0xfd000000 / 0x84aa6000
PLANE_SIZE_A    0x70190     现值 0x081F0C2F（3120×2080）
PLANE_STRIDE_A  0x70188     现值 0xC3（195 = 12480/64）
TRANS_PIPESRC_A 0x6001C     现值 0x0C2F081F（3120×2080）
PS_CTRL_A       0x68180     现值 0x00000200
```

目标值：

```
PLANE_SIZE_A   = (1039 << 16) | 1559 = 0x040F0617
PLANE_STRIDE_A = 100  (0x64)
TRANS_PIPESRC  = (1039 << 16) | 1559 = 0x040F0617
PS_CTRL_A      = 0x00000200 | PS_SCALER_EN(1<<31) | PS_BINDING_PIPE(1<<30) = 0xC0000200
```

## 1. 分两阶段（**这是本关最重要的纪律**）

| 阶段 | 做什么 | 期望看到 | 失败时 |
| --- | --- | --- | --- |
| **A** | FB 新增 1560×1040 模式；`PLANE_SIZE`/`STRIDE` 随之改变；**不开 scaler** | 桌面缩在**左上角 1/4**（未放大），其余黑/旧内容 | 只是画面变小，**不会有花屏风险**，直接回滚 |
| **B** | 只在 A 成功后：`PIPESRC` + `PS_CTRL` 打开 scaler | 左上角那 1/4**放大填满全屏** | 花屏/黑屏 → 立即回滚 |

**A 没通过就绝对不做 B。**

---

## 2. 安全阀（先做，避免变砖）

在 `probe()` 里加一个开机参数，**任何异常都能一次重启退出**：

```cpp
int off1x = 0;
if (PE_parse_boot_argn("-xeintelfb1xoff", &off1x, sizeof off1x)) {
    XIFBLOG("1560x1040 mode disabled by boot-arg");
    fScale1x = 0;
}
```

自检：`grep -c "xeintelfb1xoff" intelfb.cpp` ≥ 2。

**门 0：开机参数的存在，意味着最坏情况是"加一个启动参数再重启"，不需要重装 kext。**

## 3. 阶段 A：让 FB 对外提供 1560×1040 的 backing

文件：`~/src/NvGfx-5a19a73f36249efb99c44c3f9cb34603ef0c0eb8/kexts/XeGfxIntelFB/intelfb.cpp`

### 3.1 加常量与开关

```cpp
#define XIFB_SCALE1X_MODE_ID 0x5C010462      // 一个不冲突的 IODisplayModeID
#define XIFB_1X_W 1560
#define XIFB_1X_H 1040
#define XIFB_1X_ROW 6400                     // 1560*4 rounded up to 256
static int fScale1x = 1;                      // boot-arg 可关
```

### 3.2 五处 override 各加一个分支（**照抄已有 `XIFB_HIDPI_MODE_ID` 的结构**）

- `getDisplayModeCount()` → `n + 1`（**注意：现在已经有 `+1` 了，要变成 `+2`**）
- `getDisplayModes()` → 追加 `XIFB_SCALE1X_MODE_ID`
- `getInformationForDisplayMode()` → nominal 1560×1040，其余 flags/refreshRate 照抄 HIDPI 分支
- `getPixelInformation()` → **与 HIDPI 分支相反**：自己填 1560×1040 / 32bpp / `bytesPerRow = 6400`，
  不要转调 native
- `setDisplayMode()` → 接受它，并调用新的 `xifbTakeScale1xPlane()`

### 3.3 `setDisplayMode` 里改平面（阶段 A 只改 SIZE 与 STRIDE）

**MMIO 已经在手**：`intelfb.cpp` 里 `xifbMapBar()` 已经把 BAR0 映射成成员 `fBar`
（`volatile uint32_t *`，`IOMapInhibitCache`，长度校验 ≥ 0x71000，`fMmioReady` 置位），
`xifbMeasurePanelTiming()` 就在用它读 `fBar[0x70190/4]`、`fBar[0x7019c/4]`、`fBar[0x70040/4]`。
**所以阶段 A 不需要新映射，直接用 `fBar`。**

```cpp
    // Same buffer, reinterpreted: the panel keeps its 3120x2080 timing, but the plane now reads a
    // 1560x1040 image at the head of the same surface and the pipe scaler stretches it to the panel.
    // Stage A writes only SIZE and STRIDE, so if the scaler never engages the desktop simply shows
    // unscaled in the top-left quarter -- there is no register combination here that corrupts the panel.
    void xifbPlaneScale1x(bool on) {
        if (!fMmioReady || !fBar) return;
        if (!fSavedStride) fSavedStride = fBar[PLANE_STRIDE_A / 4];   /* remember 0xC3 once */
        fBar[PLANE_STRIDE_A / 4] = on ? (XIFB_1X_ROW / 64) : fSavedStride;        /* 100 = 6400/64 */
        fBar[PLANE_SIZE_A   / 4] = on ? ((1039u << 16) | 1559u) : 0x081F0C2Fu;   /* 1560x1040 : 3120x2080 */
        (void)fBar[PLANE_SIZE_A / 4];
        XIFBLOG("scale1x: plane %s -- stride %u, size 0x%08x", on ? "1560x1040" : "3120x2080",
                (unsigned)fBar[PLANE_STRIDE_A / 4], (unsigned)fBar[PLANE_SIZE_A / 4]);
    }
```

> 需要新增一个成员 `uint32_t fSavedStride = 0;`（记住原来的 0xC3，回退用）。

**阶段 A 验证**：

```bash
sudo log show --last 3m --predicate 'eventMessage CONTAINS "scale1x"' | tail -3
# 用户目视：桌面是否缩到左上角 1/4
sudo sysctl -n debug.xegfxaccel_iop_ok    # 帧流应照常
```

**门 A：`getPixelInformation` 返回 1560×1040/6400、`PLANE_STRIDE=100`、`PLANE_SIZE=0x040F0617`、
画面缩到左上 1/4、帧流不断。**

> 若画面雪花/花屏而不是"缩到左上角"：说明 SIZE/STRIDE 改法与缓冲内容不匹配（CA 可能还在画 3120 宽）。
> 先确认 K6 日志里 surface 的尺寸真的变成了 1560×1040 再继续。

## 4. 阶段 B：打开 pipe scaler

**只在门 A 通过后**，在 `setDisplayMode` 的 1× 分支里追加：

```cpp
            fBar[TRANS_PIPESRC_A / 4] = (1039u << 16) | 1559u;   /* 源 = 1560x1040 */
            fBar[PS_CTRL_A / 4]      |= (1u << 31) | (1u << 30); /* PS_SCALER_EN | PS_BINDING_PIPE */
```

**用户目视**：

| 现象 | 结论 |
| --- | --- |
| 全屏正常、略微柔和（2× 放大应有轻微模糊） | **成功** ← 本关目标 |
| 仍是左上 1/4 | scaler 没使能（bit 位不对）→ 停，dump `0x68100–0x68200` |
| 花屏/黑屏 | 立即回滚（`-xeintelfb1xoff`） |

**成功后立刻量帧率**（拖动 20 秒），与当前基线（拷贝路径 30–56fps）对比。

## 5. 回滚

```
1) 加启动参数 -xeintelfb1xoff，重启  → 回到 3120×2080（最安全）
```

## 7. 铁律

1. **阶段 A 不碰 `PIPESRC` / `PS_CTRL`**；阶段 B 只在门 A 通过后做。
2. `PLANE_SURF` 全程不动（还是那块缓冲）。
3. 画面异常 → 加 `-xeintelfb1xoff` 重启，**不要在线调寄存器**。
4. 每步都用日志确认寄存器真的写进去了。
5. 判据以用户目视为准。
