# Gate 0 执行提示词 · 护栏与快照（A-00）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> 主 agent 只做两件事：发这份提示词、事后独立验收（见末尾《验收锚点》）。

---

## 0. 你要做什么（一句话）

在一台已经「用核显出图但分辨率只有 1080p」的黑苹果上，**只做刹车和倒车档**：
快照、一键回滚脚本、开机护栏 daemon、去掉 `debug=0x100`，然后重启一次证明机器能自己回来。
**不装任何图形 kext，不改显示，不追求任何进展。**

这一关唯一的意义：后面 Gate 1–4 无论怎么把机器搞挂，都能自己回到今天的 1080p 可用状态。

- `/Library/Extensions` 只有三个：`HighPointIOP.kext`、`HighPointRR.kext`、`IGPUConsoleRange.kext`。
- AuxKC `sha256 = e438014093d70c94ebc79fc1ff597c5718aad7d727cb7e0aab2f3f3cb157feda`，内含且仅含上述三个。
- **XeGfx / XeGfxAccel / XeGfxAGDC / XeGfxIntelFB / NMIntelFB / XeNative 目前都没装**（这是正常的，Gate 1 才装）。

- 内置 ESP = `disk0s1`，卷标 `NO NAME`。

**三个必须记住的坑（踩过，别再踩）**

1. **boot-args 改 nvram 无效。** 内置 ESP 的 `config.plist` 里，GUID `7C436110-AB2A-4BBB-A880-FE41995C9F82` 的
   **NVRAM→Delete 数组含 `boot-args`**，Add 里又写了一遍。每次开机先删再按 config 写入。
   → 改 boot-args 只能改 `config.plist`。`sudo nvram boot-args=...` 重启即失效。
2. **U 盘 `D:\EFI\OC\config.plist` 是救援盘，配置是另一套**（带 `-x`，仍含 debug=0x100）。
   **本次绝对不要改它**，它是机器起不来时唯一的救回通道。
3. **重建 AuxKC 的唯一可用命令**（本机实测 rc=0，无 KDK）：
   ```
   sudo kmutil install --volume-root / --allow-missing-kdk -v
   ```
   不要加 `--update-all`（会重建 boot KC，风险大），不要用 `kmutil create`（参数极易写错）。

## 2. 铁律

- **本次唯一变量 = 护栏与快照**。不装 XeGfx，不碰 IGPUConsoleRange，不改显示相关任何寄存器/kext。
- **一次开机只改一个变量**（本关只有 4 个静态文件改动，打包成一次重启）。
- 不许 `softwareupdate`，不许任何系统升级（会把机器升到 26.7.2）。
- 不许删除 `/Library/Extensions` 里任何现有 kext（搬走可以，删不行）。
- 不许 `rm -rf` 通配符；任何删除都必须先 `-d` / `-f` 判存在。
- 改 `config.plist` 必须：先备份 → 后 `plutil -lint` → lint 不过就还原，**不许带着坏 config 重启**。
- 遇到计划外现象：停手、留证、报告。不要自己发挥、不要"顺手优化"。

## 3. 任务

### T1 快照

```bash
mkdir -p ~/xegfx-log/A-00
sudo mkdir -p /tmp/snap-cfg && sudo cp -p "/Volumes/NO NAME/EFI/OC/config.plist" /tmp/snap-cfg/config.plist.before
# 若 ESP 未挂载：sudo diskutil mount disk0s1
sudo tar czf ~/xegfx-snap-1031.tgz \
     /Library/Extensions \
     /Library/KernelCollections/AuxiliaryKernelExtensions.kc \
     -C /tmp/snap-cfg config.plist.before
```
同时把现场存成文本 `~/xegfx-snap-1031.meta.txt`：`nvram boot-args`、`csrutil status`、
`ls -la /Library/Extensions`、`shasum -a 256 /Library/KernelCollections/AuxiliaryKernelExtensions.kc`、
`system_profiler SPDisplaysDataType`、`diskutil list`。

> 注意：本机快照**只有约 1.5 MB**（L/E 568K + AuxKC 912K）。计划里写的「≥100 MB」是错的，别拿体积当验收。

### T2 一键回滚脚本 `/usr/local/bin/xegfx-rollback.sh`

行为要求（照这个写，别改语义）：

- 参数：`--dry-run` 只打印计划、零改动、rc=0；`--auto` 无人值守（护栏调用）；无参数 = 交互式真跑。
- 六件套固定表（按 bundle id 搬走，**不是删**）：
  ```
  org.watchthelight.XeGfx        XeGfx.kext
  org.watchthelight.XeGfxAccel   XeGfxAccel.kext
  org.watchthelight.XeGfxAGDC    XeGfxAGDC.kext
  org.watchthelight.XeGfxIntelFB XeGfxIntelFB.kext
  com.nullmoth.NMIntelFB         NMIntelFB.kext
  org.xenative.XeNative          XeNative.kext
  ```
- **必须保留**：`IGPUConsoleRange.kext`、`HighPointIOP.kext`、`HighPointRR.kext`（屏幕和磁盘靠它们）。
- 用户态残留一并搬走（存在才动）：`/Library/GPUBundles/nvmtl`、`/Library/GPUBundles/NVMTLDriver.bundle`、
  `/Library/GPUBundles/NVMTLDriver`（软链）、`/Library/GPUBundles/nvmtl-allow.txt`。
- 目标目录 `/Library/XeGfx/rollback-backup-<YYYYmmdd-HHMMSS>/`。
- **dry-run 必须逐条固定输出**（present/absent 都要打一行，这样装 kext 前也能验）：
  ```
  PLAN REMOVE XeGfx.kext (org.watchthelight.XeGfx) [absent]
  ...
  PLAN KEEP   IGPUConsoleRange.kext (org.watchthelight.IGPUConsoleRange) [present]
  PLAN KEEP   HighPointIOP.kext [...] [present]
  PLAN KEEP   HighPointRR.kext [...] [present]
  ```
- **真跑流程**：搬 kext → **若本次一个都没搬走，跳过 AuxKC 重建**（避免无意义重建把唯一能用的 KC 弄坏）→
  否则 `kmutil install --volume-root / --allow-missing-kdk -v` → 校验新 AuxKC **仍含** IGPUConsoleRange + HighPoint×2
  → 校验通过才 `reboot`；不通过则**不重启**，打印失败原因并以非 0 退出。
- 幂等：重复跑不报错，已不存在的项打 `SKIP (absent)`。
- `sudo chown root:wheel` + `chmod 755`。

### T3 开机护栏

**`/usr/local/bin/xegfx-guard.sh`**（`chmod 755`，root:wheel）：

```
STATE=/var/db/xegfx ; mkdir -p $STATE ; LOG=$STATE/guard.log
att=0 ; [ -f $STATE/attempts ] && att=$(cat $STATE/attempts)
if [ -f $STATE/armed ]; then
    att=$((att+1)) ; echo $att > $STATE/attempts
    if [ "$att" -gt 1 ]; then
        log "前一次 armed 开机没活下来（attempts=$att）→ 回滚"
        if /usr/local/bin/xegfx-rollback.sh --auto >> $LOG 2>&1; then
            rm -f $STATE/armed $STATE/attempts
            log "回滚完成，重启"
            /sbin/reboot
        else
            log "回滚失败，不重启，等人"
            echo "ROLLBACK-FAILED $(date)" > $STATE/failed
        fi
        exit 0
    fi
fi
# 存活 120 秒 → 判定本次开机成功
sleep 120
date > $STATE/ok
echo 0 > $STATE/attempts
rm -f $STATE/armed
log "存活 120s，写 ok，attempts 归零"
```
`sleep` 用**前台**（不要 `&`），这样 `launchctl list` 里能看到 PID，也算证据。

**`/Library/LaunchDaemons/org.xegfx.guard.plist`**：`Label=org.xegfx.guard`、`RunAtLoad=true`、
`ProgramArguments=[/usr/local/bin/xegfx-guard.sh]`、`StandardOutPath/StandardErrorPath` 指到 `/var/db/xegfx/`。
**不要 KeepAlive**（会无限重跑）。装之前先 `sudo mkdir -p /var/db/xegfx`（否则 launchd 打不开日志直接失败）。

装载与自检：
```bash
sudo launchctl bootstrap system /Library/LaunchDaemons/org.xegfx.guard.plist
sudo launchctl list | grep xegfx.guard          # 期望有输出
sleep 125 ; cat /var/db/xegfx/ok ; cat /var/db/xegfx/attempts   # 期望 ok 有日期、attempts=0
```

### T4 去掉 debug=0x100（改 config.plist，不是 nvram）

```bash
sudo diskutil mount disk0s1            # 挂到 /Volumes/NO NAME
P="/Volumes/NO NAME/EFI/OC/config.plist"
sudo cp -p "$P" "$P.bak-before-nodebug-$(date +%Y%m%d-%H%M%S)"
sudo /usr/libexec/PlistBuddy -c \
  "Set :NVRAM:Add:7C436110-AB2A-4BBB-A880-FE41995C9F82:boot-args -v keepsyms=1 -vi2c-force-polling -amfipassbeta amfi_get_out_of_my_way=0x1 amfi=0x80 ipc_control_port_options=0 itlwm_cc=CN" "$P"
sudo plutil -lint "$P"                                       # 必须 OK
sudo plutil -extract "NVRAM.Add.7C436110-AB2A-4BBB-A880-FE41995C9F82.boot-args" raw -o - "$P"
sudo diskutil unmount "/Volumes/NO NAME"
```

**只去掉 `debug=0x100`，其余一个字符都不许变。** 特别是：`-v`、`keepsyms=1`、`-vi2c-force-polling`、
`-amfipassbeta`、`amfi_get_out_of_my_way=0x1`、`amfi=0x80`、`ipc_control_port_options=0`、`itlwm_cc=CN` **全部保留**。
理由：本次唯一变量是"panic 后自动重启"，多改一个字符就多一个变量。
（`ipc_control_port_options=0` 计划里没列，但它和 panic 行为无关、且当前系统在用它，删了等于引入第二个变量。）

**不要**同时 `sudo nvram boot-args=...`：保持 config 是唯一真源，否则分不清改没改对。

### T5 重启验证

重启前先 arm，让护栏跑一次真实测试：
```bash
touch /var/db/xegfx/armed
sudo reboot
```
然后从 Windows 侧每 10 s 探一次，最多 180 s：
```bash
ssh -i ~/.ssh/id_xegfx_remote -o ConnectTimeout=5 change48@192.168.1.102 'echo ok; uptime'
```
回来之后立刻采集证据到 `~/xegfx-log/A-00/`：
`results`（本关没有 sysctl，写 guard 状态）、`probe`（`system_profiler SPDisplaysDataType`）、
`iored`（`ioreg -l | grep -i IOFBMemorySize` + `ioreg -c IOFramebuffer`）、`dmesg`（`log show --last 5m --predicate 'process=="kernel"' | tail -300`）、
`screen.txt`（`nvram boot-args`、`pgrep -x WindowServer`、`launchctl list | grep xegfx.guard`、`cat /var/db/xegfx/{ok,attempts}` 或 `failed`）。

## 4. 停机条件

- `plutil -lint` 不通过 → 立即还原备份，停手，报告。
- 回滚脚本 dry-run 出现 `IGPUConsoleRange` 被 `PLAN REMOVE` → 脚本写错了，停手重写。
- 重启后 180 s 没回来 → 等 3 min 再看一次；仍不通 → **不要去动机器**，报告"疑似 hang，需要人工断电一次"。
  断电重启后护栏应当自动 attempts=2 → 回滚 → 自动重启。
- 任何一步出现计划外的 panic / 屏幕消失 → 停手，留证，报告。

## 验收锚点（主 agent 会独立跑，不看你的自述）

主 agent 会自己 SSH 进来核这几条硬指标，任何一条不符即判 FAIL：

1. `tar tzf ~/xegfx-snap-1031.tgz` 含 `IGPUConsoleRange.kext` + `AuxiliaryKernelExtensions.kc` + `config.plist.before`；
   且 `tar xzOf ... AuxiliaryKernelExtensions.kc | shasum -a 256` = `e438014093d70c94ebc79fc1ff597c5718aad7d727cb7e0aab2f3f3cb157feda`。
2. `xegfx-rollback.sh --dry-run | grep -c '^PLAN REMOVE'` = 6；
   `xegfx-rollback.sh --dry-run | grep '^PLAN REMOVE' | grep -c IGPUConsoleRange` = 0。
3. `launchctl list | grep -c xegfx.guard` ≥ 1，且 `/var/db/xegfx/ok` 存在、`attempts` 内容为 0、`armed` 已被清掉。
4. `nvram boot-args` 不含 `debug=0x100`，且含全部 8 个保留项。
5. `system_profiler SPDisplaysDataType` 仍为 1920×1080，`pgrep -x WindowServer` 有 PID；
   `/Library/Extensions` 仍含 IGPUConsoleRange + HighPoint×2；`kmutil inspect` 的 aux 段仍含这三个。
6. 无本次开机后的新 panic（`ls -lt /Library/Logs/DiagnosticReports/*.panic` 最新时间早于本次开机时间）。
