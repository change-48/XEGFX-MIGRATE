# Gate 4 · A-27 执行提示词（把时序源改成"我们这块面板"，然后打 S3）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **Stage A 只是改 core 里 13 个常量 + 重编（约 20–30 分钟）。Stage B 才是 S3 接管，有黑屏风险。**
> A 不过就别做 B。

---

## 0. 卡在哪（A-26 的结论，已由主 agent 复核到字节）

A-26 把 KMS 适配器装上了、也挂到了 nub（`class XeGfxIntelKMSFramebuffer = 1`），但它停在 **`phase=1` 的 inert 态**：
`open()` 被拒、0 连接、0 模式、无 aperture → WindowServer 不可能在它上面合成 → 仍 `CA::OGL::SW`。

真正的接管是 `phase=2 + trial=1 (+expose=1) → startS3()`。但 S3 有"same-mode claim"自检，
要求**测量 raster 与引擎当前模式一致**。而现在：

```
nub 的 measured-panel-timing（我解出来的 13 词）：
  pclk 277,440,000 Hz   raster 2560 x 1600   total 2720 x 1700   60 Hz
硬件实际（A-21 实测日志）：
  900,045 kHz           3120 x 2080          3400 x 2208         119.891 Hz
```

**根因（源码级，`xg_kext.cpp:310-313`）**：core 的时序 fallback 里那个"内建 EDID DTD"是
**上游作者那台 16" 面板（BOE NE160QDM-NZL，2560×1600）**的。我们这块是 3120×2080，
而且 900 MHz 像素时钟**超出 EDID DTD 的 655.35 MHz 上限**，压根无法用 DTD 表达 ——
所以它不是"补个 DTD"能解决的。

**为什么不用 measured 源**：优先级 1 是 `XeGfxIntelFramebuffer` 的 `XeGfxMeasuredPanelTiming`，
但它的生产者在 `0003`/`0010` 补丁里，我们装的 `XeGfxIntelFB` 0.8 **没打这两个补丁**
（`ioreg` 确认该属性不存在）。而这两个补丁在我们的树上 **7 个 hunk 冲突**（A-22 改过那个文件）。

**所以本关走最省的一条：在 core 的 fallback 里直接给出这 13 个词。**

## 1. 要写入的 13 个词（已核算，与 A-21 实测自洽）

```
3400 × 2208 × 119.891 Hz = 900,045,xxx Hz   ✓ 对上日志的 "900045 kHz, 119.891 Hz"
```

| 索引 | 名称 | 值 |
| --- | --- | --- |
| 0 | tag | `0x4b350001` |
| 1 | pixel clock Hz | `900045000` |
| 2 | h visible | `3120` |
| 3 | h sync start | `3332` |
| 4 | h sync end | `3336` |
| 5 | h total | `3400` |
| 6 | v visible | `2080` |
| 7 | v sync start | `2202` |
| 8 | v sync end | `2203` |
| 9 | v total | `2208` |
| 10 | refresh mHz | `119891` |
| 11 | hsync positive | `1`（见 §2 注） |
| 12 | vsync positive | `0`（见 §2 注） |

> 极性两位是唯一没实测的。先用 `1/0`（与参考记录同形）；**若 S3 的 preflight 报极性不符**，
> 读 `TRANS_HSYNC(0x60008)` / `TRANS_VSYNC(0x60014)` 的 bit31 取真实极性再改，别猜。

## 2. Stage A：改 core 的 fallback + 重编 + 验证时序源变对

### 2.1 改哪里

`gpu/xegfx/shim/src/xnu/xg_kext.cpp` 的 `xg_timing_fallback()`（约 519-540 行），
在"`gPanelEdidDtd` 解析成功就用 edid-dtd"**之前**插入一个最高优先的本机常量源：

```c
	/* A-27: this panel (3120x2080 @119.891 Hz, 900.045 MHz) cannot be expressed as an EDID DTD
	 * (the DTD pixel clock field tops out at 655.35 MHz), and the compiled-in gPanelEdidDtd is the
	 * NE160QDM-NZL 2560x1600 reference panel.  Publish the measured live raster directly. */
	static const uint32_t kOurPanel[13] = {
		0x4b350001u, 900045000u, 3120u, 3332u, 3336u, 3400u,
		2080u, 2202u, 2203u, 2208u, 119891u, 1u, 0u
	};
	{
		uint32_t w[XG_NVK5_TIMING_WORDS];
		memcpy(w, kOurPanel, sizeof(w));
		gTimingEdid = 0;
		xg_timing_store(nub, w, "static-panel");
		return;
	}
```

要点：
- 放在 fallback 函数的**最前面**（在 `gPanelEdidDtd` 那段之前），这样它会赢过 edid-dtd / vbt-dtd。
- `xg_timing_store` 会把 `gTimingSource` 记成 `static-panel`，并给 nub 设 `measured-panel-timing` —— 这两个是验收依据。
- 若编译器对"未使用变量"报错，就把后面那段包在 `#if 0 … #endif` 里（**不要删**，留作对照）。

### 2.2 重编 + 装 + 重启

```bash
R=~/src/NvGfx-xe-2.6.2; cd "$R"
cp gpu/xegfx/shim/src/xnu/xg_kext.cpp ~/xegfx-log/A-27/xg_kext.cpp.before

  bash build/nvgfx/build_xegfx.sh 2>&1 | tee ~/xegfx-log/A-27/build-core.log | tail -20

strings -a gpu/xegfx/out/XeGfx.kext/Contents/MacOS/XeGfx | grep -c "static-panel"
```
装上（同 A-26 的方式），`kmutil create … -z` 重落 KC，**核对含 `IGPUConsoleRange` + `XeGfxIntelFB` + `XeGfx` + `XeGfxDisplay`**，然后

**Stage A 判据**
| # | 判据 | 期望 |
| --- | --- | --- |
| A-1 | 编译退出 0、有二进制 | 是 |
| A-2 | `strings … | grep -c static-panel` | 1 |
| A-3 | `measured-panel-timing` 的十六进制 | 解出来是 **3120×2080 / 3400×2208 / 900045000** |
| A-4 | 屏幕 / panic | 3120×2080 正常、零新 panic |

```bash

python3 -c "import sys,struct;b=bytes.fromhex(sys.stdin.read().strip());
n=['tag','pclk','h_vis','h_ss','h_se','h_tot','v_vis','v_ss','v_se','v_tot','refr','hp','vp'];
```

## 3. Stage B：S3 接管（**黑屏风险，单独一次开机**）

**只有 Stage A 全绿才做。**

```bash
# 先把 fail 熔丝准备好（万一黑屏，重启后它能自己退回）
sudo nvram xegfx-disp-fail=%00
sudo nvram xegfx-disp-phase=%02
sudo nvram xegfx-disp-trial=%01
sudo nvram xegfx-disp-expose=%01
touch /var/db/xegfx/armed && sudo reboot
```
**开机后 3 分钟内只看三件事，别做别的：**
1. 屏幕有没有画面（是桌面 / 黑屏 / 彩噪 / 错位）
2. `ssh` 通不通
3. `ioreg -l -w0 | grep -c "class XeGfxIntelKMSFramebuffer"`

```bash
# SSH 若能进
system_profiler SPDisplaysDataType | grep -E "Resolution|Online|Main Display"
ioreg -l -w0 -c XeGfxIntelKMSFramebuffer 2>/dev/null | grep -oE "\"XeGfxDisplay(Inert|FbOpened)\" = [A-Za-z]+"
ioreg -l -w0 -c XeGfxIntelKMSFramebuffer 2>/dev/null | grep -oE "XeGfxFbModeReady|XeGfxDisplayVersion" | head -4
ioreg -l -w0 -c XeGfxDisplayNub 2>/dev/null | grep -c "kms-kapi"
sudo log show --last 5m --predicate 'eventMessage CONTAINS "XeGfxDisplay" OR eventMessage CONTAINS "S3" OR eventMessage CONTAINS "claim"' | tail -30
```

| 现象 | 判 | 下一步 |
| --- | --- | --- |
| 屏幕正常 + `XeGfxDisplayInert = No` + `XeGfxFbOpened = Yes` | ✅ S3 接管成功 | 进 Stage C |
| 屏幕正常但 `Inert = Yes` | S3 没走（preflight 拦了） | 贴 preflight 日志，停手 |
| 黑屏但 SSH 通 | 接管半途失败 | **立刻** `sudo nvram xegfx-disp-fail=%01; sudo nvram xegfx-disp-phase=%00; sudo reboot` |
| 黑屏且 SSH 不通 | 严重 | **断电一次**；起来后确认 `fail=1`；仍不行 → 删 `XeGfxDisplay.kext` + 恢复 KC 备份 |

## 5. 铁律

- **Stage A 与 B 之间必须分开**，各自一次开机。
- 所有加速动作都在**桌面稳定、WS 空闲 10 s 后**做；**不要在 boot 阶段推 stage 7 / accelfb=3**（A-25 已证伪）。
- 装 kext 用 `kmutil create -z`；**绝不 `kickstart` `kernelmanagerd` / `syspolicyd`**。
- armed 后 120 s 内不重启。
- 判"是否软件合成"必须**动画面**采样；`powermetrics` 的列是 `CPU ms/s`。
- 保留 `IGPUConsoleRange` / `XeGfxIntelFB`（兜底），不动探针分。
