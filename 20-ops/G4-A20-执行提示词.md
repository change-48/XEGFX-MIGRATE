# Gate 4 · A-20 执行提示词（换显示归属：让 NMIntelFB 真的 start）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **这是今天第一次动显示归属。** 有黑屏/hang 风险，但护栏、`nmintelfb-starts` 自动熔断、U 盘救援都在。
> **分两次开机：A-20a 只验证"不挂"，A-20b 才真正 start。**

---

## 0. 为什么要换归属（一句话）

`debug.nmxaccel_headless` 是 `static int gNvHeadless = 0` + `CTLFLAG_RD`（**只读、恒 0、改不了**）。
所以 NVMTL 插件永远对 WindowServer 说"Intel 拥有面板"，WS 于是加载 NVMTL，
但加速器并没有真的显示头 → 走到 `CompositorSW::CompositeLayersToDestination` 就 SIGABRT。

accel 源码 `nvrm-accel.cpp:103` 写明了设计前提：
> `4 NVIDIA heads + 1 for an Intel built-in panel (NMIntelFB, IOFBDependentIndex 4): WindowServer composites`

→ **必须让 NMIntelFB 成为 framebuffer、真正拥有面板**，加速器才有显示头。

---

## 1. 现场事实（主 agent 已核实，别重新探索）

| 项 | 值 |
| --- | --- |
| 现役 framebuffer | `IONDRVFramebuffer`（由 `IGPUConsoleRange` 注入控制台范围后启动）—— 它占着面板 |
| `NMIntelFB.kext` | `~/src/intelfb-pkg/NMIntelFB.kext`（已有编好的产物）；源码 `~/src/NvGfx-xe-2.6.2/kexts/NMIntelFB/intelfb.cpp` |
| 类继承 | `class NMIntelFB : public IOFramebuffer`（直接继承，不走 NDRV）—— 这是唯一有希望的路线 |
| 探针分 | NMIntelFB **60000** < IGPUConsoleRange **65000** → 现在 NMIntelFB 根本轮不到 |
| 刹车机制 | `-nmintelfboff`、`nmintelfbstop=N`（在 stage N 优雅 decline）、`nmintelfb-starts`（连续 2 次没到 WS 自动关）、`nmintelfb-step` 面包屑 |
| 10-30 结论 | 上次挂在 `IOFramebuffer::start()` 内部（面包屑停在 step 7）。源码注释说"在 start() 里对 DSM framebuffer 做 WC 映射挂死过两次（I-090）"，**该 WC 映射已移出 start()** → 本次值得重试 |
| 当前显示 | 3120×2080 原生、`SURF 0xfd000000`、`STRIDE 195`、`results = 0 1 1 1 1 1 1 1`（stage 4 已打通） |

## 2. ⚠️ 必须先修的一处源码：depid 写在了错的位置、用了错的 ID

`intelfb.cpp`（start() 尾部）现在是：

```c
if (!IOFramebuffer::start(provider)) { ...OOM; return false; }
// ...
setProperty("IOFBDependentID",    0x4E56524D00000001ull, 64);   // ← NVRM 的 ID
setProperty("IOFBDependentIndex", 4ull, 32);
```

10-30 的实测记录：**借 NVRM 的 `0x4E56524D…01` + Index 4 + 在 `super::start()` 之后设 → 启动 panic。**
正确写法：`0x5845474600000001`（ASCII `"XEGF"` + 1）、Index **0**、且**在 `IOFramebuffer::start()` 之前**设。

改法（两处，`start()` 与 `NMINTELFB_VIRTUAL` 分支各一处，本次只需改前者，但建议一起改成一致）：

```c
    // 放在 if (!IOFramebuffer::start(provider)) 之前
    setProperty("IOFBDependentID",    0x5845474600000001ull, 64);
    setProperty("IOFBDependentIndex", 0ull, 32);
    if (!IOFramebuffer::start(provider)) { OSSafeReleaseNULL(fMMIO); fRegs = nullptr; return false; }
```

**不动其他任何逻辑**（不改 adoptFirmwareMode 的读寄存器行为，不写显示引擎）。

## 3. 铁律

- **不许改 `IGPUConsoleRange`**（它是本关的兜底：NMIntelFB 一旦 decline/失败，它仍能接管让屏幕亮起来）。
- 只把 NMIntelFB 的 `IOProbeScore` 从 60000 提到 **66000**（压过 IGPUConsoleRange 的 65000），
  **这样 NMIntelFB 先试、失败了自动轮回到原路径** —— 这是本关最关键的安全设计。
- 一次开机只改一个变量：**A-20a = `nmintelfbstop=7`（只验证不挂）**；**A-20b = 去掉 stop（真 start）**。
- 每次重启前 `touch /var/db/xegfx/armed`（护栏会搬走 NMIntelFB）。
- **`fbgeom.sh` 要加一条跳过条件**：`kmutil showloaded | grep -q NMIntelFB` 时直接退出（不建 PTE、不设 SURF）。
  原因：NMIntelFB 在**开机早期** adopt 固件模式，而 `fbgeom` 在 WS 起来后才跑；
  两者同时改 SURF/几何会让 framebuffer 的认知与实际扫描不一致。等 A-20c 再统一。
- 不许动 OpenCore / boot-args；不许开 `debug.xegfxaccelfb` / `_iop`。
- macOS 没有 `timeout`；探针用 `( ... > out 2>&1 & )`。

## 4. A-20a：只验证"能加载、不挂、会优雅退出"（一次开机）

### 4.1 编译 + 组装

```bash
cd ~/src/NvGfx-xe-2.6.2
cp kexts/NMIntelFB/intelfb.cpp ~/xegfx-log/A-20/intelfb.cpp.before    # 先备份
# 按 §2 改两行（editor 或 python 都行），确认：XEGF ID、Index 0、且在 super::start() 之前
grep -n -B2 -A2 "IOFBDependentID" kexts/NMIntelFB/intelfb.cpp

SDKROOT=MacOSX26.5.sdk OUTROOT=~/src/NvGfx-build/kexts bash build/nvgfx/build_nmintelfb.sh
ls -l ~/src/NvGfx-build/kexts/NMIntelFB.kext/Contents/MacOS/NMIntelFB
```

### 4.2 提探针分 + 装 + 刹车

```bash
P=~/src/NvGfx-build/kexts/NMIntelFB.kext/Contents/Info.plist
/usr/libexec/PlistBuddy -c "Set :IOKitPersonalities:NMIntelFB:IOProbeScore 66000" "$P" 2>/dev/null || \
/usr/libexec/PlistBuddy -c "Print :IOKitPersonalities" "$P"     # 先看真实 personality 键名
plutil -lint "$P"; plutil -p "$P" | grep -E "IOProbeScore"

sudo rm -rf /Library/Extensions/NMIntelFB.kext
sudo cp -R ~/src/NvGfx-build/kexts/NMIntelFB.kext /Library/Extensions/NMIntelFB.kext
sudo find /Library/Extensions/NMIntelFB.kext -name '._*' -delete
sudo xattr -cr /Library/Extensions/NMIntelFB.kext
sudo chown -R root:wheel /Library/Extensions/NMIntelFB.kext && sudo chmod -R 755 /Library/Extensions/NMIntelFB.kext
sudo codesign --force --sign - /Library/Extensions/NMIntelFB.kext && sudo codesign -v /Library/Extensions/NMIntelFB.kext && echo SIGN-OK

# 清掉历史面包屑与熔断计数
sudo nvram -d nmintelfb-step 2>/dev/null; sudo nvram -d nmintelfb-step-prev 2>/dev/null; sudo nvram -d nmintelfb-starts 2>/dev/null

sudo kmutil install --volume-root / --allow-missing-kdk -v
sudo kmutil inspect 2>/dev/null | grep -A14 "auxiliary kext"    # 必须含 IGPUConsoleRange + NMIntelFB + XeGfx + Accel
```

### 4.3 加 `nmintelfbstop=7` 并重启

**`nmintelfbstop` 是 boot-arg，只能写进 OpenCore config**（NVRAM 里设了也会被 config 的 Delete/Add 覆盖）：

```bash
sudo diskutil mount disk0s1
P="/Volumes/NO NAME/EFI/OC/config.plist"
sudo cp -p "$P" "$P.bak-before-nmintelfbstop-$(date +%Y%m%d-%H%M%S)"
# 在当前 boot-args 末尾追加 nmintelfbstop=7（保持其余全不变）
sudo /usr/libexec/PlistBuddy -c "Print :NVRAM:Add:7C436110-AB2A-4BBB-A880-FE41995C9F82:boot-args" "$P"
sudo /usr/libexec/PlistBuddy -c "Set :NVRAM:Add:7C436110-AB2A-4BBB-A880-FE41995C9F82:boot-args -v keepsyms=1 -vi2c-force-polling -amfipassbeta amfi_get_out_of_my_way=0x1 amfi=0x80 ipc_control_port_options=0 itlwm_cc=CN nmintelfbstop=7" "$P"
sudo plutil -lint "$P" && sudo diskutil unmount "/Volumes/NO NAME"

touch /var/db/xegfx/armed && sudo reboot
```

### 4.4 回来之后

```bash
nvram nmintelfb-step ; nvram nmintelfb-step-prev        # 期望 step = 7（在 super::start 前优雅退出）
sudo kmutil showloaded | grep -i nmintelfb || echo "NMIntelFB 未载入（decline 正常）"
system_profiler SPDisplaysDataType | grep -E "Resolution|Main Display"
pgrep -x WindowServer
sudo log show --last 10m --predicate 'eventMessage CONTAINS "NMIntelFB"' | tail -10
```
**判据**：屏幕正常、SSH 在、`nmintelfb-step = 7`。这说明"能加载、能走到第 7 步、能优雅退出"，
**还没真正 start** —— 这一轮不追求它生效，只追求"不会挂"。

## 5. A-20b：真 start（第二次开机）

**只有 A-20a 拿到 step=7 且屏幕正常才做。**

```bash
# 把 boot-args 里的 nmintelfbstop=7 去掉（恢复原样）
sudo diskutil mount disk0s1
sudo /usr/libexec/PlistBuddy -c "Set :NVRAM:Add:7C436110-AB2A-4BBB-A880-FE41995C9F82:boot-args -v keepsyms=1 -vi2c-force-polling -amfipassbeta amfi_get_out_of_my_way=0x1 amfi=0x80 ipc_control_port_options=0 itlwm_cc=CN" "/Volumes/NO NAME/EFI/OC/config.plist"
sudo plutil -lint "/Volumes/NO NAME/EFI/OC/config.plist" && sudo diskutil unmount "/Volumes/NO NAME"
touch /var/db/xegfx/armed && sudo reboot
```

可能三种结果：

| 结果 | 判据 | 下一步 |
| --- | --- | --- |
| **成功** | `ioreg -c NMIntelFB` 有实例、`IOFBDependentID/Index` = XEGF/0、屏幕亮、WS 在 | 进 §6 验 Gate 4 |
| **优雅失败** | `nmintelfb-step = 7`、屏幕仍亮（IGPUConsoleRange 接管）、`nmintelfb-starts` +1 | 说明写进去仍失败但没挂 → 报告，查 step 7 内部失败原因 |
| **hang** | SSH 180 s 不通 | **断电一次**。`nmintelfb-starts` 已 +1；若再挂一次会自动熔断（第三次开机 NMIntelFB 自己 decline）。屏幕恢复后立刻 `sudo nvram -d nmintelfb-starts` 并报告 |

## 6. 若 A-20b 成功：验 Gate 4

```bash
sudo kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60 ; sudo sysctl -w debug.xegfx_stage=7 ; sleep 25
sudo sysctl -b debug.xegfx_results | od -A n -t d4
ioreg -c NMXAccel -l -w0 | grep -E "MetalPluginName|IOFBDependent"
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null | grep -ci nvmtl        # 必须带 sudo
sudo sample "$(pgrep -x WindowServer)" 3 -file ~/xegfx-log/A-20/ws-sample.txt >/dev/null 2>&1
grep -cE "CA::OGL::SW|scanline|draw_polygon" ~/xegfx-log/A-20/ws-sample.txt   # 关键：应显著下降
sudo powermetrics --samplers tasks -n 1 2>/dev/null | sed -n '12,16p'         # 带上表头！CPU ms/s
system_profiler SPDisplaysDataType | grep -i metal
```

**判据（按重要性）**
1. `CA::OGL::SW` 计数**显著下降**（软件合成时是 300–450 行）→ 这是"真的换了合成器"的硬证据
2. `vmmap` nvmtl > 0
3. 不再有新的 `WindowServer-*.ips`（尤其 `CompositorSW::CompositeLayersToDestination`）
4. `Metal: Supported`（`Metal 3` 若出现更好）

## 7. 救援与回滚（务必先读）

| 情况 | 动作 |
| --- | --- |
| hang（SSH 不通） | 断电一次 → 等它自己起来。`nmintelfb-starts` 会 +1；连续两次后自动熔断 |
| 起来但黑屏 | SSH 进去：`sudo nvram nmintelfb-starts` 看计数；`sudo kmutil unload -b com.nullmoth.NMIntelFB`（可能被拒）→ 否则重启 |
| 完全起不来 | U 盘 `D:\EFI` 启动（它的 config 带 `-x`）→ 删 `/Library/Extensions/NMIntelFB.kext` → 重建 KC |
| 彻底不行 | `sudo cp` 用 §4.1 的 `intelfb.cpp.before` 还原源码，重编装回，或直接删 kext + 用备份的 AuxKC |

**注意：`fbgeom.sh` 已按 §3 加了 "检测到 NMIntelFB 就跳过"。NMIntelFB 失败时它会重新接管几何** ——
但 `fbgeom` 在 WS 起来后才跑，若 NMIntelFB 失败且屏幕黑，先重启，别在黑屏时等脚本。

## 验收锚点（主 agent 独立跑）

1. `nvram nmintelfb-step`（A-20a 应为 7）。
2. `ioreg -c NMIntelFB -l -w0 | grep -E "IOFBDependentID|IOFBDependentIndex|built-in"` → `0x5845474600000001` / `0` / Yes。
3. `sudo kmutil inspect` 仍含 `IGPUConsoleRange`（兜底没被拆掉）。
4. A-20b 后：`grep -cE "CA::OGL::SW|scanline|draw_polygon" ws-sample.txt` 明显小于 300。
5. 零新 panic；屏幕可读；`fbgeom.log` 在 NMIntelFB 在场时应显示"跳过"。
