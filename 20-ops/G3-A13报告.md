## 2. 本关最重要的发现：几何寄存器要「SURF 锁存」

### 2.1 现象

严格按提示词 §5 的顺序执行（`reg surf` 在前、`regset` 在后）：

```
regset 3 2 195 1 0x081F0C2F 3 0x0C2F081F
reg[2] wrote 0x000000c3  read 0x000000c3     ← 回读全对
reg[1] wrote 0x081f0c2f  read 0x081f0c2f     ← 回读全对
reg[3] wrote 0x0c2f081f  read 0x0c2f081f     ← 回读全对
SURFLIVE 0x01000000  PS_CTRL 0x80000200
```

20 秒后寄存器仍是新值、`SURF` 没被 macOS 打回、`PIPESTAT = 0`（无 underrun）——**但屏幕只有左上角一块紫色竖条纹，其余全黑**。

随后改用纯白填充，屏幕是**左上角一块白，横向约 3/5、竖向约 1/2**，即 **1920×1080 的矩形**（3/5×3120≈1872，1/2×2080≈1040）。

### 2.2 机制

`PLANE_STRIDE / PLANE_SIZE / TRANS_PIPESRC`（以及 `PS_WIN_SZ`）都是**双缓冲**寄存器：写进去只是进了"暂存区"，回读读的也是暂存值；**只有带 `PLANE_SURF` 的那次更新才会把几何一起锁存生效**。

提示词 §5 的顺序是「先 `reg surf` 换表面，再 `regset` 改几何」→ 几何永远等不到下一次 SURF 更新 → **硬件仍在用 1920×1080 的旧几何去扫一块 3120 宽的缓冲**，于是出现"只有 1/2 画面、其余黑/条纹"这种既不等于成功也不等于 A-12 失锁的第三种状态。

补一次 SURF 更新后立刻正常：

```
reg surf 0x01001000 → SURFLIVE 0x01001000
reg surf 0x01000000 → SURFLIVE 0x01000000
→ 屏幕：全屏纯白（几何 3120 生效）
```

### 2.3 对提示词的更正

| 提示词原话 | 实测 |
|---|---|
| §3「只写三个平面寄存器 …… 三个几何寄存器必须背靠背写完再等」 | 背靠背写**是对的**（不锁存就不会半改），但**还必须以一次 SURF 更新收尾**才能真正生效 |

| §1「S2 最可能的致命动作是清 PS_CTRL bit31」 | ✅ 复核成立：本关全程没碰 `PS_CTRL`，管道一次没失锁、macOS 一次没抢回 |

## 3. 三条新增的硬事实（会改后续 gate 的假设）

### 3.1 缩放比由硬件自己算，1.0 = `0x8000`

`PS_HSCALE(0x68190)` / `PS_VSCALE(0x68184)` 我们**从没写过**，但改 `PIPESRC` 后它们自己变了：

| 时刻 | PIPESRC | HSCALE | VSCALE | 含义 |
|---|---|---|---|---|
| 基线 | 1920×1080 | `0x4EC5` | `0x4276` | 20165/32768 = 0.6153 = **1920/3120**；17014/32768 = 0.5192 = **1080/2080** |
| 写入 3120 后 | 3120×2080 | `0x8000` | `0x8000` | **1.0 = 1:1** |
| `restore` 后 | 1920×1080 | `0x4EC5` | `0x4276` | 回到 1.625× 放大 |

→ **这是"缩放比确实变成 1:1"的硬件侧证据**，不依赖肉眼。也说明提示词把 `PIPESRC` 当"缩放器输入"是对的。

### 3.2 时序、DDI、水位全部健康，本关没有 underrun

`dump` 新增只读通路后实测（`xenative-ctl dump <off> [n]`）：

| 寄存器 | 值 | 解读 |
|---|---|---|
| `TRANS_HTOTAL_A 0x60000` | `0x0D470C2F` | 3400 / hdisplay 3120 —— 与提示词一致 |
| `TRANS_VTOTAL_A 0x6000C` | `0x089F081F` | 2208 / vdisplay 2080 |
| `TRANS_DDI_FUNC_CTL_A 0x60400` | `0x8A000006` | 本次读数，**不是 0**（提示词 §1 表的 `0x00000000` 是另一时刻的读数） |
| `PIPE_CONF_A 0x70008` | `0xC0000000` | 管道使能 |
| `PIPEASTAT 0x70024` | `0x00000000` | **无 underrun / 无异常位** |
| `PLANE_BUF_CFG 0x7027C` | `0x07FF0000` | DDB 给满 |
| `PLANE_WM_1_A 0x70240` | `0x80008035`（L0 使能，L1..L3 关闭） | 水位未被改动 |

→ 之前怀疑的"带宽/水位不够"在本关被排除：**几何生效后画面干净，没有撕裂、没有花屏**。

### 3.3 `restore` 原实现会留下错位屏（已修）

`doRestore` 原来的顺序是 **先写 SURF、再写几何**——正好踩中 §2 的双缓冲：几何没锁存，桌面缓冲被按 3120 的旧几何扫 → 屏幕"铺满但对不齐，右边绕到左边，轻微花屏"。本次现场出现并被修复。

修法：几何先写（暂存）→ `SURF + 0x1000` 制造一次更新 → 写回 `SURF`（锁存）→ 停 60ms。

## 6. 给 Gate 3 收尾 / 下一步（不用现在做）

1. **顺序成为铁律**：任何改 `STRIDE/SIZE/PIPESRC` 的操作，都必须以 `regset → reg surf → latch`（或 `latch`）收尾，否则是"回读正确、屏幕错误"的假象。
2. **`regset` 与 macOS 的 flip 有交互**：一旦几何被暂存，macOS 下一次自己的 SURF 更新会**用我们的几何去锁存它的 1080p 缓冲** → 满屏错位（本轮已真实撞到一次）。所以正式做"让 macOS 画进原生缓冲"时，几何必须和 macOS 自己的模式切换一起做，不能"先摆好几何等它翻页"。
3. **真正的收尾没变**（提示词 §8）：把 `IGPUConsoleRange` / `NMIntelFB` 的 adopt 分支改成 3120×2080 / stride 12480，让 macOS 直接往 `phys 0x800000` 那块 26 MiB 连续缓冲里画。本关证明了"平面 → 缩放器（1:1）→ transcoder → 面板"这一段已经通，剩下的纯粹是让系统用满那块缓冲。
4. `PS_HSCALE/PS_VSCALE` 可以当**只读判据**用：`0x8000` = 1:1，非 `0x8000` = 还在缩放。以后不用拍照也能判断"是否 1:1"。
