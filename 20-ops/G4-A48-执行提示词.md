# Gate 4 · A-48 执行提示词：证明显示引擎接受 12544 行距（零代码，A/B）

> A 方案的前提是"面板能以 12544 行距扫描"。在动 kext 之前先证明这一点。
>
> **本关不改代码、不重编、不重启。** 只用已装的 `xenative-ctl`（XeNative 0.14）做一次 A/B：
> 缓冲里是按 **12480** 行距填好的图案，把 `PLANE_STRIDE` 改成 **196**（12544）后，
> 若显示引擎采纳，画面会出现**每行右移 16 像素的阶梯斜切**；不采纳则画面毫无变化。

---

## 0. 为什么这个 A/B 能回答问题

### 0.1 算术

| 量 | 值 |
| --- | --- |
| 缓冲里的图案行距（`fill` 写入） | 12480 = **195** × 64 = 3120 px |
| 测试时告诉引擎的行距 | 12544 = **196** × 64 = **3136 px** |
| 每行的起始偏移差 | 16 px |

所以每一行的内容相对上一行右移 16 像素（并在右边缘回绕）：**红蓝分界会变成向右的阶梯**，
每 195 行绕回一次。这个特征肉眼一眼可辨，且**与"引擎是否读了这个寄存器"一一对应**。

### 0.2 为什么安全

- `fill` 仍按 **12480** 写缓冲 → **不写**缓冲之外的 130 KB。
- 改 stride 只影响**读取**：最多读到缓冲末尾之外 130 KB（仍在 stolen 区内），不破坏数据。
- `restore` 会把 SURF/SIZE/STRIDE/PIPESRC/PS_CTRL 五个寄存器原样放回（A-10 已验证）。

### 0.3 现有工具（都已装）

```
xenative-ctl status            读寄存器与决策状态
xenative-ctl fill [wb]         把图案（左红右蓝）写进缓冲，按 12480 行距
xenative-ctl regset <n> <which> <value> …    写寄存器（0=SURF 1=SIZE 2=STRIDE 3=PIPESRC 4=PS_CTRL 5=PLANE_CTL）
xenative-ctl restore           五个寄存器原样放回
```

现场读数（18:46 实测）：

```
PLANE_STRIDE     195
PLANE_SIZE       0x081f0c2f        (rows-1=0x081f=2079 → 2080 行; cols-1=0x0c2f=3119 → 3120)
SURF             0xfd000000
SURFLIVE         0xfd000000
phys_base        0x71800000
FRMCOUNT         1749304
```

## 3. A/B：先 195（对照），再 196（实验）

### 3.1 对照组：把面板指向缓冲，**行距仍是 195**

```bash
sudo /usr/local/bin/xenative-ctl regset 3 \
  1 0x081f0c2f \
  2 195 \
  0 0xfd000000 | tee $L/ab-195.txt
sleep 2
sudo /usr/local/bin/xenative-ctl status | grep -E "PLANE_STRIDE|PLANE_SIZE|SURF |FRMCOUNT" | tee -a $L/ab-195.txt
```

**请用户看屏幕并回答：是不是"左红 / 右蓝"、分界线是**直的竖线**？**（预期：是）

### 3.2 实验组：**只把行距改成 196**

```bash
sudo /usr/local/bin/xenative-ctl regset 2 \
  1 0x08140c2f \
  2 196 \
  0 0xfd000000 | tee $L/ab-196.txt
sleep 2
sudo /usr/local/bin/xenative-ctl status | grep -E "PLANE_STRIDE|PLANE_SIZE|SURF |FRMCOUNT" | tee -a $L/ab-196.txt
```

> `SIZE` 用 `0x08140c2f`：rows-1 = 0x0814 = 2068 → **2069 行**。
> 2069 × 12544 = 25,953,536 ≤ 缓冲 25,958,400 ⇒ **读取不会越界**。
> （若坚持 2080 行会读到缓冲外 130 KB；本关刻意用 2069 行避开这一点，底部 11 行会是旧内容，不影响判断。）

**请用户看屏幕并回答：分界线是不是变成了向右的**阶梯/斜线**（每行右移约 16 像素）？**

## 4. 判读（这是本关的全部结论）

| 195 时 | 196 时 | 结论 |
| --- | --- | --- |
| 直线 | **阶梯/斜线** | **引擎采纳 stride** ⇒ A 方案可行，可以进入"分配 12544 缓冲"的实现 |
| 直线 | **直线（无变化）** | 引擎**忽略**了 stride（或它只认某一组值）⇒ A 方案在此硬件上不成立，停手 |
| 直线 | 黑屏/花屏/闪烁 | stride 被采纳但值不合适 ⇒ 记录现象，停手 |
| 两次都是阶梯 | `fill` 的图案本身行距不是 12480 | 先查 `fill`，本关作废 |

## 5. 必须收尾（**无论结果如何**）

```bash
sudo /usr/local/bin/xenative-ctl restore | tee $L/restore.txt
sleep 2
sudo /usr/local/bin/xenative-ctl status | tee $L/status-after.txt
```

**门 3：`PLANE_STRIDE` 回到 **195**、`PLANE_SIZE` 回到 `0x081f0c2f`、`SURF` 回到 `0xfd000000`，
且**用户确认桌面恢复正常**（WS 每帧拷贝会把画面重新写上去，通常一秒内）。**

若 `restore` 后屏幕不正常：
```bash
sudo /usr/local/bin/xenative-ctl regset 3 1 0x081f0c2f 2 195 0 0xfd000000
```
仍不正常 → `sudo shutdown -r now`（重启后 FB 会重新编程模式，不会留后遗症）。
