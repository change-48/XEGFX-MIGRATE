# Gate 4 · A-25 执行提示词（量准第 3 条 + 让成果活过重启）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **A-25a 不重启（只测量）；A-25b 一次重启（装自启并验证冷启动）。**
> 现在机器上 core+accel 是**手动**加载的，`vmmap nvmtl = 18`、`Metal Support: Metal 3` 都成立 —— 但那活不过下次重启。

---

## 0. 已知与未知

**已成立**
- `vmmap $(pgrep -x WindowServer) | grep -ci nvmtl` = **18**
- `system_profiler` → `Metal Support: Metal 3`、`3120 x 2080`
- WindowServer **运行时**就把插件装进来了（`NVMTL: vk: UP in this Metal process … Intel(R) Graphics (ARL)`），**没重启 WS**
- `mtlprobe` 独立 16/16；`0xe00002c7` 0 次；屏幕干净、零新 panic

**未验证**
- Gate 4 第 3 条「不再软件合成」：**还没量准**。之前的 sample 都在**静止桌面**下采的，两边都是 0，没有判别力。
- 冷启动可复现性：core / accel **不自动加载**，重启后 `vmmap` 会回到 0。

---

## 1. 铁律

- A-25a 全程**不重启、不改任何文件**，只采样。
- A-25b 只新增一个 LaunchDaemon + 一个脚本，**不动** `fbgeom` / `guard` / kext / OpenCore / 探针分。
- `powermetrics` 的列是 **`CPU ms/s`**（1000 = 一整个核），不是百分比；**必须连表头一起存**。
- `sample` 只有在**画面在动**时才有判别力；静止桌面的 0 不算证据。
- 重启前 `touch /var/db/xegfx/armed`；**armed 后 120 s 内不要再重启**。
- 不许 `kickstart` `kernelmanagerd` / `syspolicyd`。

## 2. A-25a：把"是否还在软件合成"量准（不重启）

### 2.1 三个互相独立的信号，一起采

```bash
mkdir -p ~/xegfx-log/A-25

# 先确认现状
sudo /usr/bin/kmutil showloaded | grep -cE "org.watchthelight.XeGfx"
ioreg -c NMXAccel -l -w0 | grep -c "MetalPluginName"
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null | grep -ci nvmtl

# 信号 A：让画面动起来，然后立刻采 WS 的栈
open -a TextEdit            # 若打不开就用： open -a Finder / 或 open ~/Desktop
sleep 2
sudo sample "$(pgrep -x WindowServer)" 5 -file ~/xegfx-log/A-25/ws-moving.txt >/dev/null 2>&1
grep -cE "CA::OGL::SW|scanline|draw_polygon" ~/xegfx-log/A-25/ws-moving.txt      # 期望 ≈ 0
grep -cE "CA::MTL|MTLCommandBuffer|IOGPU|NVMTL|MetalContext" ~/xegfx-log/A-25/ws-moving.txt  # 期望 > 0

# 信号 B：GPU 有没有在干活（软件合成时 GPU 基本空闲）
sudo powermetrics --samplers gpu_power -n 2 2>/dev/null | tee ~/xegfx-log/A-25/gpu-power.txt
#   看 "GPU Busy"/"GPU active residency" 之类字段；采两次，中间让画面动

# 信号 C：WS 是否拿到了加速器设备
ioreg -r -c IOAccelerator -l -w0 | head -20
lsof -p "$(pgrep -x WindowServer)" 2>/dev/null | grep -ci nvmtl
```

### 2.2 判读

| 组合 | 结论 |
| --- | --- |
| A：`CA::OGL::SW` ≈ 0 **且** 出现 Metal 符号；C：`lsof` 有 nvmtl | ✅ **真的用核显合成** → Gate 4 第 3 条成立 |
| A：`CA::OGL::SW` 仍有几百行 | ❌ 仍在软件合成（此时 Metal 只是被映射，没参与） |
| A 有 Metal 符号但 `CA::OGL::SW` 也很多 | ⚠️ 混合：部分层走 GPU、部分仍在 SW → 记录比例，报告 |

> 关键纪律：**同一状态下前后各采一次**（加载 accel 前 vs 后）才叫 A/B。现在是"已加载"状态，
> 若要做严格 A/B，就等 A-25b 冷启动前采一次（那时 accel 未加载）。

## 3. A-25b：让成果活过重启（一次重启）

### 3.1 写脚本 `/usr/local/bin/xegfx-boot.sh`

参考旧脚本 `~/_xegfx-old-20261030/misc/xegfx-bootarm.sh`（有"连续 3 次失败自我禁用"的自愈），
但**步骤按今天的实际情况重写**（旧版只有 load + stage，没有 accel 与 accelfb）：

```bash
#!/bin/bash
# 开机把 CPU 侧的加速链路拉起来：core → accel → stage 7 → accelfb=3
set -u
export PATH=/usr/bin:/bin:/usr/sbin:/sbin
STATE=/var/db/xegfx-boot ; LOG=/var/db/xegfx/boot.log
mkdir -p "$STATE"
log(){ echo "[$(date '+%F %T')] $*" >> "$LOG"; }

if [ -f "$STATE/disabled" ]; then log "self-disabled, skip"; exit 0; fi
N=$(( $(cat "$STATE/attempts" 2>/dev/null || echo 0) + 1 )); echo "$N" > "$STATE/attempts"
if [ "$N" -gt 3 ]; then log "连续 $N 次未成功 → 自我禁用"; touch "$STATE/disabled"; exit 0; fi
log "=== boot-arm start (attempt $N) ==="

ok=0
for i in $(seq 1 20); do                      # 等 IOPCIDevice 与 drm 就绪，最多 100 s
    /usr/bin/kmutil load -b org.watchthelight.XeGfx >/dev/null 2>&1
    if /usr/sbin/sysctl -a 2>/dev/null | grep -q debug.xegfx_stage; then ok=1; break; fi
    sleep 5
done
[ "$ok" = 1 ] || { log "core 未能暴露 sysctl（放弃本轮）"; exit 0; }

/usr/sbin/sysctl -w debug.xegfx_wdog=60  >/dev/null 2>&1
/usr/sbin/sysctl -w debug.xegfx_stage=7  >/dev/null 2>&1
sleep 20

# accel 依赖 core 在 IOPCIDevice 上打的 nmxgpu-claimed，所以必须在 stage 7 之后 load
for i in $(seq 1 10); do
    /usr/bin/kmutil load -b org.watchthelight.XeGfxAccel >/dev/null 2>&1
    if ioreg -c NMXAccel -l 2>/dev/null | grep -q MetalPluginName; then break; fi
    sleep 3
done
sleep 3
/usr/sbin/sysctl -w debug.xegfxaccelfb=3 >/dev/null 2>&1

# 结果
R=$(/usr/sbin/sysctl -b debug.xegfx_results 2>/dev/null | od -A n -t d4 | tr -s ' \n' ' ')
log "results:$R"
ioreg -c NMXAccel -l -w0 2>/dev/null | grep -c MetalPluginName | while read n; do log "NMXAccel 实例: $n"; done
if /usr/bin/vmmap "$(pgrep -x WindowServer)" 2>/dev/null | grep -qi nvmtl; then
    log "vmmap nvmtl > 0 ✅"; echo 0 > "$STATE/attempts"
else
    log "vmmap nvmtl = 0（WS 可能还没加载插件，稍后复查）"
fi
log "=== done ==="
```

> 注意：`vmmap` 在脚本里可能拿不到（WS 是 root），失败也没关系 —— 它只影响日志里的提示，不影响加速链。
> **`echo 0 > attempts` 只在 `vmmap` 成功时才做**，避免"没成功也算成功"。

`/Library/LaunchDaemons/org.xegfx.boot.plist`：`RunAtLoad=true`、**不要 KeepAlive**、
`StandardOut/Err` 指 `/var/db/xegfx/`、`ProgramArguments=[/usr/local/bin/xegfx-boot.sh]`。

```bash
sudo chown root:wheel /usr/local/bin/xegfx-boot.sh && sudo chmod 755 /usr/local/bin/xegfx-boot.sh
sudo launchctl bootstrap system /Library/LaunchDaemons/org.xegfx.boot.plist
sudo launchctl list | grep xegfx.boot
rm -f /var/db/xegfx-boot/disabled          # 清历史熔断
```

### 3.2 冷启动前，先采一次"未加载"的基线（给 A-25a 补 A/B）

```bash
sudo kmutil unload -b org.watchthelight.XeGfxAccel 2>&1 | tail -1
sudo kmutil unload -b org.watchthelight.XeGfx 2>&1 | tail -1
# 若卸载被拒（in use）→ 直接重启，重启后自动就是未加载状态
open -a TextEdit ; sleep 2
sudo sample "$(pgrep -x WindowServer)" 5 -file ~/xegfx-log/A-25/ws-sw-baseline.txt >/dev/null 2>&1
grep -cE "CA::OGL::SW|scanline|draw_polygon" ~/xegfx-log/A-25/ws-sw-baseline.txt
```

### 3.3 重启并验证冷启动

```bash
touch /var/db/xegfx/armed && sudo reboot
```
回来后（等 boot 脚本跑完，约 30–100 s）：

```bash
cat /var/db/xegfx/boot.log | tail -25
sudo /usr/bin/kmutil showloaded | grep -cE "org.watchthelight.XeGfx"
ioreg -c NMXAccel -l -w0 | grep -E "MetalPluginName|MetalPluginClassName"
sudo sysctl -b debug.xegfx_results | od -A n -t d4
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null | grep -ci nvmtl      # ★ 冷启动后应 > 0
system_profiler SPDisplaysDataType | grep -iE "Metal|Resolution"
pgrep -x WindowServer; tail -5 /var/db/xegfx/fbgeom.log
```

**判据**：冷启动（无任何手动操作）后 `vmmap nvmtl > 0` 且 `Metal Support: Metal 3` 且屏幕干净 → **Gate 4 稳态成立**。

若 `boot.log` 显示失败，用它的 attempts/disabled 机制诊断，**不要**在重启后手动补一遍就当成功 —— 那说明自启没生效。
