# Gate 4 · A-19c 执行提示词（固化搬迁 + 受控 A/B 量 CPU + 判 Metal 级别）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **A-19a 已证明：把帧缓冲的 GGTT 入口从 `0xFE600000` 挪到 `0xFD000000`，加速器就不再抢它。**
> 本关把这件事**固化到开机自愈**，并把 Gate 4 剩下两条判据**按受控方式**量出来。

---

## 0. 为什么必须重测那两条

A-19a 报告把「Gate 4 四条」全打了 ✅，但主 agent 复核后**只有两条成立**：

| # | 判据 | 复核结论 |
| --- | --- | --- |
| 1 | `NMXAccel` 1 实例、`MetalPluginName` → NVMTLDriver | ✅ 成立 |
| 2 | `vmmap WindowServer \| grep -c NVMTL` > 0 | ✅ 成立（18，历史首次） |
| 3 | 不是软件合成 | ❌ **读数误读**，见下 |
| 4 | 系统报 `Metal 3` | ⚠️ 只报 `Metal: Supported`，级别未验 |

**第 3 条的错在哪**：`powermetrics --samplers tasks` 的列是 **`CPU ms/s`，不是百分比**（主 agent 实测表头）：
```
Name        ID   CPU ms/s   User%   Deadlines(<2ms,2-5ms)  Wakeups(Intr, Pkg idle)
```
`300.32` = **每秒 300 毫秒 CPU = 30% 单核**。计划判据「< 25%」按 ms/s 是 250，300 仍略超。
更麻烦的是：**当前基线（未装 accel、纯软件合成）实测 `375.03 ms/s`**,比装 accel 时的 300 还高 ——
单点采样完全没有判别力。必须**同条件 A/B**。

---

## 1. 铁律

- 一次只改一个变量：**A-19c-1 = 固化搬迁**；**A-19c-2 = 受控 A/B 测量**。中间不许夹别的改动。
- 固化只改 `/usr/local/bin/xegfx-fbgeom.sh`（加建 PTE + 设 SURF），**不改 kext、不重编、不动 OpenCore**。
- **`scan` 的 `live_run_pages` 在换过 SURF 之后不可信**（它锚在 `fSurfBefore`，只在 init 赋一次值）。
  验证 PTE 一律用 `xenative-ctl dump 0x800000+idx*8` 抽样，或 `mapfast` 的回读。
- **远端循环必须收尾**：任何 `while/for` 循环要么写进脚本文件、要么结束时 `ssh ... pkill -9 -f <标记>`。
  只掐本地 ssh 不会杀掉远端循环，会把驱动的客户端名额耗尽（之后所有 `IOServiceOpen` 等 15 s 返回 `0xe00002bc`，只能重启清）。
- macOS **没有 `timeout`**；探针用 `( ./mtlprobe > out 2>&1 & )`。
- 每次重启前 `touch /var/db/xegfx/armed`；重启后核对 AuxKC 含 `IGPUConsoleRange`。

## 2. A-19c-1：把搬迁固化进开机自愈（一次重启）

### 2.1 现状（先读，别猜）

```bash
cat /usr/local/bin/xegfx-fbgeom.sh          # 现有内容：只做 regset + latch
cat /var/db/xegfx/fbgeom.log | tail -5
```
现有脚本逻辑：轮询 `system_profiler` 直到报 `3120 x 2080`，然后 `regset`（STRIDE/SIZE/PIPESRC）→ `latch`。

### 2.2 要加的三步（在 `latch` **之前**）

```bash
# 1) 把帧缓冲的 GGTT 入口建到 0xFD000000（6656 页，物理 0x800000 起）
/usr/local/bin/xenative-ctl mapfast 0xFD000 6656 0x800000
#    期望 first 0x800003 / last 0x21ff003 / bad 0 —— bad 不为 0 就中止，不要 latch

# 2) 把平面指过去
/usr/local/bin/xenative-ctl reg surf 0xFD000000

# 3) 再 latch（沿用现有实现）
/usr/local/bin/xenative-ctl latch
```

顺序要点：
- `mapfast` 必须在 `reg surf` 之前（先有映射再指过去）。
- `latch` 必须最后（几何与 SURF 的双缓冲靠它锁存）。
- **只有 `mapfast` 的 `bad 0` 才继续**；否则记日志退出，保持现状（宁可没搬，也不要指到坏映射）。
- 幂等：每次开机都重建一遍，重复跑无害。

### 2.3 验证固化是否生效（重启后）

```bash
sudo /usr/local/bin/xenative-ctl status | grep -E "SURF|STRIDE|SIZE|PIPESRC|PS_CTRL"
#   期望 SURF/SURFLIVE = 0xfd000000、STRIDE 195、SIZE 0x081F0C2F、PIPESRC 0x0C2F081F
sudo /usr/local/bin/xenative-ctl dump 0x800000 2      # idx 0xFD000  → 期望 0x00800003
sudo /usr/local/bin/xenative-ctl dump 0xff4ff8 2      # idx 0xFE9FF  → 期望 0x021ff003
tail -8 /var/db/xegfx/fbgeom.log
```
**屏幕必须是完整桌面、无错位**（物理内存没变，只换了 GGTT 入口）。

> 若 `SURF` 不是 `0xfd000000`：说明 macOS 在脚本之后又重设过 SURF（例如登录时）。
> 那就把脚本改成常驻守护（每 5 s 检查一次、不一致就重设），**但先报告再改**，不要自己扩大范围。

## 3. A-19c-2：受控 A/B 量 CPU（本关的关键测量）

**必须在同一台机、同一次开机、同样条件下测两组**，否则数字没有意义（A-19a 就是栽在这）。

### 3.1 准备（把噪声清掉）

```bash
# 等系统安静：连续 3 次采样，ReportCrash / DEAD_TASKS 不应出现在前几名
sudo powermetrics --samplers tasks -n 1 2>/dev/null | sed -n '12,20p'
```
如果 `ReportCrash` 还在跑，等它结束（或先 `sudo launchctl bootout` 不必要 —— **不要杀系统进程**，等就行）。

### 3.2 A 组：软件合成基线（**不要加载 XeGfx**）

```bash
# 确认未加载
sudo kmutil showloaded | grep -i xegfx || echo "XeGfx 未加载（正确）"
# 桌面静止 10 s 后，连采 3 次
for i in 1 2 3; do
  sudo powermetrics --samplers tasks -n 1 2>/dev/null | grep -E "^WindowServer" 
  sleep 5
done | tee ~/xegfx-log/A-19c/cpu-software.txt
```

### 3.3 B 组：加速器在场（同一次开机，接着测）

```bash
sudo kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60 ; sudo sysctl -w debug.xegfx_stage=7 ; sleep 25
ioreg -c NMXAccel -l -w0 | grep -cE "NMXAccel"     # 应有实例
# 桌面静止 10 s 后，连采 3 次
for i in 1 2 3; do
  sudo powermetrics --samplers tasks -n 1 2>/dev/null | grep -E "^WindowServer"
  sleep 5
done | tee ~/xegfx-log/A-19c/cpu-accel.txt
```

### 3.4 判读（**用 ms/s，不是百分比**）

| 结果 | 含义 |
| --- | --- |
| B 组均值明显低于 A 组（例如 375 → 200 以下），且 B < 250 ms/s | ✅ 确实不再软件合成 |
| A ≈ B（都在 300–400） | ❌ 加速器没真正接管合成，只是"挂上了" |
| B 比 A 还高 | ❌ 更糟，别急着判定成功 |

**同时抓一条"更硬"的旁证**（不依赖 CPU 数字，避免又被计时噪声带偏）：
```bash
# WindowServer 的调用栈里还有没有软件合成函数
sudo sample "$(pgrep -x WindowServer)" 3 -file ~/xegfx-log/A-19c/ws-sample.txt >/dev/null 2>&1
grep -cE "CA::OGL::SW|scanline|scan_convert|draw_polygon" ~/xegfx-log/A-19c/ws-sample.txt
#   期望：0（历史上软件合成时这里是一堆 CA::OGL::SW::scanline）
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null | grep -ci nvmtl
```

### 3.5 Metal 级别

```bash
system_profiler SPDisplaysDataType | grep -iE "Metal|Resolution|UI Looks"
```
- 若出现 `Metal Support: Metal 3` → 计划要的那条成立
- 若只有 `Metal: Supported` → 记为"部分成立"，**不要写成 Metal 3**
- 顺手记录对比：未加载 XeGfx 时这一行是否存在（A-19a 实测基线**完全没有** Metal 行）

## 4. 停机与回滚

| 现象 | 处置 |
| --- | --- |
| 固化后开机屏幕黑/错位 | 立刻 `ssh` 进去 `xenative-ctl reg surf 0xFE600000` + `latch`；仍不行则把 `fbgeom.sh` 里那三步注释掉再重启 |
| `mapfast` 的 `bad` 不为 0 | **不要 latch**，保留原 SURF，报告 |
| 加载 accel 后花屏 | 说明搬迁没生效（SURF 被谁改回去了）→ 报告，别重试 |
| `IOServiceOpen failed 0xe00002bc` 或每次等 15 s | 客户端名额被泄漏 → **只能重启**；并检查是否有远端循环没 `pkill` |

## 验收锚点（主 agent 独立跑）

1. `cat /usr/local/bin/xegfx-fbgeom.sh` → 含 `mapfast 0xFD000 6656 0x800000` 与 `reg surf 0xFD000000`，且在 `latch` 之前。
2. `xenative-ctl status` → `SURF/SURFLIVE 0xfd000000`、`STRIDE 195`、`SIZE 0x081F0C2F`、`PIPESRC 0x0C2F081F`。
3. `dump 0x800000 2` → `0x00800003`；`dump 0xff4ff8 2` → `0x021ff003`。
4. `cpu-software.txt` 与 `cpu-accel.txt` 各 3 行，**必须带表头**（否则无法确认 ms/s）。
5. 两组数字我自己算均值；A/B 差异不成立就判 Gate 4 未达成。
6. 屏幕 3120×2080、`fbgeom.log` 有本次开机记录、零新 panic（应仍 9 个）。
