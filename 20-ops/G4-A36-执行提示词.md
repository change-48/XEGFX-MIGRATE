# Gate 4 · A-36 执行提示词：解开"模式信息要 open、open 要模式信息"的死循环

> 目标：让 CoreDisplay 在 `open()` 之前就能拿到模式信息 → 使我们这块 FB 成为**在线显示** →
> IOP 才有对象可建 display pipe。
>
> **本关是一次小的源码改动**（两处守卫条件），重编 `XeGfxDisplay`，装 KC，重启。

---

## 0. 为什么是这里（链条已经收敛到一条）

### 0.1 A-35 给出的决定性事实

撤掉占位 FB 后：

```
Creating FB 1 of 1 / Created FB 1 of 1 / GPU: FB: 1 of 1 opened
System set to use IOP but no display pipes are present
Unable to find display pipe for IOFB service / regID: 0x7c63 / 0x10000083f  ×7
system_profiler → 只剩 GPU 段，Displays 段整个消失（屏幕黑）
```

→ 我们这块 FB **注册了、被 open 了，但从来没有成为"在线显示"**。

### 0.2 紧挨着的一条日志就是原因

```
IOFBSetDisplayModeAndDepth: Setting mode 0x0 with depth 0x0 on displayID: 0x0 fbRegID: 0x10000083f
IOFBSetDisplayModeAndDepth: Failed to obtain mode info from IOFBGetDisplayModeInformation()
```

`IOFBGetDisplayModeInformation` → 内核侧 `getInformationForDisplayMode()`。

### 0.3 我们自己的守卫把它拒了（死循环）

```c
/* XeGfxDisplay.cpp:480  getInformationForDisplayMode() */
if (fS3) {
    if (!info) return kIOReturnBadArgument;
    if ((!fFbModeReady && !(fM3d && fM3dChecks == XEGFX_M3D_CHECKS_ALL)) ||
        fMeasuredModeCount == 0 ||
        mode != fMeasuredModes[0].modeId)
        return kIOReturnUnsupported;      /* ← CoreDisplay 在这里被拒 */
    *info = fMeasuredModes[0].info;
    return kIOReturnSuccess;
}
```

```c
/* 同样的守卫也出现在 getPixelInformation()（约 438 行） */
```

而 `fFbModeReady` 是 **`enableController()` 里才置位的**（A-32 已确证：
`XeGfxFbModeReady/FbReady are published from enableController, after open()`），
`enableController()` 又要等 WS `open()`。

于是：

```
CoreDisplay 要模式信息 → 我们要求 fFbModeReady → 它要 open 之后才有
        ↑                                              ↓
        └──────── 但 CoreDisplay 就是因为拿不到模式信息才不建显示、不 open ────────┘
```

**这就是"模式信息 ↔ open"的死循环。** 只要读接口在 open 之前可用，这个环就断了 ——
而模式表（`fMeasuredModes[]`）是在 `start()` 里从 VBT/实测时序建好的（日志 `mode: 0 id 1: 3120x2080 …`
出现在 open 之前很久），**读它根本不需要 open**。

### 0.4 顺带：`mode 0x0` 也要接受

CoreDisplay 先 `Setting mode 0x0 with depth 0x0`（"用默认/当前"的语义），随后按 mode 0 去取信息。
所以我们也要接受 `mode == 0`，把它当作 `fMeasuredModes[0]`。

## 1. 唯一改动（两处守卫，逐字）

文件：`~/src/NvGfx-xe-2.6.2/kexts/XeGfxDisplay/src/XeGfxDisplay.cpp`

**两处**的旧代码完全相同（`getPixelInformation` 约 438 行、`getInformationForDisplayMode` 约 480 行）：

```c
        if ((!fFbModeReady && !(fM3d && fM3dChecks == XEGFX_M3D_CHECKS_ALL)) || fMeasuredModeCount == 0 ||
            mode != fMeasuredModes[0].modeId)
            return kIOReturnUnsupported;
```

两处都改成：

```c
        /*
         * CoreDisplay asks for the mode record BEFORE it opens the framebuffer
         * (enableController, which publishes fFbModeReady, runs from open()).
         * Requiring fFbModeReady here deadlocked display bring-up: no mode info
         * -> no online display -> no open -> still no mode info.  The measured
         * table is built in start() from the VBT/measured timing, so answering
         * reads from it needs no open.  mode 0 is CoreDisplay's "current /
         * default" probe and must map to the measured mode as well.
         */
        if (fMeasuredModeCount == 0 ||
            (mode != fMeasuredModes[0].modeId && mode != 0))
            return kIOReturnUnsupported;
```

**只改这两处。** 不要动 `open()`、`enableController()`、`setDisplayMode()`（后者仍然只接受 `fMeasuredModes[0].modeId`，
保持"写必须真就绪"的语义）。

改完自检：

```bash

grep -n "fFbModeReady && !(fM3d" $F        # 期望：无输出（旧守卫已消失）
grep -n "mode != fMeasuredModes\[0\].modeId && mode != 0" $F   # 期望：2 行
```

## 4. 起 WS，看它是否变成"在线显示"、IOP 是否建 pipe

```bash
( sudo log stream --predicate 'process == "WindowServer" OR eventMessage CONTAINS "IOPresentment" OR eventMessage CONTAINS "M3d" OR eventMessage CONTAINS "NMXAccel" OR eventMessage CONTAINS "CoreDisplay"' > $L/stream-ws.log 2>&1 & )
sleep 2
sudo launchctl kickstart -k system/com.apple.WindowServer
sleep 25

echo "=== A) 显示是否在线 ==="
system_profiler SPDisplaysDataType 2>/dev/null | grep -E "Resolution|Online|Main Display" | head -6

echo "=== B) FB 计数与 regID ==="
grep -oE "Creating FB [0-9]+ of [0-9]+|Created FB [0-9]+ of [0-9]+" $L/stream-ws.log | tail -4
grep -oE "Unable to find display pipe for IOFB service / regID: 0x[0-9a-f]+ / 0x[0-9a-f]+" $L/stream-ws.log | sort -u | head -4

echo "=== C) 失败链 ==="
grep -c "Unable to create IOAccelDisplayPipe" $L/stream-ws.log
grep -c "Interface creation error" $L/stream-ws.log
grep -c "System set to use IOP but no display pipes are present" $L/stream-ws.log

echo "=== D) 进去了没有 ==="
grep -E "newDisplayPipe|initFramebufferResource" $L/stream-ws.log | tail -6

echo "=== E) 断言 / WS ==="
grep -c "transient surface .* not found" $L/stream-ws.log
ps -o etime=,pid= -p "$(pgrep -x WindowServer)"
```

判读：

| 现象 | 结论 |
| --- | --- |
| `Resolution: 3120 x 2080` + `Online: Yes` 出现在 `SPDisplaysDataType` | **我们的 FB 变成在线显示了** ← 本关的主要目标 |
| 且 `Unable to create IOAccelDisplayPipe` = 0、`newDisplayPipe` ≥1 | pipe 建起来了，进 §6 |
| 在线了但 pipe 仍失败 | 卡点回到 accel 侧（下一关） |
| 仍不在线 / `Displays` 段为空 | 模式信息仍没被采纳，停手报 §3.1 的计数 |

## 7. 铁律

1. **S3 只走 bootarm**；`kmutil load core` 必须等 `fbgeom.out` 末行「完成」。
2. 改 kext 必重签（adhoc）；KC 用 `kmutil create -z`，`-B/-S` 绝对路径；六 id 必核。
3. `armed` 后 120 s 内不重启；WS 第 2 实例立即停。
4. 一次一个变量：本关**只改两处守卫**，不撤占位 FB、不改 plist、不动 AGDC、不重编 core/accel。
5. 判"是否软件合成"必须动画面采样；loginwindow 下不可与 1256 比。
