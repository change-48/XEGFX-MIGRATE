# Gate 4 · A-23a 执行提示词（最便宜的一枪：把 accel 的兜底通道打开）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **成本：改 1 行 + 重编 1 个 kext + 1 次开机（预期 20–40 分钟）。**
> 成功就能立刻拿到 `vmmap nvmtl > 0`；失败就明确转 A-23b（应用上游 0011+0015 那套 KMS 适配器）。

---

## 0. 为什么先打这一枪

A-22 已经把 `0xe00002c7` 的来源查到了符号级：

```cpp
// kexts/NVRM/accel/nvrm-accel.cpp:925（~/src/NvGfx-5a19a73... 树）
if (1) { ALOG("describeBootFramebuffer: DISABLED by experiment -- no copy target"); return kIOReturnUnsupported; }
if (fBootDescOK) { r->kva = ...; r->phys = ...; r->pitch = fBootDesc.pitch; ... }   // ← 被这行挡住了
```

调用链是：
```
NVDisplayPipe::initFramebufferResource
  → askFramebufferForScanout
      → fb->callPlatformFunction(NVRM_VRAM_FN_SCANOUT)     返回 0xe00002c7（我们的头不实现它）
      → 兜底 describeBootFramebuffer()                      ← 被 `if (1)` 直接 return
  → "framebuffer would not describe its scanout (0xe00002c7)"
```

**关键点**：那条注释说"accel 加载后面板底部出现一条彩噪带"，但那是**当初 `getPixelInformation` 还没实现、
pitch 靠猜**的时候看到的。**现在 pitch = 12480 是真的**（A-22 已让它自己描述 scanout）。
所以这一枪值得打 —— 如果彩噪不再出现，`vmmap nvmtl` 很可能立刻 > 0。

---

## 1. 铁律

- **只改 `5a19` 树里的那一个 `if (1)`**，不改别的逻辑、不改探针分、不动 OpenCore。
- **不要动 `/Library/Extensions/XeGfxIntelFB.kext`**（A-22 的改动要保留 —— 它让 WindowServer 拿到了真实 scanout 描述）。
- 装 kext 一律走 **`kmutil create -z`**（A-21/A-22 已验证一次成功），**不要** `kmutil install`、**绝不要** `kickstart kernelmanagerd`。
- 一次开机一个变量：本次只换 accel 二进制。
- 重启前 `touch /var/db/xegfx/armed`；**armed 后 120 s 内不要再重启**。
- 若面板出现彩噪/花屏 → 立刻重启（不加载 accel），并在报告里明确写"彩噪复现"。

## 2. 步骤

### 2.1 改那一行 + 重编 accel


把 `if (1) {` 改成 `if (0) {`（**只改这一处**；保留 `ALOG` 与 `return`，让它在需要时仍能打日志）：

```bash
python3 - "$T/kexts/NVRM/accel/nvrm-accel.cpp" <<'PY'
import sys
p = sys.argv[1]
s = open(p).read()
old = 'if (1) { ALOG("describeBootFramebuffer: DISABLED by experiment -- no copy target"); return kIOReturnUnsupported; }'
new = 'if (0) { ALOG("describeBootFramebuffer: DISABLED by experiment -- no copy target"); return kIOReturnUnsupported; }'
assert s.count(old) == 1, "expected exactly one occurrence, got %d" % s.count(old)
open(p, 'w').write(s.replace(old, new))
print("flipped")
PY
```

重编（沿用该树自己的构建脚本与 OGKM 依赖）：

### 2.3 开机后验证（这次先看"有没有彩噪"，再看 vmmap）

**判读**

| 现象 | 含义 | 下一步 |

| `vmmap nvmtl > 0` 但屏幕**底部彩噪** | 注释里那条老毛病复现 | 立刻重启（不加载 accel），报告"彩噪复现 + pitch 已是 12480" → 转 A-23b |

| `vmmap = 0`，日志里仍见 `DISABLED by experiment` | 二进制没换成功（装了旧产物） | 核对 `shasum` 与时间戳 |
| WS 崩 | 停手重启 | 报告新 `.ips` 的栈 |

## 附：若这一枪失败（A-23b 的方向，不在本关执行）

上游 `~/src/aw/patches/` 有完整设计（已核实存在，未应用）：
`0011`（core 发布 `XeGfxDisplayNub`，224 KB）、`0015`（新增 `XeGfxDisplay` kext，5121 行、
`class XeGfxFramebuffer : public IOFramebuffer`、含 `xgGetScanoutInfo` 生产者）、

**已核实：当前 core 树里没有 `xgGetScanoutInfo` / `XeGfxDisplayNub`** → 0011 未应用 → core 需改+重编。
那是 3–6 小时的活，另发提示词。
