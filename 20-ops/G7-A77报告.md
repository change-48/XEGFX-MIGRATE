### 2.2 与 0024 的差别（这棵树没有 core 的 `xgPlaneLayout`）

0024 把平面布局交给 core（`nvAccelResidentCall("xgPlaneLayout")`）。这棵树的 XeGfx core（`gpu/xegfx/shim`）里
**没有任何平面编程代码**，`grep xgPlaneLayout` 全树 0 命中；平面寄存器（PLANE_CTL/STRIDE/SURF）由 accel 自己写
（它已经有 `gDispMmio`，A-74 起就在写 PLANE_STRIDE）。所以本关把布局切换**实现在 accel 里**，位值不猜，取自本机
i915 源码 `~/src/xe-src/drm-kmod/drivers/gpu/drm/i915`：

| 依据 | 文件 | 取值 |
| --- | --- | --- |
| tiling 字段 | `display/skl_universal_plane_regs.h:82` | `PLANE_CTL_TILED_MASK = GENMASK(12,10)` |
| 4-tile 编码 | 同上 `:88` | `PLANE_CTL_TILED_4 = FIELD_PREP(mask, 5)` → **5 << 10**（Y=4，注意不是 4） |
| tiled stride 单位 | `display/intel_fb.c:771` + `skl_universal_plane.c:679` | 4-tile tile 宽 **128 B**，`stride = scanout_stride / 128`；linear 是 /64 |

### 2.3 改了什么（`kexts/NVRM/accel/nvrm-accel.cpp` + `xegfx_accel_names.h`）

1. **selector 2**（`(sid, pending, flags)`，输出 1 个 scalar）：`pending 1` 记布局+标 pending，`0` 标 ready，
   `2` 只记布局；输出 bit0 = 该 surface 最近被翻转过（scanout surface），bit1 = Tile4 开着。仍只收 WindowServer。
2. **布局表** `gSurfLayout[32]`（自带的 IOLock），`nvSurfLayoutSet/Get`。
3. **scanout 环形表** `gXeScanoutIds[8]`：每成功 arm 一帧就记一次 surface id，selector 2 拿它回答 bit0。
4. **平面布局切换** `nvXePlaneLayoutBegin/Finish/Abort`：切布局时先把平面**灭一拍**（清 enable），等一个 vblank，
   写新 tiling 到 PLANE_CTL，再由 arm 写 STRIDE/SURF，最后 `Finish()` 重新使能——**任何一拍都不会用错的 stride
   去扫像素**。arm 失败则 `Abort()` 原样回写。10 s 内 >20 次切换自动关（计 `tile4_auto_off`）。
5. arm 里每帧算 `tile4 = gIopXeTile4 && pitch%128==0 && 布局表说 4-tiled`，stride 按 /128 或 /64 写；
   拷贝路径（`nvAccelXePlaneStride`）先把平面强制回 linear。
6. `xegfxtile4` boot-arg（**默认关**，比 0024 保守）+ `debug.xegfxaccel_iop_xe_tile4` 等 7 个 sysctl，
   **全部按 A-76 的教训显式注册**（`sysctl__debug_*` extern + `sysctl_register_oid`），并补了 14 行改名宏。

产物 `XeGfxAccel.a77new` = 330904 B、构建 sha `0c1bd31b…`、装机签名后 `0771c424…`（当前在装）。

## 9. 给下一关的路标（只写事实）

1. **先修插件挂死，再谈 Tile4**：WS 主线程自旋在 `NVMTLDriver`→`libvulkan_intel`。最快的二分是把三处新代码分别关掉
   （`nvmtl_ws_mark` 走回 selector 1 / `nvmtl_vk_tile4_ws_full` 探针去掉 / `NVMTLDevice.m` 的 want4 恒 0），
   每次只留一处，看 5 分钟内是否复现。改前用 `XEMTL_NO_TILE4=1` 环境变量也能一键回到线性。
2. **A/B 的条件**：① 先 `ls -l /private/tmp/nvmtl-ws-nowait`；② 每次切 tile4 都要 `kickstart WindowServer`
   （布局在建模时定型）；③ 切之前在 `say` 里明确说"请拖动"，并当场核对 `flips` 有没有在涨。
3. **原地重排（0026 的 `nvmtl_tile4_relayout`）是 Tile4 真正可用的前提**：没有它，只有 WS 重启那一刻创建的全尺寸面
   才是 4-tiled，日常会话里换不回来也回不去。
4. **Part 0 已把靶子钉死**：busy 26.2 ms / 68%，最大单项是 ANV 描述符（写 image view 5.4% + 分配 2.1% + 写 buffer 2.2%）
   与 objc retain/release/msgSend（6.2%）。**A-78 主攻 Device Cache/描述符，比继续压 GPU 合成段更值钱。**
5. **系统已升到 26.7.2**：A-74–A-76 的数字都来自 26.5.2，跨版本比较时要标注；本关门 1 的 fps 与 26.5.2 同量级。
