# Gate 7 · A-89 执行提示词：找出"2 拍的帧"和"3 拍的帧"差在哪（相位判别）

> A-88 的阶梯表钉死了三件事：① 余量 ≥4.5ms（加工作不掉档 ⇒ 帧不是工作量顶住的）；
> ② 链是**串行**的（worker 侧加 13.5ms 与主线程加同量、帧时间跳得一样）；
> ③ E2 打错门（`AccessComplete` 等的是 CoreDisplay 自己的信号量，不是我们的 pipe 完成）。
>
> **但 A-88 同时给出一个还没被追的线索：基线轮里 23–29% 的帧已经是 2 拍（9.5–17.5ms = 60fps）。**
> 同一驱动、同一负载，**有些帧能、有些不能** ⇒ 差的是**相位/节拍，不是能力**。
>
> 本关唯一目标：**逐帧对齐，找出"能"和"不能"的分界**。
> 判出来之后有两条路：可控的相位因子 → 直接修，60fps 到手；
> 不可控（CoreDisplay 内部节拍）→ 正式确认本栈 40fps 天花板，走 A-83 整树换血。
>
> 必读：`G7-A88报告.md`（§2 阶梯表、§3 E2 物证、§5 三条路标）、`G7-A87报告.md` §4。

## 2. P1 · 逐帧打点（本关主工作量，先取得数据）

### 2.1 需要一次拿到的字段（每帧一行）

| 字段 | 来源 | 为什么要 |
| --- | --- | --- |
| 帧序号 / 绝对时间戳（ns） | accel `performTransaction` 入口 `mach_absolute_time` | 帧间隔、相位 |
| 本次事务的 `enter→src→arm→latch→ret` | 现有 `iop_tl` | 与 2 拍/3 拍对照 |
| `AccessComplete` 等待时长 | **新增**（WS 侧拿不到，改在 accel 侧观测交易到下一帧的间隔作代理，或从 `sample` 的定点采样反推） | 是不是它决定相位 |
| 该帧落在几拍 | 由相邻帧时间戳差 / 8.333ms 分桶 | 标签 |
| **相位偏移** | `帧时间戳 mod 8.333ms` | **核心：2 拍的帧是不是起手更靠近 vblank** |
| sid | `iop_tl` 已有 | 是否与第三面有关 |

**做法**：扩 `iop_tl` 环（200 帧已够），把**绝对时间戳**也写进去（现在只有相对间隔）；
配套一个 `work/a89/classify.py`：读环 → 每帧打上 2 拍/3 拍标签 → 输出两组各自的
「相位偏移 / enter→ret / arm→latch」分布（p10/p50/p90）。

### 2.2 判读规则（先写死，避免事后拟合）

| 观察 | 结论 | 下一步 |
| --- | --- | --- |
| 2 拍帧的**相位偏移**集中在某个窄区间，3 拍帧在另一个 | **相位决定** ⇒ 可控 | 进 P2 |
| 两组相位分布重叠，但 2 拍帧的 `enter→ret` 明显更短 | **工作量决定**（与阶梯表矛盾则复查） | 回到砍工作，但要砍到临界值 |
| 两组在相位与工作量上都重叠 | **外部节拍决定**（CoreDisplay/display link） | 进 P3（判天花板） |
| 2 拍帧**成簇出现**（连续若干帧） | 节拍是周期性的（如每 N 帧对齐一次） | 记录周期，看能否借力 |

**门 P1**：两组对比表 + 一句"分界是什么"的判定（四选一）。

## 3. P2 · 若相位可控：修相位（唯一可能直接拿到 60 的路）

按 P1 的具体结论选，**每种都带运行时开关**（照 `/private/tmp/nvmtl-*` 形态）：

| 若分界是 | 可试的修法 |
| --- | --- |
| 起手时间相对 vblank 的偏移 | 在 accel 里把 arm 的时机**对齐到 vblank 后的固定偏移**（`iop_xe_latch_offset_us` 一类开关，扫 0/500/1000/2000 µs） |
| `arm→latch` 抖动（4.5ms±） | 减小抖动：latch 等待改为"等到指定 vblank 序号"，而不是"等下一个 vblank" |
| 与第三面（sid 23）相关 | 记录并统计：2 拍帧是否都落在第三面上（A-84 的 `iop_xe_early_frames/_third` 计数可直接复用） |
| 提交 worker 的启动延迟 | ahead kick 的时机（`nvmtl_pump_buffers` 何时被调用）——把 kick 提前到上一帧 latch 之后立刻做 |

**门 P2**：p50 ≤16.9ms（≥59fps）且画面正常；或明确记录"每种都试过、无效"。

## 4. P3 · 若不可控：把天花板钉死，转 A-83

如果 P1 判"外部节拍"、P2 全无效，本关就以"确认天花板"收尾：

1. 用同一负载把 **A-80/A-87/A-88 三个件的 p50/p90/p99 + 分布**整理成一张终表
   （证明 40fps 不是某一版的问题，是这条链的上限）；
2. 写一段「为什么这套栈上不去」的机理总结（串行链 + CoreDisplay 节拍 + 无第三面轮换），
   作为 A-83 整树换血的立项依据；
3. 明确 A-83 的对照目标：他们的 **82 翻/秒 @ 相同负载**（`logs/README.md`）。

**门 P3**：终表 + 机理总结完成。
