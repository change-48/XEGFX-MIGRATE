# Gate 4 · A-46 执行提示词：打开上游的 bootArm 第 6 步 —— 零拷贝延迟 flip

> 现状：我们的自启只做了 bootArm 序列的**第 4、5 步**（`accelfb=3`、`iop=1`），
> **第 6 步从来没做**，所以 `gIopXeFlip = 0`、`gIopXeDefer = 0`——
> 每帧退化成"等 GPU 完成 + 拷 26 MB"（实测拷贝 4.7 ms/帧，GPU 等待另计）。
>
> 加速器源码里写得很清楚（`nvrm-accel.cpp:3017`）：
>
> ```c
> // 6/6: the K9b deferred zero-copy flip (what the working manual config arms: flip + defer + idle wait)
> gIopXeFlip = 1; gIopXeDefer = 1; gIopXeWaitIdle = 1; gIopXeReportBusy = 1; gIopXeIdleMs = 40;
> ```
>
> **本关只加一个启动参数，让 bootArm 自己跑完 6 步。**

---

## 0. 依据（全部来自源码，不是推测）

### 0.1 三步之差

```c
// nvrm-accel.cpp:3005-3018  bootArmRun() 的尾部
gBootArmSteps |= 0x08;
ALOG("boot-armed: 4/6 debug.xegfxaccelfb=3 -> head 4 has a display pipe (piped 0x%x) after %u ms", …);

nvaccelSetIop(1);
gBootArmSteps |= 0x10;
ALOG("boot-armed: 5/6 debug.xegfxaccel_iop=1 -> display-pipe capabilities published, transaction hooks OPEN");

// 6/6: the K9b deferred zero-copy flip (what the working manual config arms: flip + defer + idle wait)
gIopXeFlip = 1; gIopXeDefer = 1; gIopXeWaitIdle = 1; gIopXeReportBusy = 1; gIopXeIdleMs = 40;
gBootArmSteps |= 0x20;
```

我们的脚本写了 4 和 5，**没写 6**。而 `gIopXeFlip` 的赋值全文件只有三处：
初始化 `0`（:1545）、flip 失败时清零（:1781/:1834/:1882）、**bootArm 第 6 步置 1（:3017）**。
**没有对应 sysctl** —— 所以只能通过 bootArm 打开。

### 0.2 第 6 步打开后，每帧走的是这条分支

```c
// nvrm-accel.cpp:2477  performTransaction() 开头
// K9: with the no-wait compositor this frame may still be under the GPU.  Hand it to the flip worker instead of
// waiting here: WindowServer's display thread stays free, and the worker writes PLANE_SURF only after the GPU
// reports idle.  The frame's geometry has to be the scanout's, as in the synchronous flip below.
if (gIopXeDefer && gIopXeFlip && s && head == 4 && nvXePlaneWriteAllowed(fb)) { … nvAccelXeFlipDeferQueue(this, s, W, H, P); … return kIOReturnSuccess; }
```

即：**不在这里等 GPU、也不拷**，把帧交给 worker，由 worker 在 GPU 空闲后直接写 `PLANE_SURF`。
两个瓶颈（拷 4.7 ms + GPU 等待）一起消失。

### 0.3 触发方式（`bootArmRequested()`，:2863）

```c
if (PE_parse_boot_argn("xegfxaccelboot", &v, sizeof v) && v) { … return true; }   // ← 用这个
if (PE_parse_boot_argn("-xegfxaccelboot", &flag, sizeof flag)) { … return true; }
```

现场读数（触发前）：

```
debug.xegfxaccel_boot        = 0
debug.xegfxaccel_boot_steps  = 0
debug.xegfxaccel_boot_delay_ms = 3000   boot_head_wait_ms = 30000   boot_pipe_wait_ms = 25000   boot_budget_ms = 90000
```

`boot_steps` 位含义（源码 :105-106）：`1` igpu、`2` fb=1、`4` head registered、`8` fb=3、`16` pipe、`32` iop、`64` flip。

## 2. 加启动参数（一处，EFI）

```bash
sudo diskutil mount disk0s1 >/dev/null 2>&1
P="/Volumes/NO NAME/EFI/OC/config.plist"
ls -l "$P"
sudo cp -p "$P" "$P.bak-before-xegfxaccelboot-$(date +%Y%m%d-%H%M%S)"

sudo python3 - <<'PY'
import plistlib
P="/Volumes/NO NAME/EFI/OC/config.plist"
with open(P,'rb') as f: d=plistlib.load(f)
key="7C436110-AB2A-4BBB-A880-FE41995C9F82"
hit=False
for e in d['NVRAM']['Add'][key]:
    if e.get('Name')=='boot-args':
        v=e.get('Value','')
        if 'xegfxaccelboot' not in v:
            e['Value']=(v.rstrip()+' xegfxaccelboot=1').strip()
        hit=True; print("NEW:", e['Value'])
if not hit: raise SystemExit("boot-args entry NOT FOUND -- stop")
with open(P,'wb') as f: plistlib.dump(d,f, fmt=plistlib.FMT_XML)
print("written")
PY

plutil -lint "$P"
sudo diskutil unmount disk0s1
```

**门 2：`plutil -lint` OK，新值 = 旧值 + ` xegfxaccelboot=1`，其余词一个不少（应含 `gfxrst=4`）。**

## 3. 改自启脚本：bootArm 接管时不再重复写第 4/5 步

> A-44 已证：**重复写 `accelfb=3` 会让 `iop_ok` 停摆 1–2 分钟**。bootArm 会自己写这两步，
> 所以脚本必须让位。只在脚本里加一个判据，其余不动。

```bash
sudo cp -p /usr/local/bin/xegfx-bringup.sh ~/xegfx-log/A-46/xegfx-bringup.sh.before
```

在脚本里找到第 6 步之前的位置（`# 6) scanout pipe`），在其**前面**插入：

```bash
# bootArm (xegfxaccelboot=1) runs steps 4..6 itself, including the K9b deferred zero-copy flip.
# Writing accelfb=3 a second time stalls the transaction counter for 1-2 minutes (A-44), so stand aside.
BA=$(/usr/sbin/sysctl -n debug.xegfxaccel_boot 2>/dev/null || echo 0)
if [ "${BA:-0}" != "0" ]; then
  WRITE "bootArm is driving (debug.xegfxaccel_boot=$BA) -- not touching accelfb/iop, waiting for its steps"
  for i in $(seq 1 40); do
    ST=$(/usr/sbin/sysctl -n debug.xegfxaccel_boot_steps 2>/dev/null || echo 0)
    [ $(( ST & 32 )) -ne 0 ] && break
    sleep 3
  done
  WRITE "boot_steps=$ST (bit32 iop, bit64 flip)"
fi
```

自检：`bash -n /usr/local/bin/xegfx-bringup.sh && echo SYNTAX-OK`

**门 3：`SYNTAX-OK`。**

```bash
sudo reboot
```

## 4. 重启后：确认 bootArm 真的跑到第 6 步

```bash
for i in $(seq 1 45); do
  ST=$(sudo sysctl -n debug.xegfxaccel_boot_steps 2>/dev/null || echo 0)
  [ $(( ST & 64 )) -ne 0 ] && break
  grep -q "6/6" /var/log/xegfx-bringup.log 2>/dev/null && break
  sleep 5
done

echo "=== bootArm 六步日志 ==="
sudo log show --last 15m --predicate 'eventMessage CONTAINS "boot-armed"' 2>/dev/null | sed -E "s/.*boot-armed/boot-armed/" | tail -10 | tee $L/bootarm.txt

echo "=== 状态 ==="
sudo sysctl debug.xegfxaccel_boot debug.xegfxaccel_boot_steps 2>/dev/null | tee -a $L/bootarm.txt
sudo sysctl debug.xegfxaccel_iop_ok debug.xegfxaccel_iop_flip debug.xegfxaccel_iop_flips 2>/dev/null | tee -a $L/bootarm.txt
sudo sysctl debug.xegfxaccel_iop_copy_skip 2>/dev/null | tee -a $L/bootarm.txt
```

**门 4（本关成败）：`boot_steps` 含 `64`（0x40），且日志出现 `6/6 … iop_xe_flip=1 … iop_xe_defer=1`。**

| 结果 | 含义 | 动作 |
| --- | --- | --- |
| `boot_steps & 64` 非 0 | 零拷贝 flip 已武装 | 进 §5 |
| 停在 32 或更低 | bootArm 某步失败（日志里有 `bootArmFinish(0, …)` 的原因） | 停手贴 `bootarm.txt`，**不要**手工补写 |
| `boot` 仍为 0 | 启动参数没生效 | 贴 `nvram boot-args` 与 `boot-args.before` 对比 |

## 5. 判决：帧路径换了吗

```bash
# 请用户拖动窗口 30 秒，然后：
echo "=== flip vs 拷贝 ==="
sudo sysctl debug.xegfxaccel_iop_ok debug.xegfxaccel_iop_flip debug.xegfxaccel_iop_copy_skip 2>/dev/null
echo "=== 拷贝计时（若不再增长 = 拷贝路径已被绕开）==="
sudo sysctl -a 2>/dev/null | grep -E "xegfxaccel_iop_(copy|memcpy)" | head -5
echo "=== CPU 与帧率（负载段）==="
for i in 1 2 3; do sudo powermetrics --samplers tasks -n 1 2>/dev/null | grep -E "^(WindowServer|kernel_task)" | tr "\n" " "; echo; done
a=$(sudo sysctl -n debug.xegfxaccel_iop_ok); sleep 6; b=$(sudo sysctl -n debug.xegfxaccel_iop_ok); echo "fps=$(( (b-a)/6 ))"
echo "=== 屏幕 ==="
system_profiler SPDisplaysDataType 2>/dev/null | grep -E "Resolution|Online|Main Display"
```

判读：

| 现象 | 结论 |
| --- | --- |
| `iop_flip` 增长、`copy_sum_us` 不再增长、`kernel_task` 明显下降、画面正常 | **零拷贝 flip 生效**，两瓶颈一起去掉 |
| `iop_flip` 仍 0、仍走拷贝 | flip 分支被别的条件挡住（`nvXePlaneWriteAllowed` / `head==4` / pitch==q.pitch），停手贴原文 |
| 画面花屏 / 撕裂 / 黑屏 | **立即回滚**（见 §6） |

## 8. 铁律

1. **只加一个启动参数**；不重编、不装机、不改 kext。
2. 脚本只加"让位"判据；**不改**它原有的 core/stage7/accel 三步。
3. bootArm 失败时**不要手工补写** `accelfb`/`iop` —— 那会掩盖真实原因。
4. 画面异常立即回滚启动参数。
5. 判据必须以用户目视为准（`screencapture` 在 SSH 下不可用）。
