# Gate 7 · A-82（激进版）：直奔 60 帧 —— 三管齐下，每管独立见效

> 目标改写：**不再以「判据全过」为节奏，以「60fps 落地」为唯一目标**。
> 验收定义：拖动窗口 25 秒，逐秒帧率中位 **≥60**，画面由使用者现场定档（清晰优先 / 流畅优先）。
> 三个杠杆并行推进，谁先到 60 谁先交付；每条都可独立回滚：
>
> - **快赢 A（10 分钟）**：系统减负（减少透明度/动态效果）——零风险、立刻可测；
> - **主攻 B（≤2 小时，最高杠杆）**：修 XeMTL 黑屏，拿到他们的翻译层——若 busy 真掉到 ~12ms，
>   清晰 60 帧当场成立；
> - **保证 C（≤2 小时）**：低分辨率 HiDPI 模式 + pipe scaler——像素砍三分之一到三分之二，
>   busy/GPU 同比降，哪怕翻译层不动也能把帧率推上去（画面会略软，使用者定档）。
>
> 必读：`G7-A81报告.md`（§3.1 三道墙、§3.3 四次尝试、§7 五条事实）、`G7-A80报告.md`（busy 拆分）、
> `G7-A55`/`G7-A58`/`G7-A60`（scaler 寄存器全套）、ArrowWhatever `docs/page-off-and-compression.md`。

## 0. 数字基线（A-77/A-80 实测，一切对比以此为准）

```
一帧 38.5ms = busy 26.2 + wait 6.3 + idle 5.9      ⇒ 拖动中位 23–29fps
60fps 要求：busy + wait ≤ 16.7ms（120Hz 下占 2 个 vblank）
GPU 合成（mark 段）13.7–15.4ms                      ⇒ 6.49MP 线性渲染太贵
XeMTL 在场证明：82 翻/秒 @ 9.2MP（翻译层是他们 70fps 的来源）
```

## 2. 快赢 A · 系统减负（10 分钟，先跑掉）

```bash
# 减透明 + 减动态（可逆，随时关）
defaults write com.apple.universalaccess reduceTransparency -bool true
defaults write com.apple.universalaccess reduceMotion -bool true
sudo launchctl kickstart -k system/com.apple.WindowServer   # 使用者重登
# 测：拖动 3 轮 25s；sample WindowServer 12 → busy 拆分
```

**判据**：记录 busy 变化（液态玻璃的多层混合是 busy 大头之一）。若 busy 掉 ≥4ms，
说明「视觉特效」是可换的筹码——把这条数字报给使用者定档。**这不算终点，只是筹码摸底。**

## 3. 主攻 B · 修 XeMTL 黑屏（≤2 小时，最高杠杆）

### 3.1 目标链（A-81 §7 已定位）

他们插件把内容写进 VRAM 镜像、提交时标「newest in VRAM at commit」；我们的 accel 从 surface 页取内容。
**页面里永远是空的** → 黑。修法不是猜，是对读 0024 的握手：

1. 合成后 accel 标 **current**（selector 5）→ 我们已实现，但**发没发出去、标没标上**要看计数；
2. 需要页面时才请求拷贝（**selector 6**，`id<<32|seq`，op0 锁 ≤300ms / 翻页前 ≤50ms）→
   我们 `nvXePoBeforeScan` 的**拒绝原因码**是本次关键；
3. 插件线程 selector 6 取活 → GPU 拷 VRAM→页面 → **selector 7** 报完成。

### 3.2 二十行代码的取证（先加计数，一次装机看全部）

- accel：selector 5/6/7/8 次数、op0 次数、`nvXePoBeforeScan` 发送次数 + **拒绝原因码**
  （no device cache / not current / locked / other key）——扩进 `iop_xe_po` 文本；
- 插件（`~/src/a81-tree-cm`）：`nvmtl_po_service` 每次 selector 6 的返回、超时、拷贝耗时。

### 3.3 定点修（按计数指的方向，最小改动）

| 计数形态 | 结论 | 修 |
| --- | --- | --- |
| selector 5 被调但没标上 | `nvXePoCurrent` 挂接条件不符（缺 selector 4 探测/锁 seeds） | 按 0024 §36.12 补 |
| selector 5 没被调 | 插件没认出 current 通道 | 对齐探测返回值（surface 0 语义） |
| 6 被请求但插件不接 | 参数/seq/超时语义相反 | 对齐 `id<<32\|seq` |
| 6 完全没被请求 | before-scan 判据从不满足 | 看拒绝原因码，放宽/修前置 |

**门 B**：**画面出内容**（用户目视桌面正常）＋ `page-offs` 增长。然后立刻：

```bash
sudo sample WindowServer 12 -file ~/xegfx-log/A-82/sample-xemtl.txt
# busy 拆分（复用 work/a77/parse_sample.py 的三分类）
~/xegfx-log/A-74/fps-probe2.sh 25    # 3 轮
```

**判决**：busy ≤12ms → 直接测 fps，**大概率当场 60**，本关结束；
busy 18–22 → 60 还差一口气，进 C 组合；busy >22 → 翻译层不比我们快，转 C 或下一天整树换血。

## 4. 保证 C · 低分辨率 HiDPI + pipe scaler（≤2 小时）

**原理**：真实 Mac 的「缩放」模式就是这条路——管线按**小尺寸 timing** 扫描，面板 FITTER 放大到
3120×2080。CA 合成、GPU 渲染、拷贝全部按小 backing 走，像素收益线性。
（A-55/58/60 的失败是「只改 DM 不改 timing」，CoreDisplay 按 3120 合成；**这次改真 timing**。）

### 4.1 档位（从轻到重，逐档给使用者看）

| 档 | looks like | backing | 像素降幅 | 预估 fps（busy 线性折算） |
| --- | --- | --- | --- | --- |
| 1 | 1400×933 | 2800×1866 | −19% | 28–34 |
| 2 | 1280×853 | 2560×1706 | −33% | 33–40 |
| 3 | 1100×733 | 2200×1466 | −50% | 38–48 |
| 4 | 960×640 | 1920×1280 | −62% | 45–58 |

### 4.2 实现（寄存器地址与位值全在 A-55，照抄）

- FB（`intelfb.cpp` 0.8）：`getDisplayModeCount/Modes/InformationForDisplayMode/PixelInformation/setDisplayMode`
  追加**真 timing 模式**（active 区 = 档位尺寸，refresh 120Hz，pixel clock 按同比例缩）；
  `setDisplayMode` 里切平面 SIZE/STRIDE 到小 backing；
- accel：`setDisplayMode` 后写 scaler 全套（pipe A）：
  ```
  TRANS_PIPESRC_A 0x6001C = (h-1)<<16 | (w-1)
  PS_WIN_POS_A    0x68170 = 0
  PS_WIN_SZ_A     0x68174 = (2080-1)<<16 | (3120-1)
  PS_VPHASE_A     0x68188 = 0x3000（按档位算也可先给 0x3000）
  PS_HPHASE_A     0x68194 = 0x3000
  PS_CTRL_A       0x68180 = EN(bit31) | TYPE(bit30) | BINDING(27:25=PIPE0)   ← 注意 BINDING 不是 bit30
  ```
  （A-55 §0.4/§4 原文；先写 PIPESRC/WIN，最后写 PS_CTRL 使能）；
- 逃生门：boot-arg `-xeintelfb1xoff`（A-55 已加过的框架）+ sysctl 运行时不启用。

### 4.3 门 C

- 每档：画面（放大应略柔和，允许；**花屏/斜屏/黑 = 立刻回退该档**）、`iop_ok` 增长、
  **拖动 3 轮中位**记入表；
- 达到 60 即停在该档，交给使用者定档（可以同时报「清晰但 40」与「略软但 60」两个选项）。

## 5. 组合与终局（本关交付形态）

| 情形 | 交付 |
| --- | --- |
| B 的 busy ≤12 | 清晰 60（首选）；C 不用做 |
| B 的 busy 18–22 | **B+C 组合**：档 2/3 + XeMTL → 目标 60，报画面档位 |
| B 失败（≤2h 内画面出不来） | 回滚插件，纯 C 档 3/4 → 45–58，如实报「60 需整树换血」 |
| A 的减负有效 | 作为筹码写进档位表（减少特效 → 换更高清晰度档） |

**验收表**（必交）：档位 × busy × fps × 使用者定档意见，四列。
