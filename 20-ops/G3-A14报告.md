## 4. `PS_CTRL` 变成 `0x00000200`：这不是异常，是更强的 1:1

提示词锚点要求 `PS_CTRL = 0x80000200`（"未被写"）。实测本次开机后是 **`0x00000200`** —— bit31 掉了。

- **不是我们写的**：脚本只写 `which` 2/1/3（STRIDE / SIZE / PIPESRC），从未碰 `PS_CTRL`；A-13 的 `regset` 实现也确认不触碰该寄存器。
- **是系统/kext 自己关的**：源头变成原生 3120 后，`PIPESRC = 3120×2080` 与目标同尺寸，**管道缩放器没有必要存在**，kext 直接旁路（bit31 = pipe scaler enable = 0）。
- **语义上这比 `0x8000` 更硬**：`0x8000` 是"缩放比算出来正好 1.0"，而 bit31=0 是"缩放单元根本不参与"，不存在"算错"的可能。
- 连带结果：`PS_HSCALE(0x68190) / PS_VSCALE(0x68184)` 读数变成 `0x00016dee / 0x0001ddbd`（缩放器停用后的残留），**这两个寄存器从此不能再当 1:1 判据**。A-13 报告 §6.4 的"不用拍照也能判断"到此作废，替代判据见下节。

## 9. 给下一关的三条结论（会改后续假设）

1. **配置层就够，不需要 `XeGfxIntelFB` 那条自建 IOFramebuffer 的重工程** —— 只要 OpenCore 给原生控制台模式，macOS 自己会把 `PE_Video` 尺寸、`IOFBMemorySize`、平面几何、时序全部按 3120×2080 摆好。
2. **缩放器会自己退出**：源=目标后 `PS_CTRL` bit31 被系统清掉，`PS_HSCALE/VSCALE` 失去判据意义。**以后判断 1:1 请用"帧缓冲像素采样 + `PLANE_STRIDE×64 == rowBytes`"这一对**，别再依赖 `0x8000`。
3. **自愈脚本的价值只剩"补一次 latch"**：macOS 已经把几何写对，脚本做的是锁存那一下。它必须保留（否则中间态没人收尾），但判据可以换成 `ioreg`/日志以缩短那 28 秒窗口。
