# Gate 7 · A-87 执行提示词：拆掉类锁那 4ms（40fps → 60fps 的最后一格）

> 局势（A-86 实测，稳态）：
> ```
> 主线程 busy 9.76 + wait 5.73 = 15.49ms   < 2 拍（16.67ms）
> 但帧仍落 3 拍 —— 因为 pass 边界越过了那一拍（idle 8.61ms，86% 是 CGXRunOneServicesPass 的 mach_msg）
> wait 里 4.06ms 是同一把类锁：dealloc 2.06 / enqueue 0.90 / submit 0.55 / surface_in 0.42
> ⇒ 砍掉 2–4ms 就能把 pass 边界拉回 2 拍 = 16.67ms = 60fps
> ```
> A-86 已排除三条：`nogsub` 掉到 32.48、`cap=1/2/4` 全噪声。
> **结论：不是"提交串行"，是"提交在锁里"。**
>
> 本关目标：把那 4ms 从锁里搬出去。两条路，按风险从低到高：
> **P1 先试"拆锁"**（给 ahead 通道一把独立的锁，改动最小）；
> **P2 若不够或不安全，做 §4.4 的完整重构**（锁内只 claim、锁外干活，附 UAF 防线）。
>
> 必读：`G7-A86报告.md`（**§4.4 是设计书，逐条照做**、§6 三个测量坑）、`G7-A85报告.md` §2.3。

| enqueue | `-[NVMTLCommandBuffer enqueue]` | ? | ? | ? |

**要回答的核心问题**：ahead pass 与 dealloc/enqueue **是否真的共享同一批可变状态**？
如果 ahead 只碰 `_nextSubmit` 与 `part->inflight`，而 dealloc 碰的是 `_parts` 数组本身，
那**给 ahead 一把独立的锁就是安全的**——这是 P1 的前提。

**门 P0**：表填满，明确一句「ahead 与其余四个入口的共享状态是 ___，拆锁是否安全：是/否」。

## 3. P1 · 拆锁（最小改动，先试这条）

### 3.1 做法

```objc
// 新增一把专供 ahead 通道的锁（不是类锁）
static NSObject *gAheadLock;   // +initialize 里建

// nvmtl_gsub_ahead_pass 及其内部调用链改用 gAheadLock
@synchronized (gAheadLock) { … 现有的 ahead 逻辑 … }
```

**只换锁对象，不动逻辑**——如果 P0 判"共享状态确实只有 `_nextSubmit`/`part->inflight`"，
这一改就能把 dealloc(2.06) + enqueue(0.90) 从等待里摘出来，**理论上 −2.9ms**。

**风险点**：`part->inflight` 若同时被 execution worker 的 `nvmtlAdvancePart` 读写，
拆锁后要保证它仍是原子的（用 `std::atomic<int>` 或保留对类锁的短暂获取）。

### 3.2 门 P1

| 判据 | 期望 |
| --- | --- |
| 计数自洽 | 提交数 == 完成数；无重复 claim；`peak in flight` 合理 |
| `dealloc` 的锁等待 | 从 2.06ms 降到 **<1ms**（`sample` 验证） |
| 拖动 p50 | **≤16.9ms（≥59fps）** |
| 画面 | 拖动/截屏/神奇效果正常；30 分钟无 panic、无 WS 看门狗 |

**拿到 60 就停**，P2 不必做。

## 4. P2 · 完整重构（P1 不够时才做，**照 A-86 §4.4 逐条**）

六步，一条都不能省（**特别是第 5、6 条，错了就是黑屏/长按电源**）：

1. 结构体加 `BOOL aheadBusy;`；
2. `nvmtl_gsub_ahead_pass` **锁内只做**：选 part、`_nextSubmit++`、`aheadBusy = YES`，
   把 (part, f) 收进**本地 `NSMutableArray`**（强引用，防 UAF），**出锁**；
3. 锁外做 `nvmtl_prepare_submission_copies` + `nvmtl_buffer_sync_in` + `nvmtl_vk_submit_begin`；
4. 再进锁：`part->inflight = f; aheadBusy = NO;` 并更新计数；
5. **`nvmtlAdvancePart` 必须把 `aheadBusy` 当成"不是我的"**（`claimed=NO; return NO`）——
   否则 ahead 与 execution 会**同时提交同一个 part**；
6. **防 UAF**：`nvmtlFinishExecution` 的 `[_parts removeAllObjects]` 会释放正在 submit 的 part
   → 出锁那段必须本地强引用 + `_partsRetiring` 在 claim 阶段就拦住后续 pass。

**门 P2**：同 P1 的判据 + 连续 30 分钟 + 一次显示关/开（A-84 的休眠不可触发）。

## 5. P3 · 描述符池复用（可与 P1/P2 叠加，风险最低）

`nvmtl_snapshot_set_md` 每次 bind 都新建 descriptor set（busy ≈1.1ms/帧）。
改成按**绑定签名**（image view 组合 + buffer 组合的哈希）复用池化 set，LRU 64。

**门 P3**：`anv_AllocateDescriptorSets` 从 0.32ms 降到 <0.05ms；p50 降 ≥0.5ms；画面正常。
