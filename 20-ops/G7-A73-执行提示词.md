# Gate 7 · A-73 执行提示词：把 WS 两次事务之间的 42.8ms 分解掉（纯测量，零行为改动）

> 目标：A-72 已证明**拖动稳态下 pipeline 创建 ≈ 0/s**（墙 B 不在编译），且一帧 52ms 里
> **42.8ms 发生在两次 accel 事务之间（WindowServer 侧）**。本关把这 42.8ms 拆开，
> 判定它落在哪条路上——这决定 G7 阶段 1 之后主攻哪个方向。
>
> **本关仍然只加测量，零行为改动。**
> 必读：`20-ops/G7-120fps-研究.md`、`20-ops/G7-A72报告.md`、
> `20-ops/AI-远程连接说明.md`、`20-ops/AI-远程调试作业说明.md`。

---

## 0. 背景（一分钟版）

- 机器/栈同 A-72：255H / Xe-LPG+ `8086:7D51`，3120×2080@120Hz，拖动中位 18fps，一帧 ~52ms。
- A-72 实测：accel 事务 9.2ms（vblank 4.77 + 拷贝 3.69，注意本树 vblank 在拷贝**前**）+
  WS 侧 42.8ms（`iop_gap_last_us` ≈ 51ms）。
- A-51 旧采样（6 秒 12591 样本）：libvulkan 26.5%、CA::OGL 15%、NVMTL 12–13%、
  Render::Updater 5.7%、naga 3.7%、**等待仅 1.2%**。
- A-72 新事实：pipeline 创建稳态 0/s ⇒ 上面那 26.5% 的 libvulkan 时间**不是管线编译**，
  需要重新归因。
- **待证伪的四个假设（本关就是要在它们之间做裁决）**：
  - H1（主嫌疑）：**插件每帧把 WS 的 IOSurface 按只读缓冲 host-import 失败 → CPU 拷贝**
    （上游 commit `e60f462`："plugin: copy, do not host-import, read-only buffers (userptr hold
    fails with protection failure, execbuffer efault)"——读路径被改成拷贝）。26MB×每帧数次就是十几 ms。
  - H2：NVMTL 翻译层每帧重建对象/录制命令的 CPU 成本（无缓存命中）。
  - H3：WS 在等 GPU（`vkQueueWaitIdle`/`vkWaitForFences`/Metal `waitUntilCompleted`）——
    与 A-51 的 1.2% 矛盾，需复核。
  - H4：GPU 本身合成 6.49MP 太慢（execbuffer 时间长）——修法方向是 Tile4/CCS/带宽。
- 前人成果对齐：ArrowWhatever 的 `0006-plugin-host-import`（host-import 修好）和
  `0026-plugin-marks-tile4-pageoff`（IOSurface Device Cache + page-off，正是为了消
  CPU↔GPU 之间的每帧搬运）都指向 H1/H4。**但本关只测量，不移植。**

## 2. Part 1 · 零代码测量（先做，一轮就有裁决力）

### 2.1 sample 复测（请用户拖动 25 秒）

```bash
sudo sample WindowServer 6 -file ~/xegfx-log/A-73/sample-drag.txt   # 拖动中进行
sudo powermetrics --samplers tasks -n 1 > ~/xegfx-log/A-73/powermetrics-drag.txt
```

**分析要求（这次要按函数聚合，不是只按库）**：

| 聚类 | 归到哪 | 对应假设 |
| --- | --- | --- |
| `memcpy`/`bcopy`/`copy_io`/cache-bypass 拷贝类符号（含经 libvulkan 的） | 拷贝毫秒数 | H1 |
| libvulkan 里非编译的路径：`vkQueueSubmit`/command buffer 录制/`anv_Blit`/surface state 重建 | 提交毫秒数 | H2 |
| `vkQueueWaitIdle`/`vkWaitForFences`/`waitUntilCompleted`/semaphore/psynch | 等待毫秒数 | H3（复核 1.2%） |
| `CA::Render::Updater`/`CA::OGL` 自身绘制调用 | CA 毫秒数 | H2/H4 |
| 着色器编译类符号（`anv_pipeline`/`naga`/SPIR-V） | 编译毫秒数 | 应 ≈ 0（与 churn≈0 互证） |

给出各聚类的毫秒/秒（不是百分比，方便和 42.8ms/帧直接对账：×帧率/1000）。

### 2.2 GPU 侧读数（如果这棵树有这些 core sysctl）


## 3. Part 2 · 插件侧每帧成本计数（改插件，只加观测）

文件：`~/src/NvGfx-xe-2.6.2/plugin/nvmtl_vk.c`（以及 import 相关的 `XeMTLDevice.m`/`NVMTLObjects.*`，哪里有 import 就在哪加）。

### 3.1 先定位 H1 的拷贝点（读码，不跑）

上游 `e60f462` 的行为：只读缓冲 host-import **失败**（userptr hold 保护错误）→ **改走 CPU 拷贝**。
在插件里找到这条路（提示：grep 拷贝 fallback、userptr/host import 相关分支；`0006-plugin-host-import.patch`
里改的函数名就是线索，可 `curl` 下来对照，**只读不改**）。把找到的拷贝点函数名、调用条件写进报告。

### 3.2 加什么（每秒一行 `/private/tmp/nvmtl-ws-prof.log`）

| 计数 | 含义 | 对应假设 |
| --- | --- | --- |
| `import_copy` 次数 + `copy_bytes` | H1 拷贝点每秒被走多少次、拷多少字节 | **H1（关键）** |
| `iosurface_import` 次数 | 每帧从 IOSurface 建纹理/缓冲的次数（重建 vs 复用） | H1/H2 |
| `submit` 次数 | 每秒 `vkQueueSubmit` | H2 |
| `wait_us` | 每秒 `vkQueueWaitIdle`/`vkWaitForFences` 总耗时 | **H3（关键）** |
| `commit_p50/p90` | commit→submitted→completed 的环形缓冲（照 A-72 `iop_tl` 的做法，256 槽无锁） | 总览 |

**纪律**：
- 全部 `_Atomic` 计数，热路径只做原子加；环形缓冲照抄 A-72 的栈上填充+末尾发布模式。
- **顺手修 A-72 报告 §6.3 的 `ps_flush` 顺序 bug**（`sec_creates`/`sec_new` 打成 0——先打印后清零），
  一次 kickstart 一起生效。
- 每秒写日志的线程/频率与 A-72 相同（有活动的线程上、每秒至多一次 open/append/close）。

### 3.3 验证与测量

构建 → 装 → kickstart WS（先跟用户说）→ 等 `iop_ok` 恢复 → 请用户拖动 25 秒 × 3 轮：

```bash
: > /private/tmp/nvmtl-ws-prof.log
~/xegfx-log/A-72/fps-probe.sh 25 | tee ~/xegfx-log/A-73/fps-r1.txt
tail -30 /private/tmp/nvmtl-ws-prof.log | tee ~/xegfx-log/A-73/prof-r1.txt   # 逐轮
sudo sysctl -n debug.xegfxaccel_iop_tl > ~/xegfx-log/A-73/tl-r1.txt
```

**门 2**：三轮 `import_copy_bytes`、`wait_us`、`commit_p90` 数字一致（±30%）；
fps 与 A-72 基线（16–19）不回归；`iop_ok` 增长、无新 panic。

## 4. Part 3 · 裁决表（本关最重要的一张表）

把实测换算成「毫秒/帧」（÷ 帧率），和 42.8ms 对账：

| 裁决条件 | 墙 B 的真身 | G7 阶段 2 主攻 |
| --- | --- | --- |
| `import_copy` 每帧 ≥ 数 MB 或 ≥ 5ms | **H1 成立**：插件每帧 CPU 搬运 surface | 移植 `0006` host-import + `0026` Device Cache/page-off（前人已验证有效） |
| `wait_us` 每帧 > 10ms | **H3 成立**：WS 在等 GPU | GPU 慢 → Tile4/CCS；或等待策略 → marks/no-wait |
| 两者都小，CA/提交占 30ms+ | **H2 成立**：翻译/录制 CPU | 减图层效果、或插件对象缓存深挖（难路） |
| sample 里 GPU 相关但 CPU 全小 | **H4 成立**：GPU 合成慢 | Tile4/page-off/CCS（`0024`/`0026`） |

允许「混合」结论（比如 H1 占 15ms + H2 占 20ms），但每项都要有毫秒数支撑。
**只报数字与对应关系，不写修法。**
