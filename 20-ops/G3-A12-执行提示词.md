# Gate 3 · A-12 执行提示词（把图案真正送上屏，再动尺寸）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **分两步，一步一个变量：先把我们的图案在 1080p 下送上屏，再单独切到 3120×2080。**

---

## 0. 一句话

A-11 已经证明**PTE 写入是通的**（写 2025 条指回桌面物理页 → 完整还原桌面），
也定位到唯一剩下的障碍：**像素填充那条路径写不进 DRAM**（`fillat` 写完，画面一个像素都没变）。
本关换一条写入路径：**用内核自己分配的内存、通过它的 VA 写图案**，再用已经验证过的 `fGtt` 路径一次性写全 PTE。

## 2. 已知事实与约束（这些不要再验证）

1. **PTE 写入到达引擎内存**（A-11 E2-1b 判决）：`map 0x1000 2025 0x800000` + `reg surf 0x01000000` → 桌面完整还原。
2. **只写 1 条 PTE 会黑**：一个 1080p 表面要 **2025 页**连续，3120×2080 要 **6338 页**。写不全就是黑/花屏。
3. **`fill` / `fillat` 写不进 DRAM**（A-11 E3-fill）：这是本关要绕开的缺陷，**不要再去修它**，换路径。
4. **`TRANS_FRMCOUNT` 恒定**，不能当帧活性判据。
5. **`IOServiceOpen` 约 980 次后失效**（`0xe00002bc`）→ 批量操作必须在 kext 内部一次做完，不要 shell 循环刷。
6. **`reg stride` 偶发读回不一致** → 写完读回不符就**再写一次再判**，别据此下结论。
7. `wbinvd` 在本内核可用、不 panic。

---

## 3. 铁律

- **第一步只做 1080p**：SURF 换掉、PTE 换成我们的缓冲，但 `SIZE / PIPESRC / STRIDE / PS_CTRL / PLANE_CTL` **一个都不动**。
  图案会因此被缩放器放大到全屏 —— **这是预期的**，看到"放大的图案"就是成功。
- **第二步才动几何**，且必须先第一步成功。
- 缓冲区**必须长期持有**（静态成员，不要每次调用新建再 release —— 那正是 A-11 定位到的缺陷形态）。
- 图案必须**通过与 PTE 表同一类"长期持有映射"之外的路径**写：用 `IOBufferMemoryDescriptor` 拿到的 **VA** 直接写（普通内核内存）。
- 每次实验失败后立刻 `restore`；收尾必须回到第 1 节的原值。
- 不许改 boot-args / EFI / GPUBundles；不许装加速器；不许 `softwareupdate`。
- 改 kext 后重建 AuxKC 只用 `kmutil install --volume-root / --allow-missing-kdk -v`，
  **重启前逐条核对 id**，`IGPUConsoleRange` 必须在（这条已经救过两次场）。

## 4. 代码改动（XeNative 0.9）

### 4.1 缓冲区：内核分配 + VA 写

```cpp
// 静态持有，永不释放
static IOBufferMemoryDescriptor *sBuf = nullptr;

// 一次分配，8192 对齐
sBuf = IOBufferMemoryDescriptor::inTaskWithOptions(
           kernel_task, kIODirectionOutIn, NAT_SIZE, 8192);
void *va = sBuf->getBytesNoCopy();     // 通过这个 VA 写图案（普通内存，一定会落 DRAM）
```

写图案用**普通 32-bit store**（`((volatile UInt32*)va)[y*W + x] = v;`），
**不要**再走 `withPhysicalAddress` + `writeBytes`。

### 4.2 PTE：一次写全，物理页逐页取

```cpp
// 物理页可能不连续，逐页取，逐条写
for (UInt64 i = 0; i < pages; i++) {
    addr64_t pa = sBuf->getPhysicalSegment(i * 4096, nullptr, 0);
    fGtt[base + i] = (pa & PHYS_MASK) | fPteFlags;   // fPteFlags 用活页那条的（0x3）
}
xnWbinvd();
// 逐条回读校验：首、中、尾三条必须等于期望值，否则报错不写显示寄存器
```

**必须逐条回读校验**（首/中/尾 + 随机 8 条），不一致就停手。

### 4.3 新增一条命令，把整个动作合成一次

```
xenative-ctl buf1080          # 分配 + 填 1920x1080 图案(stride 120) + 写 2025 条 PTE + 回读校验
xenative-ctl buf3120          # 同一块缓冲重填 3120x2080 图案(stride 195) + 写 6338 条 PTE + 回读校验
xenative-ctl where            # 打印缓冲 phys 首页、页数、图案指纹
```
索引固定用 **`0x20000`**（GGTT 偏移 `0x20000000`）：远离活段（`0xFE600`）、也远离低地址区（GPU 上下文可能用），且在 4 GiB 内。

## 5. 第一步：1080p 下让图案上屏（唯一变量 = SURF）

```bash
xenative-ctl status > ~/xegfx-log/A-12/s1-before.txt
xenative-ctl buf1080                      # 分配/填充/映射/校验，一条命令
xenative-ctl where                        # 记下 phys 首页 + 页数
xenative-ctl reg surf 0x20000000          # index 0x20000
# 看屏幕 + 拍照
xenative-ctl restore                      # 无论成败都先恢复
```

**判读**

| 现象 | 结论 |
| --- | --- |
| 屏幕出现**被放大的我们的图案**（红蓝 + 白块被拉长） | ✅ 成功。缓冲写入、PTE、平面、引擎全链路通了 → 进第二步 |
| **全黑** | 缓冲仍然没写进 DRAM，或者 PTE 没写全。先查 `where` 的页数与回读校验结果，再看 §5.1 |
| 出现**花屏/斜纹** | PTE 写全了但物理页顺序错 → 检查 `getPhysicalSegment` 的偏移是否按 4096 递增 |
| 画面没变化 | SURF 没写进去 → 读回 `status` 确认 |

### 5.1 若全黑（只做一件：换写入通道，不要同时改别的）

按顺序试，每条之间 `restore`：

1. **`IOMallocContiguous(NAT_SIZE, 4096, ...)`** 拿连续物理内存，用返回的 VA 写图案（这条也天然让 PTE 连续）。
2. 若 1 也黑：把图案经 **BAR2 aperture** 直接写到显存窗口（如果 `scan` 能证明 BAR2 前 256 MB 是 GGTT 0..256 MB 的镜像，
   就直接 `memcpy` 到 `bar2 + 0x20000000`，即映射到我们自己那块 —— 这条是 MMIO 写，一定被引擎看见）。

## 6. 第二步：切到 3120×2080（唯一变量 = 几何）

**只有第一步看到"放大的图案"才做。**

```bash
xenative-ctl buf3120                      # 同一块缓冲重填 3120 宽图案 + 写 6338 条 PTE
xenative-ctl reg stride 195
xenative-ctl reg size 0x081F0C2F
xenative-ctl reg pipesrc 0x0C2F081F
xenative-ctl reg ps 0x00000200            # 清 bit31，关缩放器（写前是 0x80000200）
xenative-ctl reg surf 0x20000000
# 读回全部 5 个寄存器；stride 读回不符就重写一次
```

**判读**

| 现象 | 结论 |
| --- | --- |
| 图案 1:1 铺满，四角白块贴边，1px 棋盘能看出点阵 | ✅ **Gate 3 达成** |
| 图案正确但仍被放大（棋盘糊成灰、四角内缩） | PS_CTRL 没生效 → 读回确认 bit31，重写一次 |
| 黑/花屏 | 几何组合有问题 → `restore`，报告读回的 5 个值与拍照，**不要在同一次里再试别的组合** |

## 7. 交付格式

| # | 步骤 | 命令 | 观察 | 结论 |
|---|---|---|---|---|
| S1 | 1080p 图案上屏 | `buf1080` → `reg surf 0x20000000` | 放大图案 / 黑 / 花屏 | |
| S2 | 3120 几何 | `buf3120` + 4 个 `reg` | 1:1 / 仍放大 / 黑 | |

必须给出：`where` 的缓冲物理地址与页数、PTE 回读校验结果（首/中/尾 + 随机 8 条）、
5 个寄存器的写前/写后读回值、**屏幕照片**（手机拍，截图拿不到原生像素）。

一行结论：`A-12 成功：原生 3120×2080 出图` / `A-12 停在 S1：图案上不了屏` / `A-12 停在 S2：<现象>`。

## 验收锚点（主 agent 独立跑）

1. `xenative-ctl status` 收尾回到原值（若失败）；若成功，`SURF` 应为 `0x20000000` 且 `PS_CTRL` bit31=0。
2. `xenative-ctl scan` 的 `live_run_pages` 仍 6656、`live_phys` 仍 `0x800000`（活段未被破坏）。
3. `PTE[0x1000]` 仍为 0（不要在那里留垃圾）。
4. 屏幕 1920×1080 或 3120×2080，WindowServer 在，零新 panic，`IGPUConsoleRange` 在。
5. `~/xegfx-log/A-12/` 里有 S1、S2 的寄存器前后值 + 照片 + PTE 校验输出。
