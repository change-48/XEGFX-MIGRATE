# Gate 5 · A-52 执行提示词：先证明 pipe scaler 能动（零代码，三步可逆）

> 目标：让 CA 只合成 **1560×1040**、由显示管道放大到 3120×2080，把每帧像素砍到 1/4。
> 但在改 FB 之前，必须先证明**这块屏的 pipe scaler 真的能工作**。
>
> **本关零代码、不重编、不重启**，只用已装的 `xenative-ctl` 做三次可见的、可逆的寄存器实验。

---

## 0. 已知（只读侦察，已确认）

```
PLANE_SURF_A        0x7019C     现值 0xfd000000
PLANE_SIZE_A        0x70190     现值 0x081F0C2F   (w-1=3119, h-1=2079)
PLANE_STRIDE_A      0x70188     现值 0xC3         (195 × 64 = 12480)
TRANS_PIPESRC_A     0x6001C     现值 0x0C2F081F   (w-1=3119, h-1=2079)  ← 本关主角
PS_CTRL_A           0x68180     现值 0x00000200
```

`xenative-ctl regset` 可写 `0=SURF 1=SIZE 2=STRIDE 3=PIPESRC 4=PS_CTRL 5=PLANE_CTL`，
`restore` 会把 SURF/SIZE/STRIDE/PIPESRC/PS_CTRL 五个原样放回（A-10 已验证）。

**任务**：把 PIPESRC 从"整屏"改成"半屏"，再看管道会不会把它放大回满屏。

| 步骤 | 写什么 | 期望看到 | 说明 |
| --- | --- | --- | --- |
| 1 | PIPESRC = `0x040F0617`（1559×1039） | 画面**缩在左上角 1/4**（或右上角出现旧内容） | 证明 PIPESRC 被采纳 |
| 2 | PS_CTRL = `0xC0000200`（bit31 使能 + bit30 绑定管道） | 左上角那 1/4 **被放大填满全屏**（2 倍） | 证明 scaler 工作 |
| 3 | restore | 回到正常桌面 | — |

## 1. 前置：记录基线

```bash
L=~/xegfx-log/A-52; mkdir -p $L
sudo /usr/local/bin/xenative-ctl status | tee $L/status-before.txt
```

**门 1：`PIPESRC 0x0c2f081f`、`PS_CTRL 0x200`、`SURF 0xfd000000`。**（若不同，按实测记下，后面用实测值）

---

## 2. 第 1 步：只改 PIPESRC（不改 PS_CTRL）

```bash
sudo /usr/local/bin/xenative-ctl regset 1 3 0x040F0617 | tee $L/step1.txt
sleep 3
sudo /usr/local/bin/xenative-ctl status | grep -E "PIPESRC|PS_CTRL" | tee -a $L/step1.txt
```

**请用户看屏幕**（3 秒内）：

- **画面缩在左上角 1/4，其余变旧/黑** → PIPESRC 被采纳 ✅ 进第 3 步
- 画面完全没变 → PIPESRC 没被采纳（管道可能被别的逻辑覆盖）→ **跳到第 5 步收尾**
- 花屏/黑屏 → **立即 `restore`**，跳到第 5 步

> 说明：这一步**没有**动 PS_CTRL，所以理论上不该有任何放大，只应看到"少读了一块"。

---

## 3. 第 2 步：打开 scaler（只加两个 bit）

```bash
sudo /usr/local/bin/xenative-ctl regset 1 4 0xC0000200 | tee $L/step2.txt
sleep 3
sudo /usr/local/bin/xenative-ctl status | grep -E "PIPESRC|PS_CTRL" | tee -a $L/step2.txt
```

**请用户看屏幕**：

- 左上角那 1/4 **放大填满全屏**（看得出是 2 倍放大的桌面）→ **scaler 能动** ✅✅ 这是本关要的答案
- 仍是 1/4、其余黑 → scaler 没使能（bit 位不对或该管道无 scaler）
- 花屏/黑屏 → **立即 `restore`**

> 两个 bit 的来历：Intel 显示管道的 `PS_CTRL` 里 bit31 = `PS_SCALER_EN`、bit30 = `PS_BINDING_PIPE`（绑定到管道）。
> 现值 `0x200` 保留，其余不动。**若这一步导致花屏，说明该平台寄存器布局不同，停手即可。**

---

## 4. 第 3 步（仅在"放大成功"后才做）：量一次真实收益的上界

不必现在做。记录一条即可：

```
若 2 倍放大成功，则"CA 只画 1560×1040"在像素上是 1/4 的成本；
按 A-51 实测 22 ms/帧、其中约 28% 是 CA 渲染 + 22% 是插件/Vulkan，
理论新帧时间 ≈ 22 × 0.25 ≈ 5.5 ms ⇒ 上限 ~180 fps（实际受其它固定开销限制，预计 60–100）。
```

---

## 5. 收尾（**无论结果如何必须执行**）

```bash
sudo /usr/local/bin/xenative-ctl restore | tee $L/restore.txt
sleep 2
# restore 会把 SURF 放回 0xfe600000（A-10 之前的旧缓冲），必须补写回当前的 0xfd000000
sudo /usr/local/bin/xenative-ctl regset 3 1 0x081F0C2F 2 195 0 0xfd000000
sleep 2
sudo /usr/local/bin/xenative-ctl status | tee $L/status-after.txt | grep -E "PIPESRC|PS_CTRL|PLANE_STRIDE|SURF "
```

**门 3：`PIPESRC 0x0c2f081f`、`PS_CTRL 0x200`、`SURF 0xfd000000`，且用户确认桌面恢复正常。**

若 `restore` 后仍不正常 → `sudo shutdown -r now`（重启后 FB 重新编程模式，不会留后遗症）。

## 7. 铁律

1. 每一步只写**一个**寄存器组；写完立刻回读 `status`。
2. 画面异常**先 `restore`**，不要连续试第二个值。
3. 不要动 `PLANE_*`（SURF/SIZE/STRIDE）——它们保持现状。
4. 判据以用户目视为准。
5. 这是**可见的花屏风险**，但**不会冻死系统**：桌面每帧仍在被拷贝，`restore`/重启即可恢复。
