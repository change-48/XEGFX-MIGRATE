# Gate 4 · A-21 执行提示词（换回 accel 认的那个头：XeGfxIntelFramebuffer）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **一次开机、零编译、零源码改动**（只改两个 plist 数字 + 装一个现成 kext）。
> 这是 A-20 那个死结的正解方向，但要按**正确的探针顺序**来。

---

## 0. A-20 留下的死结

| framebuffer | 能接管面板？ | accel 认它？ |
| --- | --- | --- |
| `NMIntelFB`（继承 `IOFramebuffer`，自己 adopt） | ✅ 能（A-20 已证） | ❌ `NMIntelFB is not an XeGfxIntelFramebuffer -- not ours` |
| `XeGfxIntelFramebuffer`（继承 `IONDRVFramebuffer`，只换类名） | 未试（10-30 时因缺 console range 而 start 失败） | ✅ 这才是它设计上要认的头 |

`XeGfxIntelFB/intelfb.cpp` 文件头注释写明了它的动机：
> *CoreDisplay picks the GPU vendor from the IOFramebuffer class name, and IONDRVFramebuffer reads as no vendor, which turns IOPresentment off for WindowServer (I-108)*

→ 也就是说：**它就是为了让 WindowServer 的 IOPresentment 打开才存在的**。这正是 Gate 4 缺的那一环。

---

## 1. ⚠️ 纠正 A-20 报告 C1 的一条建议（照原样做会直接失败）

报告建议：*"把 `XeGfxIntelFB` 的 `IOProbeScore` 提到 66000 压过 IGPUConsoleRange"*。**这是反的。**

```
IGPUConsoleRange       65000   ← 先探针：把控制台范围注入 device memory，然后主动让位
XeGfxIntelFB           20001   ← 后探针：此时基类 IONDRV 才拿得到 VRAM 描述符，能 start
Apple IONDRVFramebuffer 更低   ← 兜底
NMIntelFB              66000   ← 现在是我们提上去的，导致它抢占
```

如果把 XeGfxIntelFB 提到 66000，它会**抢在 IGPUConsoleRange 注入之前**探针 ——
没有那块 console range，基类就是 10-30 那个 `(IONDRVSupport) IGPU: Not usable`，start 必然失败。

**正确做法：XeGfxIntelFB 的分保持 20001 不动，把 `NMIntelFB` 的分降下来。**

## 3. 铁律

- **只改两个 plist 数字 + 装一个 kext**。不改源码、不重编、不动 OpenCore。
- **不许把 `IGPUConsoleRange` 的分改掉**（65000 是序列的起点，改了就全乱）。
- **一次开机只改一个变量**：本次 = 换 framebuffer 归属。**不要在同一次里加载 accel**（accel 放到下一步，避免又混在一起）。
- **armed 之后 120 秒内不许再重启** —— A-20 就是因此在观察窗口内重启，被护栏判成"没活下来"触发回滚，把 kext 全搬走了。
- 重启前 `touch /var/db/xegfx/armed`；重启后**逐条核对 AuxKC** 含 `IGPUConsoleRange` + `XeGfxIntelFB`。
- `kmutil install` 打印 `rebuild done` **不可信**；判据是 `kmutil inspect` 里逐条 id 都在。
  若 `not approved`，用 `20-ops/A-20/policy_fix.sh` 修策略后再装。

## 4. 步骤

### 4.1 降 NMIntelFB 的分（不删，便于一键换回）

```bash
P=/Library/Extensions/NMIntelFB.kext/Contents/Info.plist
sudo plutil -p "$P" | grep -E "IOKitPersonalities|IOClass|IOProbeScore"   # 先看真实 personality 键名
# 用真实键名（A-20 时是 NMIntelFB）
sudo /usr/libexec/PlistBuddy -c "Set :IOKitPersonalities:NMIntelFB:IOProbeScore 5000" "$P"
sudo plutil -lint "$P" && sudo plutil -p "$P" | grep IOProbeScore    # 期望 5000
```

### 4.2 装 XeGfxIntelFB（分不动，20001）

```bash
SRC=~/_xegfx-old-20261030/LE/XeGfxIntelFB.kext
sudo rm -rf /Library/Extensions/XeGfxIntelFB.kext
sudo cp -R "$SRC" /Library/Extensions/XeGfxIntelFB.kext
sudo find /Library/Extensions/XeGfxIntelFB.kext -name '._*' -delete
sudo xattr -cr /Library/Extensions/XeGfxIntelFB.kext
sudo chown -R root:wheel /Library/Extensions/XeGfxIntelFB.kext && sudo chmod -R 755 /Library/Extensions/XeGfxIntelFB.kext
sudo codesign --force --sign - /Library/Extensions/XeGfxIntelFB.kext
sudo codesign -v /Library/Extensions/XeGfxIntelFB.kext && echo SIGN-OK

P=/Library/Extensions/XeGfxIntelFB.kext/Contents/Info.plist
sudo plutil -p "$P" | grep -E "IOClass|IOProbeScore|IOPCIMatch"
# 期望 IOClass = XeGfxIntelFramebuffer、IOProbeScore = 20001、IOPCIMatch 含 0x7d518086
```

### 4.3 重建 + 逐条核对 + 重启

```bash
sudo /usr/bin/kmutil install --volume-root / --allow-missing-kdk -v
sudo /usr/bin/kmutil inspect 2>/dev/null | grep -A16 "auxiliary kext"
```
**必须同时看到**：`com.nullmoth.NMIntelFB`（分已降）、`org.watchthelight.XeGfxIntelFB`、
`org.watchthelight.IGPUConsoleRange`、`org.watchthelight.XeGfx`、`XeGfxAccel`。
缺任何一个 → 不要重启；用 policy 修复脚本处理后重装。

```bash
touch /var/db/xegfx/armed && sudo reboot
```

### 4.4 回来之后：先只验"归属换成功"

```bash
ioreg -l -w0 2>/dev/null | grep -c "class XeGfxIntelFramebuffer"
ioreg -l -w0 2>/dev/null | grep -c "class NMIntelFB"
ioreg -l -w0 2>/dev/null | grep -c "class IONDRVFramebuffer"
ioreg -c XeGfxIntelFramebuffer -l -w0 2>/dev/null | grep -E "IOFBDependentID|IOFBDependentIndex|built-in" | head -4
system_profiler SPDisplaysDataType | grep -E "Resolution|UI Looks|Online|Main Display|Metal"
pgrep -x WindowServer
tail -8 /var/db/xegfx/fbgeom.log                       # NMIntelFB 不再 owning → 应恢复工作
sudo /usr/local/bin/xenative-ctl status | grep -E "SURF|STRIDE|PS_CTRL"
```

**判据**

| 现象 | 含义 | 下一步 |
| --- | --- | --- |
| `XeGfxIntelFramebuffer` = 1、`NMIntelFB` = 0、`IONDRVFramebuffer` = 0、屏幕正常 | ✅ 归属换成功，且是 accel 认的那个类 | 进 §5 |
| `XeGfxIntelFramebuffer` = 1 但屏幕黑/异常 | 它 start 了但没接管好 | 报告；回退见 §6 |
| `XeGfxIntelFramebuffer` = 0、`IONDRVFramebuffer` = 1 | 它 start 失败，回落到了 Apple 的 IONDRV（屏幕仍会正常） | 报告 `log show` 里 `IONDRVSupport` / `XeGfxIntelFB` 的行；**不要反复重试** |
| `SURF = 0xfd000000` | `fbgeom` 已恢复工作（stage4=-28 的根因也顺手解掉） | 记下，这是额外收益 |

### 4.5 再验"accel 认不认"（同一次开机，接着做）

```bash
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60 ; sudo sysctl -w debug.xegfx_stage=7 ; sleep 25
sudo sysctl -b debug.xegfx_results | od -A n -t d4           # 期望 stage4 = 1（fbgeom 已搬 SURF）
sudo log show --last 3m --predicate 'eventMessage CONTAINS "NMXAccel"' | tail -15
```
**关键读这一句**：
- 出现 `passed the start gate … registering it`（或类似"注册成功"）→ ✅ 头被认了
- 仍是 `not an XeGfxIntelFramebuffer -- not ours` → 说明类名检查还有别的条件，**停手报告，不要继续**

```bash
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null | grep -ci nvmtl        # 带 sudo！
ls -t /Library/Logs/DiagnosticReports/WindowServer*.ips 2>/dev/null | head -2
```
**若出现新的 `WindowServer-*.ips` 且内容含 `CompositorSW::CompositeLayersToDestination` → 停手**，那是 A-19c 那个 SIGABRT 复现。

## 5. 若 accel 认了：量 Gate 4

```bash
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null > ~/xegfx-log/A-21/vmmap-full.txt
grep -ci nvmtl ~/xegfx-log/A-21/vmmap-full.txt
sudo sample "$(pgrep -x WindowServer)" 3 -file ~/xegfx-log/A-21/ws-sample.txt >/dev/null 2>&1
grep -cE "CA::OGL::SW|scanline|draw_polygon" ~/xegfx-log/A-21/ws-sample.txt
sudo powermetrics --samplers tasks -n 1 2>/dev/null | sed -n '1,20p'   # 必须带表头
system_profiler SPDisplaysDataType | grep -i metal
```

> **测量纪律（A-19c 的教训）**：`sample` 的命中数受"桌面是否在动"影响极大（498 vs 0 都不是证据）。
> 必须在**同一状态下**对比：加载 accel 前后各采一次，且两次都**先让桌面静止 10 秒**。
> `powermetrics` 的列是 `CPU ms/s`，不是百分比。

## 6. 回退（两条，都很短）

**① 换回 NMIntelFB 接管**（把分改回来即可，kext 都还在）：
```bash
sudo /usr/libexec/PlistBuddy -c "Set :IOKitPersonalities:NMIntelFB:IOProbeScore 66000" /Library/Extensions/NMIntelFB.kext/Contents/Info.plist
sudo /usr/bin/kmutil install --volume-root / --allow-missing-kdk -v   # 核对 id 后重启
```

**② 回到 A-20 之后的干净状态**（不装 XeGfxIntelFB）：
```bash
sudo rm -rf /Library/Extensions/XeGfxIntelFB.kext
sudo /usr/libexec/PlistBuddy -c "Set :IOKitPersonalities:NMIntelFB:IOProbeScore 66000" /Library/Extensions/NMIntelFB.kext/Contents/Info.plist
sudo /usr/bin/kmutil install --volume-root / --allow-missing-kdk -v
```

起不来时：U 盘 `D:\EFI`（带 `-x`）→ 删掉出问题的 kext → 重建 KC。
