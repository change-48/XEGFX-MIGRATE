# Gate 4 · A-42 执行提示词：把 `accelfb=3` 补回去（A-41 的唯一缺口）

> A-41 已经把编译层打通：`native emitter` 归零、CA abort 归零、特化 60/60、`CA::MTL>0`、`CompositorSW=0`。
> 但 A-41 的执行参数用了 `debug.xegfxaccelfb=1`（**是我提示词写错**），而加速器源码里：
>
> ```c
> static void triggerFromSysctl(int how) {
>     if (how >= 4) gNvAperture = 1;
>     if (how >= 3) { gNvScanout = 1;
>         if (gAccel->registerFramebufferLocked(1))
>             ALOG("sysctl debug.nvaccelfb=%d: scanout-backed display pipe ENABLED …");
> ```
>
> `how >= 3` 才开 scanout。写 1 → `gNvScanout = 0` → 没有 scanout 支持的 display pipe
> → `bufferFlipCount = 0`、`Invalid display` 94 次。
>
> **本关只补这一个参数**，其余与 A-41 完全一致。

---

## 0. 依据

| 事实 | 出处 |
| --- | --- |
| `how >= 3` 才 `gNvScanout = 1` 并 `registerFramebufferLocked(1)`（"scanout-backed display pipe ENABLED"） | `kexts/NVRM/accel/nvrm-accel.cpp:764-774` |
| A-38 用 `accelfb=3` 时出现 `(CPU copy target)` + `initFramebufferResource … over the LIVE SCANOUT`、`surfaceCount 251–308` | A-38/A-39 报告 |
| A-41 用 `accelfb=1`：`CA::MTL>0` 但 `bufferFlipCount=0`、`Invalid display` ×94、`surfaceCount` 只到 59 | A-41 报告 §4F/§5 |
| `Invalid display` 不在我们的源码里（grep 全树 0 命中）→ 是 CoreDisplay 说的 | 已核实 |

即：**编译/管线这一层已经通了；缺的是"scanout-backed pipe"**，而它由一个 sysctl 的数值决定。

## 3. 本关唯一动作：`accelfb=3`，并确认那句日志

```bash
( sudo log stream --predicate 'eventMessage CONTAINS "NVMTL" OR eventMessage CONTAINS "NMXAccel" OR eventMessage CONTAINS "AGDC" OR process == "WindowServer"' > $L/stream.log 2>&1 & )
sleep 2

# 关键：写 3（不是 1）。读回值恒 1 属已知（读的是 gNvAccelArmed），不影响内部 how
sudo sysctl -w debug.xegfxaccelfb=3; echo "read-back: $(sudo sysctl -n debug.xegfxaccelfb)"
sleep 5

echo "=== 门 3：scanout-backed pipe 是否开了（这一行是本关的核心）==="
sudo log show --last 3m --predicate 'eventMessage CONTAINS "NMXAccel"' 2>/dev/null \
  | grep -E "scanout-backed display pipe ENABLED|registering any published head|level [0-9]+" | tail -6 | tee $L/accelfb3.txt

echo "=== 四条形态（回归）==="
sudo log show --last 3m --predicate 'eventMessage CONTAINS "NMXAccel"' 2>/dev/null \
  | grep -E "accepted as head 4|CPU copy target|initFramebufferResource|heads published" | tail -4 | tee $L/shape.txt
```

**门 3（本关成败）：出现 `scanout-backed display pipe ENABLED`。**
- 出现 → 进 §4。
- 没出现但出现 `level 3: registering any published head that has no pipe yet` → 说明**没有可注册的头**，
  记录当时的 `ioreg -l -w0 -c XeGfxIntelFramebuffer | grep -E "IOFBDependentID|IOFBDependentIndex"` 后停手。
- 连 `level` 都没有 → 该 sysctl 没进到 `triggerFromSysctl`，贴 `debug.xegfxaccelfb` 的原始回显与日志后停手。

## 4. 判决：重启 WS，看 `bufferFlipCount` 与 `Invalid display`

```bash
sudo launchctl kickstart -k system/com.apple.WindowServer
sleep 60

echo "=== A) 加速器统计（本关核心判据）==="
sudo ioreg -l -w0 -r -c NMXAccel 2>/dev/null | grep -oE '"(surfaceCount|bufferSwapCount|bufferFlipCount|contextGLCount)"=[0-9]+' | tee $L/perfstats-60s.txt

echo "=== B) Invalid display 次数（A-41 是 94）==="
grep -c "Invalid display" $L/stream.log

echo "=== C) WS 存活与崩溃签名 ==="
pgrep -x WindowServer | wc -l; ps -o etime=,pid= -p "$(pgrep -x WindowServer)" 2>/dev/null
ls -t /Library/Logs/DiagnosticReports/WindowServer-2026-11-01-*.ips 2>/dev/null | head -2
sudo log show --last 5m --predicate 'process == "WindowServer"' 2>/dev/null | grep -c "OS_REASON_COREANIMATION\|WATCHDOG"

echo "=== D) 合成栈 ==="
sudo sample $(pgrep -x WindowServer) 2 -file $L/ws.txt >/dev/null 2>&1
echo "MetalContext=$(grep -c 'MetalContext' $L/ws.txt) CompositorSW=$(grep -c 'CompositorSW::CompositeLayersToDestination' $L/ws.txt)"

echo "=== E) 屏幕 ==="
system_profiler SPDisplaysDataType 2>/dev/null | grep -E "Resolution|Online|Main Display"
```

判读：

| 现象 | 结论 |
| --- | --- |
| `bufferFlipCount > 0` 且 WS 活过 60 s、`Invalid display` = 0 | **呈现打通**，Gate 4 第 3 条达成 |
| `bufferFlipCount` 仍 0、但 `surfaceCount` 明显增长 | scanout pipe 开了但帧没翻 → 下一步查 flip 请求（`nvrm-accel` 的 flip 路径） |
| `Invalid display` 仍大量出现 | 记下那个 displayID，与 `ioreg` 里的 FB id 对照（`0x23d05e40` 是 A-41 的值） |
| WS 又被看门狗收走 | 贴主线程栈的前 12 帧（是否仍是那个 QuartzCore 递归） |
