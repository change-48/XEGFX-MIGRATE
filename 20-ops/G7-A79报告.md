## 1. P0 · 休眠唤醒丢帧

### 1.1 取证（改码之前）

A-78 的休眠卡死快照（`A-78/counters-a74-sleep-wedge.txt`）里有一条此前没被注意的事实：

```
pipe_perform 2219   ← 与 pipe_validate 2219 一起冻住
iop_ok 1724         ← 拷贝路径计数同时冻住
flips 494 / defer_queued 495 / defer_armed 494 / defer_dropped 1 / defer_copied 1
flip_fail 1
```

即**不是「flip 通道单独坏了」**：唤醒后连 `performTransaction` 都不再进来。本关先做两组对照把它定位：

| 实验 | 条件 | 结果 |
| --- | --- | --- |
| E-a | `flip=0 defer=0`（拷贝路径）+ `pmset displaysleepnow` → `caffeinate -u` 唤醒 | **完全正常**：`ok` 4039→4222，`vblank_waits` 继续增长，`fail=0` |
| E-b | `flip=1 defer=1` + 同一触发 | **同样正常**：`flips` 84→260，`fail=0`，`drop=0` |
| E-c | `flip=1 defer=1` + DPMS ×5 快速循环 | 正常，`flips` 585→831 |
| E-d | `flip=1 defer=1` + **整机睡眠**（`pmset sleepnow` + RTC 定时唤醒） | 正常，`flips` 1740→1908，`fail=0`；使用者确认画面正常 |

**⇒ 触发条件在 26.7.2 + A-74 插件 + 现行 accel 上不再复现。** 结合代码，能解释 A-78 那次「一次失败就永久黑」的机制只有一条
（`nvrm-accel.cpp` 原 `nvAccelXeFlipArm` 失败分支）：

```c
gXeFlipUncertain = s; ((OSObject *)s)->retain();   // 之后每次 arm 开头直接 return false —— 永不清除
gIopXeFlip = 0; gIopXeDefer = 0;                  // 把操作员设的开关直接改掉，本 boot 内不再恢复
```

也就是说：**单次 25 ms 的 latch 超时 = 本 boot 内 flip 通道永久死亡**，而「谁会 latch 失败」取决于当时的显示电源状态。
这不是「唤醒 bug」，是一条设计上的死路。P0 的任务因此从「找唤醒触发点」变成「拆掉这条死路」。

### 1.2 修法（已装机）

| # | 改动 | 代码位置 |
| --- | --- | --- |
| 1 | latch 超时**不再是判决**：超时后先问面板「还在扫吗」（30 ms 读 `0x70040`）。不在扫 = 显示器在睡，这一帧走拷贝、**路径保持 armed**，不 pin、不关 | `nvXePanelScans` / `nvAccelXeFlipArm` |
| 2 | 在扫（真漏帧）→ **重铺平面**（补 `PLANE_CTL` enable 位 + 写回缓存 stride，读回核对）→ **同一帧内重试一次** | `nvXePlaneRepair` |
| 3 | 两次都失败 → **停车 2 s**（`gXeFlipSuspended` 门控，**不再改 `debug.xegfxaccel_iop_xe_flip`**），拷贝路径保证屏幕活着；2 s 后 `nvXeFlipTick` 自动重铺 + 复活 | `nvXeFlipTick` |
| 4 | `gXeFlipUncertain` 加**2 s 上限**，到期丢弃（原来永久 pin） | `nvAccelXeFlipArm` 入口 |
| 5 | 「6 帧连续不上屏」也改成停车 2 s，不再把 `flip/defer` 清零 | `nvAccelXeFlipDeferRun` |
| 6 | 10 Hz 面板健康检查：vblank 停 >300 ms 记日志，恢复时判定为「显示唤醒」并重铺平面 | `nvXePlaneWatch` |
| 7 | 新增 `debug.xegfxaccel_plane_dump`：**实时**读 `PLANE_CTL/STRIDE/SURF/FRMCOUNT` + 路径状态（`xenative-ctl` 打印的是缓存快照，FRMCOUNT 不动，A-78 因此拿不到寄存器证据） | `nvXePlaneDumpText` |
| 8 | 新增故障注入 `debug.xegfxaccel_iop_xe_flip_failtest=N`：让下 N 次 arm 假装漏 latch，用于演练自愈 | 同上 |

```
ffffff8002b97fee T __ZN20IOSurfaceDeviceCache10setCurrentEv
```

三个都是 `T`（导出）→ 可链接。装后 `kmutil showloaded` 正常、新 sysctl 全部出现，证实 kxld 解析通过。
