# Gate 4 · A-24 执行提示词（把 Metal 插件装回去，然后看 vmmap）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **成本：恢复文件 + 打签名 + 1 次开机（约 15 分钟）。**
> A-23a 已经把 accel 的 scanout 通道打通了，本次只是把"被回滚搬走的插件"放回来。

---

## 0. 现在的状态（A-23a 之后）

机制侧**已经通了**（原文）：
```
NMXAccel: boot framebuffer .Display_boot: 3120 x 2080 pitch 12480, 25958528 bytes (CPU copy target)
NMXAccel: NVDisplayPipe::initFramebufferResource(head 4, index 0, res ...) -> vidmem
          over the LIVE SCANOUT phys 0x70800000 3120 x 2080 pitch 12480
NMXAccel:   debug.xegfxaccelfb now reads 1 (heads published 0x10, registered 0x10, piped 0x10)
```
`0xe00002c7` **一次都没出现**，屏幕干净。

唯一缺的东西：**`/Library/GPUBundles` 是空的**（16:24 那次护栏回滚把它整个搬走了）。
没有插件 → Metal.framework 无可 dlopen → WindowServer 拿不到 Metal 设备 → `vmmap nvmtl` 必然 0。
**所以上一关的 `vmmap = 0` 不是 accel 的问题，是插件不在。**

已知现场：
- 备份 `/Library/XeGfx/rollback-backup-20261031-162412/` 里有：
  `NVMTLDriver -> NVMTLDriver.bundle`（软链）、`NVMTLDriver.bundle/`、`nvmtl/`（11 个文件）、`nvmtl-allow.txt`
- 签名工具 `/usr/local/bin/xegfx-metal-fix.sh` + `/usr/local/bin/patch-csflags.py` 都在；
  它给插件与 `nvmtl/*.dylib` 打 `CS_PLATFORM_BINARY`（否则 dyld 拒绝映射进 WindowServer）
- accel 的 `MetalPluginName` 已是 `../../../Library/GPUBundles/NVMTLDriver`、`NVMTLDevice`

---

## 1. 铁律

- 一次开机一个变量：本次只做"装回插件 + 签名"。**不改 accel、不改 framebuffer、不改探针分、不动 OpenCore**。
- **签名必须重启才生效**（CDHash 不覆盖 flags/platform 字段，缓存按 CDHash 索引）。
- 重启前 `touch /var/db/xegfx/armed`；**armed 后 120 s 内不要再重启**。
- 装载后**先抬头看屏幕**再跑任何 GPU 程序 —— A-16 那次"上 1/3 彩噪"就是这条路上的老账。
- 不许 `kickstart` `kernelmanagerd` / `syspolicyd`；装 kext 若需要，走 `kmutil create -z`。

---

## 2. 步骤

### 2.1 恢复插件（4 条）

```bash
B=/Library/XeGfx/rollback-backup-20261031-162412
mkdir -p ~/xegfx-log/A-24
ls -la "$B" | tee ~/xegfx-log/A-24/backup-list.txt

sudo mkdir -p /Library/GPUBundles
sudo cp -R  "$B/NVMTLDriver.bundle" /Library/GPUBundles/
sudo cp -R  "$B/nvmtl"              /Library/GPUBundles/
sudo cp -p  "$B/nvmtl-allow.txt"    /Library/GPUBundles/
sudo ln -sfn NVMTLDriver.bundle     /Library/GPUBundles/NVMTLDriver

sudo chown -R root:wheel /Library/GPUBundles
sudo find /Library/GPUBundles -type d -exec chmod 755 {} \;
sudo find /Library/GPUBundles -type f -name "*.dylib" -exec chmod 755 {} \;
sudo chmod 644 /Library/GPUBundles/nvmtl/intel_icd.x86_64.json /Library/GPUBundles/nvmtl-allow.txt
sudo xattr -cr /Library/GPUBundles
```

**落地校验**（不对就先别往下走）：

```bash
ls /Library/GPUBundles/nvmtl | wc -l        # 期望 11
test -L /Library/GPUBundles/NVMTLDriver && echo SYMLINK-OK
codesign -v /Library/GPUBundles/NVMTLDriver.bundle && echo BUNDLE-SIG-OK
for f in /Library/GPUBundles/nvmtl/*.dylib; do codesign -v "$f" || echo "BAD $f"; done; echo SIG-CHECK-DONE
```

### 2.2 打 CS_PLATFORM_BINARY（关键，别省）

```bash
sudo /usr/local/bin/xegfx-metal-fix.sh 2>&1 | tee ~/xegfx-log/A-24/metal-fix.txt
```
看输出里 `flags` 是否出现 `0x04000000`（`CS_PLATFORM_BINARY`），`platform` 是否为 1。
至少确认这两处：
```bash
codesign -d --verbose=4 /Library/GPUBundles/NVMTLDriver.bundle/Contents/MacOS/NVMTLDriver 2>&1 | grep -E "flags|platform"
codesign -d --verbose=4 /Library/GPUBundles/nvmtl/libvulkan_intel.dylib 2>&1 | grep -E "flags|platform"
```
> 若脚本报 `missing /usr/local/bin/patch-csflags.py`，先确认该文件在（A-00 时代的遗留脚本，应该还在）；
> 不在就**停手报告**，不要自己写一个替代品。

### 2.3 顺手查一个旧账（只读，不改）

A-23a 报告里 `results` 第 5 项又是 `-28`，而 A-19c 时有 `fbgeom` 搬到 `0xFD000000` 才变成 `1`。
先看清这次开机 `fbgeom` 到底跑没跑：

```bash
tail -15 /var/db/xegfx/fbgeom.log
sudo /usr/local/bin/xenative-ctl status | grep -E "SURF|SURF_before|STRIDE"
```
记录：`fbgeom` 本次开机是"完成"还是"跳过/失败"，`SURF_before` 是 `0xfe600000` 还是 `0xfd000000`。
**只记录，不要在本关修改它。**

### 2.4 重启并验证

```bash
touch /var/db/xegfx/armed && sudo reboot
```

回来后：

```bash
# 1) 先看屏幕（这是最要紧的），再看别的
system_profiler SPDisplaysDataType | grep -E "Resolution|Online|Main Display"
pgrep -x WindowServer

# 2) 应用侧 Metal 是否恢复（插件层的独立验证，与 WS 无关）
( ~/xegfx-probes/mtlprobe > ~/xegfx-log/A-24/mtl.txt 2>&1 & ) ; sleep 30
tail -4 ~/xegfx-log/A-24/mtl.txt        # 期望 MTLCopyAllDevices count = 1、16/16

# 3) 加载 core + 推 stage
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60 ; sudo sysctl -w debug.xegfx_stage=7 ; sleep 25
sudo sysctl -b debug.xegfx_results | od -A n -t d4
sudo sysctl -w debug.xegfxaccelfb=3
sleep 5

# 4) 判据
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null > ~/xegfx-log/A-24/vmmap-full.txt
grep -ci nvmtl ~/xegfx-log/A-24/vmmap-full.txt                     # ★ 期望 > 0
sudo log show --last 5m --predicate 'eventMessage CONTAINS "NMXAccel" OR eventMessage CONTAINS "nvmtl"' | tail -30
ls -t /Library/Logs/DiagnosticReports/WindowServer*.ips 2>/dev/null | head -2
system_profiler SPDisplaysDataType | grep -i metal
```

**判读**

| 现象 | 含义 | 下一步 |
| --- | --- | --- |
| `vmmap > 0` + 屏幕干净 | ✅ **Gate 4 达成**（呈现=CPU 拷贝路径，不是零拷贝） | 收尾，量四条 |
| `vmmap > 0` 但**上 1/3 彩噪** | A-16 老毛病复现 | **立刻重启**（不加载 accel），报告"彩噪复现 + pitch 已是 12480 + 走的是 copy target" → 转 A-23b |
| `vmmap = 0`，但 `mtlprobe` 16/16 | 插件在、app 侧通，但 WS 没拿 | 贴 `log show` 里 nvmtl 的加载记录（是被拒还是没尝试） |
| `mtlprobe` 也失败 | 插件层没恢复 | 查 `codesign -d --verbose=4` 的 flags/platform、`nvmtl-allow.txt` 内容、`log show` 里 dyld 的拒绝原因 |

### 2.5 若成功：量 Gate 4 四条

```bash
sudo vmmap "$(pgrep -x WindowServer)" 2>/dev/null | grep -ci nvmtl
system_profiler SPDisplaysDataType | grep -i metal
sudo powermetrics --samplers tasks -n 1 2>/dev/null | sed -n '1,20p'   # 列是 CPU ms/s，必须带表头
```
**测量纪律**：`sample` 的 `CA::OGL::SW` 只在"桌面在动"时可比；判"换没换合成器"用
`vmmap nvmtl > 0` + 有无 `CompositorSW` 崩溃，不要用静止桌面的 sample 计数。
