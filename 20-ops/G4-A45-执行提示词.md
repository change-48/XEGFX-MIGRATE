# Gate 4 · A-45 执行提示词：把每帧 12ms 的 scanout 拷贝降下来

> 实测（2026-11-01 15:00，用户拖动窗口期间，9 个采样点）：
>
> ```
> WindowServer CPU  478–872 ms/s（均值 ~740）
> kernel_task CPU   300–695 ms/s（均值 ~490）
> 帧率              31–61 fps（均值 ~41），面板 120Hz
> ```
>
> `kernel_task` 490 ms/s ÷ 41 fps ≈ **每帧 12 ms**，全部花在 `performTransaction` 的像素拷贝上
> （3120×2080×4 = 26 MB，12 ms ⇒ **2.2 GB/s**）。
>
> 原因在源码：那是一段**逐 4 字节、两边都 `volatile`** 的循环（3120/1 × 2080 = **650 万次**存取），
> 编译器无法向量化，对写合并内存又是窄写——WC 缓冲几乎用不上。
>
> **本关只改这一段**：同样的字节、同样的顺序，换成行级 `memcpy`（源 pitch 12544 与扫描 pitch 12480
> 只在**行**上不同，所以按行搬是对的）。

---

## 0. 依据

### 0.1 现行代码（`kexts/NVRM/accel/nvrm-accel.cpp`，`performTransaction()` 尾部）

```c
    nvAccelIopHome(fb, head);
    const unsigned words = (((pitch < q.pitch) ? pitch : q.pitch) & ~3u) / 4;
    const unsigned spr = pitch / 4, dpr = q.pitch / 4;
    volatile unsigned int *d = (volatile unsigned int *)q.kva;
    for (unsigned y = 0; y < h; y++) {
        const volatile unsigned int *sp = src + (unsigned long)y * spr;
        volatile unsigned int *dp = d + (unsigned long)y * dpr;
        for (unsigned x = 0; x < words; x++) dp[x] = sp[x];
    }
```

### 0.2 上游同处（`raw.githubusercontent.com/.../xe/kexts/NVRM/accel/nvrm-accel.cpp` 第 1219–1226 行）

**逐字相同**。所以这不是"我们落后于上游"，而是上游自己也还吃这个代价
（他们的面板 2560×1600 像素少 24%，同样受着）。

上游的优化方向是**消除拷贝**（Issue #12：ArrowWhatever 的 GGTT 零拷贝 scanout + 延迟 flip），
那属下一步；本关先把现存的路径做到它该有的速度。

### 0.3 为什么行级 `memcpy` 是对的

- 源 pitch **12544**（CA 的 IOSurface，256 字节对齐），扫描 pitch **12480**（3120×4）；
  两者**只差在行距**，每一行内部的 12480 字节是连续的 → 按行整体搬完全等价。
- 两边的行首都是 64 字节对齐（12480/64=195、12544/64=196），`memcpy` 会走到宽存/整行写，
  从而真正触发 WC 缓冲的整行合并。
- 语义不变：字节数、行序、覆盖范围与原来一致；`nvAccelIopHome(fb, head)` 仍在拷贝之前调用。

## 1. 改动（一处）

文件：`~/src/NvGfx-xe-2.6.2/kexts/NVRM/accel/nvrm-accel.cpp`

把

```c
    const unsigned words = (((pitch < q.pitch) ? pitch : q.pitch) & ~3u) / 4;
    const unsigned spr = pitch / 4, dpr = q.pitch / 4;
    volatile unsigned int *d = (volatile unsigned int *)q.kva;
    for (unsigned y = 0; y < h; y++) {
        const volatile unsigned int *sp = src + (unsigned long)y * spr;
        volatile unsigned int *dp = d + (unsigned long)y * dpr;
        for (unsigned x = 0; x < words; x++) dp[x] = sp[x];
    }
```

改成

```c
    /*
     * Copy the frame into the scanout.
     *
     * This used to walk the picture one 4-byte word at a time through volatile
     * pointers, which is 6.5 M dependent load/store pairs for a 3120x2080 panel
     * and defeats both vectorisation and write combining: measured 12 ms a frame
     * on 2026-11-01 (kernel_task 490 ms/s at 41 fps, 26 MB per frame = 2.2 GB/s).
     *
     * The two pitches only differ per row (source 12544, scanout 12480), so a row
     * is contiguous on both sides.  Move whole rows: memcpy issues wide stores and
     * lets the WC buffers merge full lines.  Same bytes, same order as before.
     */
    const unsigned bytes = (((pitch < q.pitch) ? pitch : q.pitch) & ~3u);
    const unsigned spr = pitch / 4, dpr = q.pitch / 4;
    volatile unsigned int *d = (volatile unsigned int *)q.kva;
    if (pitch == q.pitch && bytes == pitch) {
        memcpy((void *)d, (const void *)src, (size_t)bytes * h);   /* identical layout: one shot */
    } else {
        for (unsigned y = 0; y < h; y++)
            memcpy((void *)(d + (unsigned long)y * dpr),
                   (const void *)(src + (unsigned long)y * spr), (size_t)bytes);
    }
```

自检：

```bash
F=~/src/NvGfx-xe-2.6.2/kexts/NVRM/accel/nvrm-accel.cpp
grep -n "for (unsigned x = 0; x < words; x++) dp\[x\] = sp\[x\];" $F     # 期望：无输出
grep -n "memcpy((void \*)d, (const void \*)src" $F                        # 期望：1 行
grep -c "volatile unsigned int \*d = (volatile unsigned int \*)q.kva;" $F # 期望：≥1（变量仍在，只是不再逐字用）
```

**门 1：旧的逐字循环已消失、新分支存在。**

## 4. 测量：与 A-44 同一口径（**必须同样在"用户拖动窗口"期间**）

```bash
# 起 5 分钟采样，然后请用户做与上次相同的动作（拖窗口/滚动/开关窗口/启动台），约 1 分钟
cat > /tmp/loadprobe.sh <<'EOF'
#!/bin/bash
L=/tmp/loadprobe.txt; : > $L
for i in $(seq 1 150); do
  cpu=$(sudo powermetrics --samplers tasks -n 1 2>/dev/null | grep -E "^(WindowServer|kernel_task)" | head -2 | tr "\n" " ")
  a=$(sudo sysctl -n debug.xegfxaccel_iop_ok)
  echo "$(date +%H:%M:%S) $cpu | iop_ok=$a" >> $L
  sleep 2
done
echo DONE >> $L
EOF
chmod +x /tmp/loadprobe.sh; sudo nohup /tmp/loadprobe.sh >/dev/null 2>&1 &
```

分析（与上次同一脚本）：

```bash
python3 - <<'PY'
import re
rows=[]
for line in open("/tmp/loadprobe.txt"):
    line=line.strip()
    if not line or line=="DONE": continue
    m=re.match(r"(\d\d:\d\d:\d\d)\s+WindowServer\s+\d+\s+([\d.]+).*?kernel_task\s+\d+\s+([\d.]+).*?iop_ok=(\d+)", line)
    if m: rows.append((m.group(1), float(m.group(2)), float(m.group(3)), int(m.group(4))))
prev=None; ws=[]; kk=[]; ff=[]
for t,w,k,ok in rows:
    fps = 0 if prev is None else (ok-prev)/2.0
    prev=ok
    if w>200 or k>300 or fps>40: ws.append(w); kk.append(k); ff.append(fps)
avg=lambda a: sum(a)/len(a) if a else 0
print("负载样本:", len(ws))
print("WS   ms/s 均值 %.0f" % avg(ws))
print("kern ms/s 均值 %.0f" % avg(kk))
print("帧率 fps  均值 %.1f" % avg(ff))
if kk and ff and avg(ff)>0: print("每帧拷贝 ≈ %.1f ms" % (avg(kk)/avg(ff)))
PY
```

### 判据（对照 A-44 的基线）

| 指标 | A-44 基线 | 本关期望 |
| --- | --- | --- |
| `kernel_task` | ~490 ms/s | **≤ 200** |
| 每帧拷贝 | ~12 ms | **≤ 4 ms** |
| 帧率 | ~41 fps | **≥ 55** |

**本关成功 = 每帧拷贝降到 4 ms 以内。** 帧率若只小幅提升是正常的——还有 WindowServer 侧开销待优化（下一关）。

## 7. 铁律

1. **只改这一段拷贝**；不动 `nvAccelIopHome`、不动采样验证段、不动 `nvAccelIopFlip` 分支。
2. 屏幕一旦花屏 = pitch 处理错，**立刻回滚**（每行字节数必须取 `min(pitch, q.pitch)`）。
3. 构建失败不改编译参数。
4. 测量必须**同样在用户拖动期间**，否则与基线不可比（空闲时 WS 只有 10 ms/s）。
5. 一次一个变量：本关不碰 WS 侧、不碰 flip、不改 plist。
