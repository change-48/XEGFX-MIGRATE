## 1. 开工前的三条前提，逐条核对的结果

| # | 提示词的说法 | 实测 | 判定 |
| --- | --- | --- | --- |
| 0.1 | 1560×4=6240 → 6400，`/64 = 100` 可表达 | 成立 | ✅ |

### 1.1 提示词指的文件是旧副本，不是装机的那份

```
提示词：  ~/src/NvGfx-5a19a73.../kexts/XeGfxIntelFB/intelfb.cpp   22540 B  KMOD "0.5"
实际装机：~/src/NvGfx-xe-2.6.2/kexts/XeGfxIntelFB/intelfb.cpp      25432 B  KMOD "0.8"
```

用未改动的 `NvGfx-xe-2.6.2` 源码 + `build_xegfxintelfb.sh` 重新构建：

```
ce9baccb4832efe5df6070e851fda1c1f88148a8756f30b19e80d0cd80b3bfab  新建
ce9baccb4832efe5df6070e851fda1c1f88148a8756f30b19e80d0cd80b3bfab  /Library/Extensions 里的
```

逐字节相同 ⇒ `NvGfx-xe-2.6.2` 才是装机树，`NvGfx-5a19...` 里那份是 10-30 的旧版。

**而 0.8 版没有"追加一个模式"的任何框架**：它不 override `getDisplayModeCount` / `getDisplayModes` / `setDisplayMode`，
没有 HiDPI 分支，模式列表里只有固件给的一个 mode（ID=100，3120×2080）。"照抄 HIDPI 结构"这一步无源可抄。

### 1.2 scaler 的位定义（按 i915 源码核实，本机 `~/src/xe-src/linux/drivers/gpu/drm/i915/i915_reg.h:1929` 起）

```
PS_SCALER_EN        = REG_BIT(31)              ← 提示词对
PS_SCALER_TYPE_MASK = REG_BIT(30)  /* icl+ */  ← 提示词把 bit30 当成 PS_BINDING_PIPE，错
PS_BINDING_MASK     = REG_GENMASK(27,25)
PS_BINDING_PIPE     = 0                        ← 真正的"绑定到 pipe"
```

`0xC0000200` 实际写进去的是 `EN + TYPE=linear`，`BINDING` 仍是 0——恰好还是 0，所以这个错误"碰巧不致命"，
但语义是错的，而且**光写 `PS_CTRL` 不会有画面**。`skl_pfit_enable()` 实际要求：

```
PS_CTRL_1A   0x68180  EN(31) | BINDING=0 | filter
PS_WIN_POS_1A 0x68170  0
PS_WIN_SZ_1A  0x68174  (h-1)<<16 | (w-1)        ← 放大后的窗口 = 面板尺寸
PS_VPHASE_1A 0x68188   phase
PS_HPHASE_1A 0x68194   phase   (2x 放大 = 0x3000，由 skl_scaler_calc_phase(1,0.5) 算出)
TRANS_PIPESRC  0x6001C (1039<<16)|1559            ← 放大前的源尺寸
```

提示词里"只加两个 bit"的方案注定停在"左上角 1/4"。

### 1.3 加速器侧的 scanout 描述是缓存一次的

`nvrm-accel.cpp: describeBootFramebuffer()` 把结果填进 `fBootDesc` 后一直复用。它下游有硬护栏：

```c
if (w != q.width || h != q.height)
    NVIOP_FAIL(kIOReturnBadArgument, "source %ux%u is not the scanout's %ux%u", ...);
```

所以画面切换到 1560×1040 后，**拷贝会被这个检查拒绝**（不会越界读，也不会 panic），结果是**面板冻在最后一帧**，
而不是提示词预期的"桌面缩到左上角 1/4"。

## 2. 已完成的实际改动（已回滚）

在 0.8 真实源码上实现了阶段 A，编译通过（`-Werror` 零告警，73248→73376 B）：

- `XIFB_1X_MODE_ID 0x58470101`、1560×1040、行距 6400 常量
- 新增 `getDisplayModeCount` / `getDisplayModes`（base+1）、`getInformationForDisplayMode` 的 1560×1040 分支、
  `getPixelInformation` 的 1560×1040/6400 分支、`getTimingInfoForDisplayMode`（`kIOScalingInfoValid` + scaled 1560×1040）、
  `setDisplayMode` 的 1× 分支
- `xifbApplyScale1x(level)`：0 复原 / 1 只改 `PLANE_STRIDE`+`PLANE_SIZE` / 2 再开 pipe scaler（先 stride 后 size）
- 安全阀：`-xeintelfb1x=<0|1|2>`、`-xeintelfb1xoff`、`sysctl debug.xegfxintelfb_scale1x`
  （kext 的静态 sysctl 不在内核 link set 里，必须像加速器那样手动 `sysctl_register_oid`，第一版就是漏了这一步）

**节点证据**（13:12 那次启动，日志原文）：

```

XeGfxIntelFB: getDisplayModeCount: base 1 -> 2
XeGfxIntelFB: getDisplayModes: base 1 + quarter mode 0x58470101
XeGfxIntelFB: quarter mode 0x58470101: 1560x1040 nominal, refresh 120.053 Hz, flags 0x3 (base 0)
XeGfxIntelFB: quarter mode 0x58470101: 1560x1040 scaled to 3120x2080, 899888 kHz
```

即 **"多出一个 1560×1040 模式"这条链路本身是通的**；没走到的是"选中它"和"开 scaler"。

这是本关第二个关键事实，也是必须停下来的原因：

```

用树里未改的源码重建                  323712 B  7bcb399a585d...
```

`__text` 82229 vs 84229。字符串集对比（`comm`）：

```
只存在于装机版：        （空）
```

⇒ **源码树里有 A-53（scanout 缓冲/接管平面）和 A-54（flip 映射缓存）的改动，装机的加速器里一条都没有**，

## 4. 卡死那一次的取证

```
Kernel-2026-11-02-131730.panic
panic(cpu 4): thread_invoke: preemption_level 1, possible cause: blocking while holding a spinlock
Panicked task: pid 750: iconservicesagent
  _kalloc_ext → _IOMallocZero → XeGfx:_malloc → XeGfx:_idr_preload
  → XeGfx:_drm_gem_handle_create_tail → XeGfx:_i915_gem_create_ext_ioctl
  → XeGfxAccel:IOAccelXeGfxDRMClient::externalMethod
uptime 73 s
```

**回溯里没有一帧是 `XeGfxIntelFB`**。同一签名在**改动之前**就出现过：

```
Kernel-2026-10-30-163615.panic : idr_preload
Kernel-2026-10-30-164541.panic : idr_preload
Kernel-2026-10-30-164911.panic : idr_preload
Kernel-2026-11-02-131730.panic : idr_preload   ← 本次
```

⇒ 既有 bug：`idr_preload` 在抢占关闭的上下文里走 `malloc` 会阻塞，内核自己 panic。触发只要有人创建 GEM handle。

**连带后果**：这次（及前一次）没跑到 WindowServer，boot guard 计数到 `%02` → `XeGfxIntelFB` 拒绝 probe
→ 面板落到通用 `IONDRVFramebuffer`，`iop_ok` 恒 0（§3.8 那个"变 CPU 渲染"）。
`nvram xeintelfb-starts=%00` + 重启后恢复。
