# Gate 3 收尾 · A-14 执行提示词（让 macOS 自己按原生尺寸画）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **一句话：把 OpenCore 的控制台分辨率从 1920×1080 改成原生，让 macOS 的 framebuffer 自己变成 3120×2080。**

---

## 0. 为什么是这一步（A-13 之后的最后一块拼图）

A-13 已经证明：**平面 → 缩放器（1:1）→ transcoder → 面板**这段完全通了，我们的图案能原生 1:1 铺满。

但现在屏上的内容是"我们写的测试图"，不是桌面。原因是：

- 固件在 `phys 0x800000` 处映射了 **6656 页 = 26 MiB** 的连续帧缓冲（`live_run_pages 6656`），
  这个尺寸（26 MiB）**正好够 3120×2080×4（24.75 MiB）**。
- 而 macOS 只用前 **2025 页（8.29 MB = 1080p）**，因为 `IGPUConsoleRange` 开机日志写的是：
  ```
  IGPUConsoleRange: console 0x70800000 (1920x1080 rowBytes 7680) is DSM+0x0
  ```
- 这个 `1920x1080 rowBytes 7680` **不是 kext 里写死的**。主 agent 读了 `igpurange.cpp`：
  它只做一件事 —— 把开机视频信息（`PE_Video` 的 `v_baseAddr/v_width/v_height/v_rowBytes`）
  这个范围追加成 IONDRVFramebuffer 的 device memory 2。**宽高完全来自 GOP / OpenCore 的控制台模式。**
- 而 OpenCore 的 `config.plist` 里明确写着：
  ```
  UEFI → Output → Resolution = "1920x1080"
  ```

**所以真正的源头在这里：OpenCore 只给了 1080p 的控制台，macOS 就只按 1080p 用那块 26 MiB 缓冲。**

把它改成原生，macOS 就会自己按 3120×2080 / rowBytes 12480 往那块缓冲里画 ——
连 PTE 都不需要碰（那段 PTF 已经映射好、且 `< 256MB`、连续）。

---

## 1. 已核实的先例与约束（别自己发明参数）

按 OpenCore 官方文档（`UEFI → Output`）：

| 键 | 语义 | 本机现值 |
| --- | --- | --- |
| `Resolution` | `WxH` / `WxH@Bpp` / `Max`。向 GOP 请求该模式，**GOP 不支持就保持当前** | `1920x1080` |
| `ForceResolution` | 强制设置分辨率，但**依赖 `OC_FORCE_RESOLUTION_PROTOCOL`，该协议只有 `OpenDuetPkg` 支持** | `false` |
| `ProvideConsoleGop` | 补 GOP 协议 | `true` |
| `UIScale` | 控制台缩放 | `1` |

**结论：不要开 `ForceResolution`** —— 我们是 UEFI 启动，那个协议不存在，开了也是空操作，只会增加变量。
真正有用的只有 `Resolution`。`Max` 会"从显示器 EDID 取最大可用分辨率"，而这块面板原生就是 3120×2080，
所以 `Max` 是首选、`3120x2080` 是备选。

---

## 2. 风险与前置（先读完再动手）

改成原生后会出现一个**中间窗口期**：macOS 已经按 3120 宽画，但平面几何还是 1080p
（`SIZE 0x0437077F / STRIDE 120 / PIPESRC 0x077F0437`，固件开机设的），
**屏幕会是错位的**。必须有一个开机自愈脚本在 macOS 起来后立刻把几何改成 3120 并锁存。

**顺序必须是：先装自愈脚本 → 再改 config → 再重启。** 反过来会黑屏/花屏一段时间且没人修。

自愈脚本必须**只在控制台真的是 3120 时才动作**，否则保持完全不动（万一 GOP 不接受原生，机器行为跟今天一样）。

---

## 3. 步骤

### 3.1 先装自愈脚本（这一步不改任何显示状态）

**`/usr/local/bin/xegfx-fbgeom.sh`**（root:wheel, 755）：

```bash
#!/bin/bash
# 只在 macOS 报 3120x2080 时把平面几何切成原生并锁存；否则完全不动。
LOG=/var/db/xegfx/fbgeom.log
log(){ echo "[$(date '+%F %T')] $*" >> "$LOG"; echo "[$(date '+%F %T')] $*"; }

for i in $(seq 1 24); do          # 最多等 120 s，等 WindowServer 起来
    res=$(system_profiler SPDisplaysDataType 2>/dev/null | grep -m1 "Resolution:")
    case "$res" in
        *"3120 x 2080"*) break ;;
    esac
    sleep 5
done
case "$res" in
    *"3120 x 2080"*) ;;
    *) log "console 不是 3120x2080（$res），不动"; exit 0 ;;
esac

log "检测到原生控制台，应用 3120 几何"
/usr/local/bin/xenative-ctl regset 3 2 195 1 0x081F0C2F 3 0x0C2F081F >> "$LOG" 2>&1
/usr/local/bin/xenative-ctl latch                                     >> "$LOG" 2>&1
/usr/local/bin/xenative-ctl status                                    >> "$LOG" 2>&1
log "完成"
```

LaunchDaemon `/Library/LaunchDaemons/org.xegfx.fbgeom.plist`：`RunAtLoad=true`，**不要 KeepAlive**，
`StandardOut/Err` 指 `/var/db/xegfx/`。装之前先确保 `/var/db/xegfx` 存在。

```bash
sudo launchctl bootstrap system /Library/LaunchDaemons/org.xegfx.fbgeom.plist
sudo launchctl list | grep fbgeom      # 有输出即注册成功
```

> 注意 `xenative-ctl regset` 的 `which` 映射是 `0=SURF 1=SIZE 2=STRIDE 3=PIPESRC 4=PS_CTRL 5=PLANE_CTL`，
> 上面这条写的是 **STRIDE=195、SIZE=0x081F0C2F、PIPESRC=0x0C2F081F**，**没有碰 PS_CTRL**（它保持 `0x80000200`）。

### 3.2 改 OpenCore 的 Resolution（唯一变量）

```bash
sudo diskutil mount disk0s1
P="/Volumes/NO NAME/EFI/OC/config.plist"
sudo cp -p "$P" "$P.bak-before-native-$(date +%Y%m%d-%H%M%S)"

# 首选 Max（从 EDID 取最大）
sudo /usr/libexec/PlistBuddy -c "Set :UEFI:Output:Resolution Max" "$P"
sudo plutil -lint "$P"                       # 必须 OK
sudo plutil -extract UEFI.Output.Resolution raw -o - "$P"
sudo diskutil unmount "/Volumes/NO NAME"
```

**只改这一个键。** 不要动 `ForceResolution`、`UIScale`、`ProvideConsoleGop`、boot-args、任何 kext。
U 盘 `D:\EFI` 的救援配置**不要碰**。

### 3.3 重启并验证

```bash
touch /var/db/xegfx/armed && sudo reboot
```
≤180 s 内 SSH 回来，然后：

```bash
# 1) 控制台到底变成什么了（这是本关的核心读数）
sudo log show --last 10m --predicate 'eventMessage CONTAINS "IGPUConsoleRange: console"' | tail -2

# 2) 系统认的模式
system_profiler SPDisplaysDataType | grep -E "Resolution|IOFBMemorySize"

# 3) 自愈脚本有没有生效
cat /var/db/xegfx/fbgeom.log
sudo /usr/local/bin/xenative-ctl status | grep -E "STRIDE|SIZE|PIPESRC|PS_CTRL|SURF"
```

## 4. 判读

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| 日志出现 `console 0x… (3120x2080 rowBytes 12480)`，且 `system_profiler` 报 `3120 x 2080` | ✅ **Gate 3 达成**：macOS 自己按原生尺寸画，几何已由脚本切成 1:1 | 收尾报告 + 照片 |
| 日志仍是 `1920x1080 rowBytes 7680`，`system_profiler` 仍 1080p | GOP 不接受 `Max`（或 EDID 没给出原生） | 见 §5 |
| 控制台变了但 `system_profiler` 没变 | `Resolution` 只影响 OpenCore 自己的 UI，没传进 `PE_Video` | 报告，转 kext 路线 |
| 屏幕错位/花屏但 SSH 在 | 自愈脚本没跑或跑早了 | 手动执行 `regset` + `latch`；把脚本的等待条件改宽后重试 |
| SSH 180 s 不通 | 严重 | 等 3 min；仍不通→断电一次；护栏会 attempts=2 自动回滚 kext。**若还不行，用 U 盘 `D:\EFI` 启动并用 ESP 里的 `config.plist.bak-before-native-*` 还原** |

---

## 5. 若 `Max` 无效：第二个（也是最后一个）配置级尝试

把 `Resolution` 从 `Max` 改成显式 `3120x2080`（**只改这一处**），再重启一次。
- 若控制台日志变成 `3120x2080 rowBytes 12480` → 成功，继续 §3.3 的验证。
- 若仍是 1080p → **说明 GOP 里没有这个模式**，配置层到此为止。
  停止在"配置路线"，报告，由主 agent 决定是否转 `XeGfxIntelFB`（自建 IOFramebuffer + 详细时序）路线 ——
  那是另一个量级的工程，不属于本关。

## 验收锚点（主 agent 独立跑）

1. `sudo log show --last 30m | grep "IGPUConsoleRange: console"` → 出现 `3120x2080 rowBytes 12480`。
2. `system_profiler SPDisplaysDataType` → `3120 x 2080`，`IOFBMemorySize` ≥ `25958400`。
3. `xenative-ctl status` → `PLANE_STRIDE 195`、`PLANE_SIZE 0x081F0C2F`、`PIPESRC 0x0C2F081F`、`PS_CTRL 0x80000200`（未被写）。
4. `xenative-ctl dump 0x68184 1` 与 `dump 0x68190 1` → 都是 `0x8000`（1:1 的硬件侧证据）。
5. `live_run_pages` 仍 6656、`live_phys` 仍 `0x800000`（证明系统真的用上了那 26 MiB）。
6. 屏幕内容可读、无错位；WindowServer 在；零新 panic；`IGPUConsoleRange` 仍在。
7. 失败时：`Resolution` 已还原或明确记录当前值，机器回到 1080p 可用状态。
