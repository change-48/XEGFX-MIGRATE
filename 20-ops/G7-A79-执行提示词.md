# Gate 7 · A-79 执行提示词：先修两条「必修缺陷」（休眠丢帧 + 内部 cb 污染 marks），再上 page-off + Device Cache + CCS

> 目标：A-78 判决 Tile4 画面线冻结（黑屏一票否决），但留下两枚**必修的地雷**——它们污染一切后续验收：
> ① **显示休眠→唤醒后 accel flip 通道必挂**（A-74 好件同样复现，与插件无关，只能重启）；
> ② **插件内部命令缓冲参与 WS marks**（A-78 §4.2：relayout 副本把面标 pending 后疑似不释放）。
> 修完这两条再上 **page-off + Device Cache + CCS（0024/0026 的剩余半边）**——前人最大单项：
> 58 → 82 翻/秒（page-off 关 vs 默认），神奇效果 60/59/48 → 89/85/76。
>
> **Tile4 保持冻结**（`tile4=0` + 哨兵，relayout 代码休眠留存——page-off 复用它的「同页换布局 + GPU 拷贝」能力）。
> 必读：`G7-A78报告.md`（§1.3/§1.4 休眠取证、§4 现象）、`G7-A77报告.md`、
> `AI-远程连接说明.md`、`AI-远程调试作业说明.md`。

## 2. P0 · 休眠唤醒丢帧（必修，先做，装机前把自愈写进去）

### 2.1 复现与取证（先拿机制证据再改码）

1. `flip=1 defer=1` 下让显示睡（`pmset displaysleepnow` 被拒就请使用者**合盖 2 秒再开**或按亮度键）；
2. 卡住时（`flips` 冻结、`fail=1`）抓：
   - **平面寄存器**：PLANE_CTL/STRIDE/SURF + pipe 状态（用 `10-diag/XeDiag.kext` 只读 dumper，
     或 accel 里已有的 `gDispMmio` 加一条只读 log）；
   - defer 状态：队列深度、`armed`、worker 最后一次失败的原因（arm 里失败分支加一条 log：谁拒绝了）；
   - 对照：睡前同寄存器值。
3. 判定失配点：pipe 被系统关了？平面 enable 位被清了？GGTT 映射失效了？——**只记证据**。

### 2.2 修法（两级，都装机）

- **自愈（必做）**：accel 里监听显示唤醒（`IORegisterNotifier`/display-wake 通知，或 worker 发现
  连续 N 次 arm 失败/长无 vblank 时）→ 重铺平面（按缓存值写 CTL/STRIDE/SURF）→ 清 defer 状态 → 重 arm。
  **修不好的兜底：唤醒后自动 `flip=0` 退拷贝路径**（屏幕活着、fps 掉一点），并打一条大 log。
  绝不允许「黑屏 + 只能重启」这个形态存在。
- 0024 对齐（顺手）：连续失败关 flip 的阈值行为对齐 0024（超时照样 arm + `idle_forced` 已在；失败计数语义核对）。

**门 P0**：休眠→唤醒 × 3 次（含一次合盖）：**桌面内容回来**（flips 恢复，或可感知地退到拷贝路径 + 一条 log），
不需要重启、不需要 kickstart。这是 A-79 一切后续验收的前提。

## 3. P1 · 内部命令缓冲不得参与 WS marks（必修）

1. **取证**：accel 的 pending 表（`gSurfPend`）加一个 dump sysctl（`surface_marks`：每条 id/seq/年龄），
   QUAD/STRING 注意注册坑；
2. **修法**：插件 commit 路径加「内部」标志（relayout 副本、以及 P2 的 page-off 拷贝线程都会走）：
   `nvmtl_ws_mark_pending` / `after_commit` 对内部 cb **跳过**（0026 的做法是副本等待走独立通道——
   relayout 里「先等 pending cb ≤500ms」那段就是独立通道，照它办：内部 cb 不登记 hold、不标 pending）；
3. 验证：手动触发一轮 relayout（tile4 切 1 再切 0——画面会黑，但 P0 的自愈现在应该能把通道救回来，
   **这同时是 P0 自愈的实战测试**）→ 之后 pending 表清空、无 pending 超龄条目、`mark_timeouts` 不增长。

**门 P1**：内部 cb 走完后 pending 表清空；`mark_timeouts` 无增长；relayout 触发后 flip 通道存活（靠 P0 自愈）。

## 4. P2 · page-off + Device Cache + CCS（主菜，分三级推进，每级可停）

### 4.1 二级 a · accel 侧 selectors（无调用者=惰性，先装机）

从 0024 移植：selector 3（锁 seeds）、selector 4（device cache 探测）、selector 5–8（page-off
current/wait/done/detach）、`nvXePoControl`/`nvXePoBeforeScan`（**等待一律 A-76 的
解锁→等→重锁→重验形态**——源码就在 `~/xegfx-log/A-77/before/nvrm-accel.cpp`，
**只取 pageoff 解锁与调用点计数部分**，合并进 A-77 基线源码，逐处核对重验字段）、
`IOSurface op 0` 控制钩子（device cache current 标记 + 加锁时等合成）、
`iop_xe_po` / `iop_xe_locks` 统计。

**门 2a**：装机后 selectors 无调用者、安全模式无回归（= A-77 末态行为 + P0/P1 修复）。

### 4.2 二级 b · 插件私有拷贝（lazy 版先行）

从 0026 移植：私有 optimal-tiling 图像创建（BGRA8、≥1024×600、非 scanout 判据）、
page-off 拷贝线程（走 P1 的内部通道！）、哨兵 `.xemtl-no-pageoff` / `-lazy`、
device cache current 标记（每次合成后经 selector 5）。
**先 lazy**（活 3s/画 100 次才升级私有），因为 lazy 版前人数字（60/59/48）已显著、且风险最低。

**门 2b**：`iop_xe_po` 计数增长、私有拷贝存在（log）、**画面正常**（一票否决）；
`imp_ok` 不暴涨（device cache 生效=导入减少）；拖动 3 轮 fps ≥ 33。

### 4.3 二级 c · coherent 规则 + CCS A/B

1. 按 0026 补一致性规则（锁计数不标 current、>4 次/s 退直画、唯一 root 保留、释放持同步对象）；
2. CCS A/B 照前人：`touch /private/tmp/xemtl-noccs` + kickstart WS（下次启动 `INTEL_DEBUG=noccs`）
   vs 默认，各 3 轮拖动；
3. 30 分钟日常使用稳定性（**含一次休眠唤醒**——P0 自愈实战）。

**门 2c（A-79 成功线）**：

| # | 检查 | 期望 |
| --- | --- | --- |
| 1 | 画面 | 全程正常（含截屏对照——前人踩过三次截屏白屏，一致性规则就是防它） |
| 2 | 帧率 | 拖动 3 轮中位 **≥ 38**（前人 page-off +24 翻/秒的按比例折算下限；busy 墙仍在，38 是现实线） |
| 3 | CCS A/B | noccs vs 默认的 fps 差值留档（前人 97-99 vs 76，我们量化自己的压缩收益） |
| 4 | 稳定性 | 30 分钟 + 1 次休眠唤醒：无黑屏、无 WS 报告、无 panic、`flip_fail=0` |
| 5 | 留档 | 全部 A/B 逐秒 + `iop_xe_po`/`iop_xe_locks`/`iop_tl` |

## 5. 时间盒与停点（执行方纪律）

- P0 卡住 > 90 分钟：只交自愈兜底版（唤醒退拷贝路径 + log），进 P1。
- P1 卡住 > 30 分钟：只交取证数据（pending 表 dump），P2 的插件拷贝线程改走「显式不标 pending」最小补丁。
- P2 每级可停：停在哪级，报告写到哪级，**判据表如实标「未做」**。
- 本关无论走到哪级，P0 的门必须过（否则 A-80 一切免谈）。

## 6. 回滚（由轻到重）

1. `touch /private/tmp/xemtl-no-pageoff`（插件 page-off 关）。
2. `sudo sysctl -w debug.xegfxaccel_iop_xe_flip=0 …defer=0`（拷贝路径）。
3. 插件回 A-74 件 / accel 回 A-77 件（`~/xegfx-log/A-79/` 三件套）+ 重启。
4. `sudo nvram xeintelfb-starts=%00`。
黑屏/只剩鼠标 → 直接重启，别折腾（A-78 §8.4）。
