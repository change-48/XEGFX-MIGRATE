# Gate 4 · A-32 执行提示词：抓 WS 卡在哪一行（不再猜）

> 目标：A-31 已经把链路全打通（`first present accepted` / `open() RELEASED` / AGDC / IOP 两个句柄），
> 但 WindowServer 在初始化里被扣住 → watchdog 杀掉 → panic。
> **本关只做一件事：拿到 WS 被扣住时的真实栈，定位到具体一层。**
>
> **零代码改动、零重编、零 kext 安装。** 需要重启一次（进 S3 后必须靠重启回干净态）。

---

## 0. 先纠正 A-31 报告里的两处判断（否则 A-32 会走错方向）

### 0.1 `NVMTL` 不是"别的加速器"，它就是我们 `NMXAccel` 的用户态前端

报告 §4.3 写「WS 拿到的是 NVMTL 而不是我们的 NMXAccel …… 两者口径不一致」。
**这条不成立。** `NVMTLDriver` 是 `XeGfxAccel` 配套的 Metal 插件（A-24 的
`NVMTL: vk: UP in this Metal process — "Intel(R) Graphics (ARL)"` 就是它），
它通过 Vulkan 走到 `NMXAccel`。所以 WS 用 NVMTL **恰恰说明它在用我们的加速器**。

→ 不要按"WS 选错了加速器"去查。要把"NVMTL 起来之后做了什么"当主线。

### 0.2 报告 §3.2 那段"WS 主线程栈"是**别的进程**

```
dyld → adid → CoreFoundation ×4 → libsystem_kernel → kernel + 317728
```
`adid` = `/System/Library/PrivateFrameworks/CoreADI.framework/.../adid`（AirPlay）。
那个 spin 是全系统 dump，按字母序排列，第 49 行属于 **`AirPlayXPCHelper [167]`**，不是 WindowServer。

**而且那份 spin 只含内核线程，没有 WS 的用户态栈** —— 所以"A-31 卡在 kernel 侧同步调用"
这个结论目前**没有证据**。这正是本关要补的。

### 0.3 唯一有信号的新线索（本关的假设）

A-31 的 `stream.log` 里，加速器在 WS 起来后连续打印：

```
NMXAccel: newSurface -> …
NMXAccel: getStampMemory(…) -> descriptor …
NMXAccel: createUserGPUTask -> … init=1          ← 反复出现
```

同窗口 `stream-ws.log` 里 NVMTL 做了 **28 次 pipeline 特化**，然后 WS 就再不 checkin。
`createUserGPUTask` 是 Vulkan 提交的入口。**最可能是"提交下去、等 fence 等不到"**，
而这条只有拿到 WS 的用户态栈（`vkQueueSubmit` / `vkWaitForFences` / `MTLCommandBuffer waitUntilCompleted`）
才能定。

> 注：`<decode: mismatch for [%p] got [SCALAR private sz:0]>` 这类是 **IOKit 结构化日志解码伪影**
> （格式串 `%p` 与实际参数类型不匹配），不是错误。**不要把它们当故障线索。**

## 1. 前提与预算（务必先看）

```
当前状态（21:17 实测）：phase=%00 trial=%00 expose=%00 fail=%01 starts=%01
                        core/accel 未加载、bootarm 已删除、无 armed、WS 204 存活、3120×2080
预算：starts 只剩 2 格；每进一次 S3 消耗一格。**本关只允许 1 次 S3。**
风险：WS 被 watchdog 杀满 120 s → kernel panic（A-31 已发生一次）。
     → 本关规则：**只允许出现 2 个 WS 实例**，第 2 个一并抓完立刻重启，不等它自己死。
```

## 2. 进 S3（与 A-31 完全一致，单路径，已验证）

### 2.1 预检

```bash
mkdir -p ~/xegfx-log/A-32; L=~/xegfx-log/A-32
{ echo "== nvram =="; nvram -p | grep xegfx
  echo "== loaded =="; sudo /usr/bin/kmutil showloaded | grep -iE "watchthelight|NMIntelFB"
  echo "== ws =="; pgrep -x WindowServer
  echo "== screen =="; system_profiler SPDisplaysDataType | grep -E "Resolution|Online"
} | tee $L/preflight.txt
test -f /var/db/xegfx/armed && echo "armed=YES(BAD)" || echo "armed=NO(ok)"
```

要求：`phase=%00`、`fail=%01`、`starts=%01`、无 armed、3120×2080、WS 存活。
**`xegfx-disp-bootarm` 必须已删除**（A-31 已删；若又出现，先 `nvram -d`，否则 stages 双跑）。

### 2.2 core → stage 7（手工，唯一入口）

```bash
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60 >/dev/null
sudo sysctl -w debug.xegfx_stage=7 >/dev/null
sleep 20
sudo sysctl -b debug.xegfx_results | od -A n -t d4 | tee $L/results.txt     # 期望 0 1 1 1 1 1 1 1
sudo log show --last 2m --predicate 'eventMessage CONTAINS "ran 58 sysinit_set"' 2>/dev/null | wc -l   # 期望 1
```

**门 1：`results` 七项全 1、`ran 58` = 1。** 不过就停手（A-30 的教训）。

### 2.3 accel（先装，门 2）

```bash
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfxAccel; echo "rc=$?"
sleep 3
sudo ioreg -l -w0 2>/dev/null | grep -c "class NMXAccel" | tee $L/accel.txt    # 期望 ≥1
```

### 2.4 S3 + 等 FB 注册

```bash
( sudo log stream --predicate 'process == "WindowServer" OR eventMessage CONTAINS "XEGFX_DISPLAY" OR eventMessage CONTAINS "AGDC" OR eventMessage CONTAINS "M3d:" OR eventMessage CONTAINS "NVMTL" OR eventMessage CONTAINS "NMXAccel"' > $L/stream.log 2>&1 & )
sleep 2
sudo nvram xegfx-disp-phase=%02 xegfx-disp-trial=%01 xegfx-disp-expose=%01 xegfx-disp-fail=%00
sudo touch /var/db/xegfx/armed
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfxDisplay; echo "display rc=$?"
for i in $(seq 1 60); do
  ioreg -l -w0 -c XeGfxFramebuffer 2>/dev/null | grep -q '"XeGfxFbRegistered" = Yes' && { echo "FB registered @${i}s"; break; }
  sleep 1
done
for i in $(seq 1 30); do
  n=$(sudo ioreg -l -w0 2>/dev/null | grep -c '"XeGfxAccelPresent" = Yes'); [ "$n" -ge 1 ] && { echo "accelPresent @${i}s"; break; }; sleep 1
done
for i in $(seq 1 10); do
  sudo sysctl -w debug.xegfx_agdc=1 >/dev/null 2>&1; sleep 1
  s=$(sudo sysctl -n debug.xegfx_agdc 2>/dev/null); echo "agdc arm $i -> $s"; [ "$s" = "1" ] && break
done
sudo sysctl debug.xegfx_agdc_fbmap
# 基线快照：进 WS 之前的加速器计数
sudo sysctl -a 2>/dev/null | grep -E "debug.nvaccel_" | sort | tee $L/nvaccel-before.txt
```

**门 3：FB registered + accelPresent + agdc state=1。** 任一不过 → 停手（此时屏幕可能已进入彩噪，见 §5）。

## 3. 本关的唯一动作：尽早、反复抓 WS 的栈

### 3.1 起 WS，并把"抓栈"做成循环（**关键：不要等它被 watchdog 杀**）

```bash
( sudo log stream --predicate 'process == "WindowServer" OR eventMessage CONTAINS "NVMTL" OR eventMessage CONTAINS "NMXAccel" OR eventMessage CONTAINS "QuartzCore"' > $L/stream-ws.log 2>&1 & )
sleep 2
sudo launchctl kickstart -k system/com.apple.WindowServer

for i in $(seq 1 8); do          # 8 × 12 s ≈ 96 s，留出重启余量
  sleep 12
  P=$(pgrep -x WindowServer)
  echo "[$i] ws=$P etime=$(ps -o etime= -p $P 2>/dev/null | tr -d ' ') n=$(pgrep -x WindowServer | wc -l)"
  sudo sample "$P" 1 -file "$L/sample-$i.txt" >/dev/null 2>&1
  sudo sysctl -a 2>/dev/null | grep -E "debug.nvaccel_" | sort > "$L/nvaccel-$i.txt"
  sudo sysctl -n debug.xegfx_agdc_cmds >> "$L/nvaccel-$i.txt" 2>/dev/null
  # 出现第 2 个 WS 实例 → 立刻停，不再等
  [ "$(pgrep -x WindowServer | wc -l)" -ge 2 ] && { echo "SECOND-INSTANCE at $i"; break; }
  # 已经稳定活过 60 s → 也不必继续
  [ "${i}" -ge 5 ] && echo "reached i=$i, stopping sampling"
done
sudo ioreg -l -w0 -c XeGfxFramebuffer > $L/ioreg-fb.txt 2>/dev/null
sudo ioreg -l -w0 -c NMXAccel > $L/ioreg-accel.txt 2>/dev/null
```

> 若 WS 一直存活且能 checkin（`etime` 持续增长、无新 pid），说明本关**成功**，跳 §4.2 的"成功分支"。
> 只要有第 2 个实例或 `etime` 冻结，立刻进 §5 停机。

### 3.2 立刻判：栈里有没有这几类帧

```bash
for f in $L/sample-*.txt; do
  echo "=== $f"
  grep -cE "vkWaitForFences|vkQueueSubmit|vkDeviceWaitIdle|MTLCommandBuffer|waitUntilCompleted|waitUntilScheduled" "$f" 2>/dev/null
  grep -oE "vk[A-Za-z]+|MTL[A-Za-z]+|NVMTL[A-Za-z_]*|IOSurface[A-Za-z]*|IOAccel[A-Za-z]*" "$f" 2>/dev/null | sort | uniq -c | sort -rn | head -6
done
```

判读：

| 栈里最先大量出现的 | 结论 | 下一步 |
| --- | --- | --- |
| `vkWaitForFences` / `vkDeviceWaitIdle` / `waitUntilCompleted` | **卡在 GPU 完成等待** —— 我们提交了但没回 fence | A-33：查 accel 的 fence/中断完成路径（`debug.nvaccel_pipe_*`、`nvaccel_scanout_*`） |
| `vkQueueSubmit` 且**没有** wait | 卡在提交本身（ioctl 里阻塞） | A-33：查 `createUserGPUTask` 的内核侧等待 |
| `IOKitWaitQuiet` / `IOService` / `mach_msg` 且无 vk 帧 | 卡在 IOKit 层（服务不 quiet 或 user client 阻塞） | A-33：查哪个服务不 quiet（`ioreg -l -w0 | grep -c busy`、`kmutil showloaded` 时机） |
| `CA::OGL::` / `QuartzCore` 为主 | 卡在 CA 自己（surface 记账） | A-33：回到 `transient surface not found` 那条线 |

**同时看计数器的变化**（这一条能独立佐证）：

```bash
diff $L/nvaccel-before.txt $L/nvaccel-1.txt | head -20
diff $L/nvaccel-1.txt $L/nvaccel-5.txt | head -20
```

- `debug.nvaccel_iop` / `nvaccel_iop_flip` **在涨** → 呈现路径在被调用，卡点在等完成
- 全部**冻结** → 卡点在进入我们代码之前（IOKit / CA 层）

## 4. 结束与判定

### 4.1 无论结果，96 s 内必须收工（避免 watchdog panic）

```bash
sudo ioreg -l -w0 > $L/ioreg-final.txt
sudo log show --last 6m --predicate 'process == "WindowServer" OR eventMessage CONTAINS "XEGFX" OR eventMessage CONTAINS "NMXAccel"' > $L/log-final.txt 2>/dev/null
sudo nvram xegfx-disp-phase=%00 xegfx-disp-trial=%00 xegfx-disp-expose=%00 xegfx-disp-fail=%01
sudo rm -f /var/db/xegfx/armed
sudo shutdown -r now
```

### 4.2 判定

| 情况 | 结论 |
| --- | --- |
| WS 活过 60 s 且 `etime` 持续增长、无新实例 | **Gate 4 第 3 条有希望**：补 §4.3 的成功取证（见下） |
| WS 被扣住 / 出现第 2 实例 | 本关达成目标（拿到栈），报 §3.2 的判读结果 |

§4.3 成功取证（仅当 WS 稳定）：

```bash
# 需要有已登录桌面 + 动态画面（静止桌面无可比性）
sudo sample $(pgrep -x WindowServer) 2 -file $L/ws-stable.txt >/dev/null 2>&1
grep -cE "CA::OGL::SW|scanline|draw_polygon" $L/ws-stable.txt     # 基准 1256
grep -cE "CA::MTL|MTLCommandBuffer|NVMTL|MetalContext" $L/ws-stable.txt
sudo ioreg -l -w0 -r -c NMXAccel 2>/dev/null | grep -A30 "PerformanceStatistics" | head -20
system_profiler SPDisplaysDataType | grep -iE "Metal|Resolution"
```

## 5. 停机（照做，别等）

1. **屏幕彩噪 / 黑屏 / 冻结 >10 s** → 立即执行 §4.1 的收工块（存档 + 清门 + 重启）。
2. **出现第 2 个 WS 实例** → 先把 `sample-*.txt` 抓完（这一步只要几秒），然后立即 §4.1。
3. `etime` 冻结超过 30 s → 同上。
4. `starts` 涨到 `%02` 后，**下一次进 S3 就是最后一次**（`%03` 自动禁用）。

## 7. 铁律（新增 A-31 两条）

1. `kmutil` 在 `/usr/bin`；**绝不** kickstart `kernelmanagerd` / `syspolicyd`。
2. **`xegfx-disp-bootarm` 与手工 `debug.xegfx_stage` 只能二选一**（A-30 的 `-19` 就是双跑）。
3. 进 S3 后**不要**让 WS 自己死到 120 s —— 那会 panic 并消耗 `starts`。
4. `armed` 之后 120 s 内不重启。
5. `sample`/`spindump` 必须在**进程还活着**时抓；被 watchdog 杀掉后只剩内核线程 dump（A-31 就是这样丢的）。
6. `<decode: mismatch/bad range>` 是日志解码伪影，**不是**故障线索。
7. 一次一个变量：本关不改代码、不改 nvram 门结构、不同时试 K5。
