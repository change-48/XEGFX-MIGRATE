# Gate 4 · A-18b 执行提示词（先证伪/证实"PTE 被抢"，再决定改源码）

> 用法：把本文件全文作为一条消息发给执行会话。执行会话不需要任何前置上下文。
> **第一步只用现成命令、零新代码、一次重启，就能判定花屏是不是"帧缓冲的 PTE 被分配器抢走"。**

---

## 0. 现在的判断（已被 A-18a 收窄到一条）

A-18a 已证明：
- **显示寄存器一个字节没动**（`regs-diff` 0 字节）：`0x7019c` SURF 与 `0x701ac` SURFLIVE 都还是 `0xfe600000`
- GPU 提交后 **GGTT 页表被改写**：`live_run_pages 6656 → 1701`、`present_entries 3518 → 4789 (+1271)`
- **应用侧 Metal 真的通**：`mtlprobe 16/16`
- **`vmmap | grep -c nvmtl = 18`** → 计划里那条"历史分水岭"**已经满足**

主 agent 又查到根因源码（`~/src/NvGfx-xe-2.6.2/gpu/xegfx/shim/src/xnu/xg_kext.cpp:501-508`）：

```c
if (rc == 1 && gPipeLit && gBootSurf && xg_boot_fb_size) {
    int err = xg_i915_reserve_bootfb(gBootSurf, xg_boot_fb_size);
    IOLog("XeGfx: boot surface GGTT 0x%x + %llu reserved: %d\n", gBootSurf, xg_boot_fb_size, err);
    /* -ENOSPC at or above GUC_GGTT_TOP is i915's own GuC-top reservation, which keeps it free (N-256) */
    if (err == -28 && gBootSurf < 0xfee00000u)
        rc = -28;   /* something else sits there: compositing into it would overwrite it */
}
```

`xg_i915_reserve_bootfb(0xFE600000, 25958400)` **返回 -28（ENOSPC）**。后果：
**这段 26 MB 在 i915 的 GGTT 分配器里没有被标记为已占用**，加速器一分配缓冲就可能落进去，
把帧缓冲那批 PTE 改写掉 → 硬件扫描时读到别处的内存 → 局部画面被写花。

算术上也讲得通：`0xFE600000 + 25,958,400 = 0xFFEC1800`，**跨过了 `GUC_GGTT_TOP = 0xFEE00000`**，
所以 insert 撞上 GuC 自己的保留区直接 ENOSPC；而注释那条"at or above GUC_GGTT_TOP keeps it free"的前提
（整段都在 GuC 之上）不成立 → 两头不讨好地失败。

**这条 `-28` 我们一直当成"显示归属冲突、已知可接受"。它其实不是无害的 —— 它就是 Gate 4 花屏的根。**

## 2. 铁律

- S1 全程**不改任何文件**，只用现成命令。
- 花屏出现后**不要放着不管超过 1 分钟**：先把 S1 做完，然后立刻重启。
- **macOS 没有 `timeout` 命令**（A-18a 踩过）。探针一律用 `( ./mtlprobe > out 2>&1 & )` 后台跑。
- 开机后 **XeGfx 不会自动加载**：必须先 `sudo kmutil load -b org.watchthelight.XeGfx`，再推 stage。
- 每次重启前 `touch /var/db/xegfx/armed`；重启后核对 AuxKC 含 `IGPUConsoleRange`。
- 不许动 OpenCore / boot-args / 显示几何 / `fbgeom`；不许开 `debug.xegfxaccelfb` / `_iop`。

## 3. S1：复现 + 原值重写帧缓冲 PTE（判定实验）

### 3.1 复现

```bash
mkdir -p ~/xegfx-log/A-18b
sudo kmutil load -b org.watchthelight.XeGfx
sudo sysctl -w debug.xegfx_wdog=60
sudo sysctl -w debug.xegfx_stage=7
sleep 25
sudo sysctl -b debug.xegfx_results | od -A n -t d4 | tee ~/xegfx-log/A-18b/results.txt

# 记基线：live 段与活页
sudo /usr/local/bin/xenative-ctl scan 7000 | tee ~/xegfx-log/A-18b/scan-before.txt
# 期望 live_run_pages 6656 / live_phys 0x800000

# 跑一次探针（后台，避免 TCC 阻塞），跑完看屏幕
( ~/xegfx-probes/mtlprobe > ~/xegfx-log/A-18b/mtl.txt 2>&1 & )
sleep 30
cat ~/xegfx-log/A-18b/mtl.txt | tail -5
sudo /usr/local/bin/xenative-ctl scan 7000 | tee ~/xegfx-log/A-18b/scan-after-stripe.txt
```
**看屏幕：应出现上 1/3 横向彩噪条纹。** 同时 `scan-after-stripe.txt` 的 `live_run_pages` 应明显小于 6656。

### 3.2 关键动作：把帧缓冲 PTE 按原值重写回去

原始映射是确定的：索引 `0xFE600` 起 **6656 页**，物理从 `0x800000` 起逐页 +0x1000，标志位 `0x3`
（A-09/A-10 已实测过 `[liveIdx+0]=0x800003`、`[+1]=0x801003` …）。

```bash
# 用 kext 内的 map 一次写完（不要 shell 循环，IOServiceOpen 约 980 次就失效）
sudo /usr/local/bin/xenative-ctl map 0xFE600 6656 0x800000
# 期望输出 bad 0，first 0x800003，last = (0x800000 + 6655*4096)|0x3 = 0x1A00003
```

**立刻抬头看屏幕：**

| 现象 | 结论 | 下一步 |
| --- | --- | --- |
| **屏幕当场恢复正常** | ✅ **证实**：花屏 = 帧缓冲那批 PTE 被分配器改写 | 进 S2（改源码，见 §5） |
| 屏幕部分恢复 / 条纹变样 | 部分证实：可能只有一部分索引被抢 | 同样进 S2，但在源码改动里要覆盖整个范围 |
| **完全没变化** | ❌ **证伪**：不是 PTE 被抢，可能是物理内存被写（GPU 的缓冲正好落在 `0x800000..0x1A00000`） | 停手报告，转"分配器物理地址冲突"方向 |

### 3.3 收尾（无论结果）

```bash
sudo /usr/local/bin/xenative-ctl scan 7000 | tee ~/xegfx-log/A-18b/scan-after-remap.txt
sudo /usr/local/bin/xenative-ctl status > ~/xegfx-log/A-18b/regs-after.txt
sudo reboot      # 不要停在花屏状态
```
> `map` 会把分配器刚写进去的 PTE 覆盖掉，这会让加速器自己的缓冲指向帧缓冲的物理页 ——
> 对 GPU 是脏的，但对"判定实验"无害，**重启即恢复**。

## 5. S2：只有 S1 证实才做（改源码 + 重编）

**不要在本轮直接动手。** 先回报告，由主 agent 确认后再发 S2 的详细提示词。这里只留方向：

`xg_kext.cpp:501-508` 的修法是把"一次 insert 整个范围"改成"**拆成两段 insert**"：

```c
uint64_t end = (uint64_t)gBootSurf + xg_boot_fb_size;
#define GUC_GGTT_TOP 0xFEE00000u
if (end <= GUC_GGTT_TOP) {
    err = xg_i915_reserve_bootfb(gBootSurf, xg_boot_fb_size);      // 原路径
} else {
    uint64_t lo = GUC_GGTT_TOP - gBootSurf;                        // 顶端以下那一段
    err = xg_i915_reserve_bootfb(gBootSurf, lo);                   // 先保留下半段
    /* 上半段落在 GuC 自己的保留区里：GuC 保留区本就"keeps it free"，
       不必再 insert，也不能 insert（必然 ENOSPC） */
}
```
配套注意：
1. 重编要按 `build/nvgfx/build_xegfx.sh`（`~/src/xe-src` + `PYTHONPATH=~/src/kcabi` + `SDKROOT=MacOSX26.5.sdk`，
   且 `gpu/xegfx/out` 必须先存在）。
2. 当前 6 处二进制补丁（3×`pci_dev_put`、1×stage-loop、2×`idr_preload`）是打在**二进制**上的，
   重编后**必须重新应用**（最好改成源码级修改，否则又要重新定位偏移）。
3. S2 属"一次开机一个变量"里的**大变量**：core 重编 + 补丁重打，必须单独一轮。
