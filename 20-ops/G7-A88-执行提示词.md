# Gate 7 · A-88 执行提示词：先测出"工作量 → 帧时间"的量化曲线，再按曲线砍（目标 60fps）

> 局势：A-87 把类锁 4.08ms 搬干净（0.01ms），**帧一步没动**（25.3 → 25.0）。
> 省下的时间原样转到 `AccessComplete`（0.88 → 3.01）。而且 `defer=0` 让 busy 从 11.3 降到 9.0，
> 帧反而**更慢**（32.17）。
>
> **⇒ 主线程工作量已经不是限速项。剩下的唯一出路是先搞清楚"帧时间到底怎么被量化"。**
> 我们的面板只有一个模式（`IOFBModes` 只有 ID 100 = 3120×2080@120，`DM` 已核对），
> 所以"降刷新率换整档"这条路**不存在**。
>
> 本关三件事，按序：
> ① **量化曲线**（诊断，必须做）：人为在工作里插 X µs，扫 X，看帧时间怎么跳；
> ② **提前信号 E2**（唯一"拆拍"的机制）：A-84 当时算 20.7ms 跨不过，但那是把 latch 减掉算的；
>    若 E2 能**去掉一整个"拍"**（而不只是减 4.5ms），15.4ms 的工作量就够 2 拍 = 60fps；
> ③ 按 ① 的曲线决定还要砍多少 busy（描述符池 1.1ms / malloc / objc）。
>
> 必读：`G7-A87报告.md`（§4 新归因）、`G7-A84报告.md` §3（E2 判据与实测）、
> `G7-A86报告.md` §6（三个测量坑）。

## 2. P1 · 量化曲线（诊断，决定后面砍多少）

在插件提交路径里加一个**可调自旋**（开关 `/private/tmp/nvmtl-spin` 里写微秒数，默认 0）：

```objc
// nvmtlSubmitWithEvents 或 ahead pass 的出锁段里
static void nvmtl_spin_us(int us) { if (us<=0) return;
  uint64_t t0=mach_absolute_time(); uint64_t ns=us*1000ULL;
  while ((mach_absolute_time()-t0)*NSEC_PER_TICK < ns) { __asm__ __volatile__(""); } }
```

**扫描**：X = 0 / 1000 / 2000 / 3000 / 5000 / 8000 µs（每次 2 轮 × 25s，无人值守），
记录 p50 / p90 / idle / `arm->latch`。

**产出**：一张 X → 帧时间的阶梯表。它会告诉我们两件事：
1. **台阶在哪里**（16.67？25.0？33.3？）——即当前 25ms 到底比"2 拍"多出多少余量；
2. **再加 X µs 会不会立刻跳一拍**——如果加 1ms 就跳 33.3，说明我们**离下一个台阶只有 <1ms**，
   那么砍 busy 1–3ms 就能**反向掉档**（25 → 16.67）。

**门 P1**：阶梯表完成，明确写出「当前离 2 拍的边界还有 ___ ms」和「要掉到 16.67 需要减 ___ ms」。

## 3. P2 · 提前信号 E2（唯一能"拆拍"的机制）

### 3.1 为什么值得再做一次

A-84 §3.4 的算式是「25.20 − 4.53（latch）≈ 20.7 > 16.68 ⇒ 无用」——
**那是"把 latch 减掉"的算法**。但 E2 的真实作用是**换一拍的相位**：
写完 `PLANE_SURF` 就通知 WS，WS 就能在**当前这一拍内**开始下一帧，而不是等 latch 完成后的下一拍。
如果它真能去掉一整拍（8.33ms），15.4ms 的工作量就落在 2 拍里 = **60fps**。
**这两件事不是一回事，A-84 只算了前者。**

### 3.2 实现（0024 的 E2，简化判据 + 开关）

```objc
// accel 侧（nvrm-accel.cpp）
// write PLANE_SURF 之后立刻 signalTransactionInterrupt()，不等 arm->latch
if (gIopXeEarly) signalTransactionInterrupt();
// 计数：iop_xe_early_flips（早通知次数）
```

- 开关 `debug.xegfxaccel_iop_xe_early`（默认 0）；
- **判据放宽**：0024 要求"连续 32 帧第三面"（我们实测永不满足），本关**先不设判据**，
  直接受开关控制——因为这是我们自己验证，不是产品默认；
- **撕裂观测**：开关打开后请使用者目视拖动（重点：窗口边缘、光标残影），并截屏对比。

### 3.3 门 P2

| 判据 | 期望 |
| --- | --- |
| 帧时间 | **≤16.9ms（≥59fps）** —— 这是本关唯一的目标 |
| 画面 | 无撕裂/无残影（若有，由使用者定档：收益换瑕疵是否接受） |
| 稳定性 | 3 轮 + 30 分钟无 panic、无 WS 看门狗 |

**若 E2 只降到 20ms 左右**（说明只减了 latch 没换相位）→ 记录数字，进 P3。

## 4. P3 · 按 P1 曲线砍 busy（若 P2 没到 60）

按 P1 给出的"还需减 X ms"决定砍哪些，候选按性价比排序：

| 项 | 量级 | 风险 |
| --- | --- | --- |
| 描述符池复用（`nvmtl_snapshot_set_md` 每次 bind 新建 set） | 1.1ms busy | 低（只动 busy，不碰锁） |
| `malloc`/`objc` 碎片（A-86 §4.1 的剩余项） | ~1ms | 中 |
| CA 绘制本身 | 不可控 | — |

**门 P3**：p50 ≤16.9ms 且画面正常。
