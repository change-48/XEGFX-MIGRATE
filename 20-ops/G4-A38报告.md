## 6. 判决点 2（§6）与那个 panic：现场是怎么没的

时间线（全部有日志出处）：

```

          "WindowServer last exited with reason namespace: COREANIMATION, code 7"
```

WS 的退出原因（`ws-ca-crash.ips`）：

```
exception  : EXC_CRASH / SIGABRT
termination: namespace COREANIMATION, code 7
details    : function=fixed_frag_lph_cph spec=Xh
             native emitter: float32 bit literal f0x7fc00000 used as non-float type Half
```

**归因（重要，不要误判成本关引入）**：同一个 `COREANIMATION code 7 / fixed_frag_lph_cph / f0x7fc00000 as Half`
签名在本机**早就存在**——`10-30 18:34:01` 与 `10-30 20:40:12` 各有一份 WS `.ips`，那时
`AGDC_FB_CLASS` 还是旧值、AGDC 根本起不来。所以这是 **CA 走 Metal 渲染器时的着色器发射器缺陷**，
不是 A-38 造的；A-38 做的是**让它变得可达**：AGDC 一起来 → IOP 配上 pipe → CA 不再退回 `CompositorSW`
→ 一碰 Metal 就 abort。换句话说，`CA::MTL` 那条"期望 > 0"**很可能已经成立**，但成立的表现是 CA 崩掉，
而不是我们采到栈。

**旁证**：`surfaceCount 0 → 308`。A-37 里加速器只当"拷贝目标"，一个 surface 都不接；本关 308 个，
说明登录窗口/CA 确实开始在加速器上分配 surface 了。

## 9. 给下一关（A-39）的输入

1. **AGDC 这条链到此为止算通了**：`state=1`、`fbmap n=1`、IOP 双句柄、pipe 创建零失败、
   `surfaceCount 308`。以后不要再把它当"AGDC 起不来"的问题。
2. **新阻塞点换成 CA 的 Metal 着色器发射器**：
   `COREANIMATION code 7 / function=fixed_frag_lph_cph spec=Xh / float32 bit literal f0x7fc00000 used as non-float type Half`，
   `SIGABRT` → 120 s 无 checkin → watchdog panic。该签名 10-30 已有两份，**是本机既有缺陷**。
   要查的方向：`NVMTLDriver` 报给 CA 的 feature set（`spec=Xh` 即 half 精度变体）与
   `MTLDevice` 能力集，以及那个 `f0x7fc00000`（NaN）字面量被当 half 用的编译路径。
3. **采样顺序必须改**：`kickstart WS` 会连带掉会话，正确顺序是
   "load core → accel → accelfb=**3** → **kickstart WS（此时在登录窗口，掉了不心疼）→ 等登录 → 采样**"。
   本关正是按这个顺序拿到双句柄的，只是登录之后 CA 先崩了。
4. **`debug.xegfxaccelfb` 语义记牢**：读回恒 `1`（读的是 `gNvAccelArmed`），
   要让 `gNvScanout=1` **必须写 `3`**。提示词里"写 3 折成 1、别再试 3"的说法作废。
