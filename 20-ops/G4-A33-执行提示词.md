# Gate 4 · A-33 执行提示词：给加速器补上 `IOCFPlugInTypes`（plist 一处，零重编）

> 目标：让 IOPresentment 能创建 `IOAccelDisplayPipe`，从而让 CoreAnimation 走硬件合成路径，
> 消掉 `transient surface not found` → SIGABRT 的 10 秒循环。
>
> **本关不重编、不改源码。** 只改 `XeGfxAccel.kext/Contents/Info.plist` 一处 + 重签 + 重建 KC + 一次重启。

---

## 0. 为什么是这一处（证据链已闭合，不是猜）

### 0.1 A-32 的日志顺序（`20-ops/A-32/stream-ws.log`，16 次，每个 WS 实例一次）

```
21:33:30.721  (IOKit) io_service_t has no IOCFPlugInTypes for <private>
              onePlugin invalid for pluginType <private>
              no factories for plugin for <private>, kr = 0x0, factories = 0x0, factoryCount = 0
21:33:30.723  (XeGfxAccel) NMXAccel: newUserClient(type 4 / 0x4) -> family returned 0x0, client IOAccelDisplayPipeUserClient2
21:33:30.723  (IOPresentment) Error: Pipe creation failed
21:33:30.723  (IOPresentment) Error: Unable to create IOAccelDisplayPipe
21:33:30.723  (IOPresentment) Error: Interface creation error: 0x2002.
```

读法：
- **内核侧 user client 建成了**（`type 4` → `IOAccelDisplayPipeUserClient2`，family 返回 `0x0`）
- 但**用户态的 CFPlugIn 工厂没有**（`has no IOCFPlugInTypes`、`factoryCount = 0`）
- → 接口创建失败 `0x2002` → 没有 pipe → IOP 关掉 `useIOP` → CA 退回 legacy surface + `CompositorSW`
- → `(QuartzCore) context(N) transient surface … not found` → **SIGABRT**（A-32：每次 14 ms 后自杀）

旁证（我们查的）：
- `newDisplayPipe()` 在**二进制里有实现**（`strings` 命中 2 处），但日志里**一次都没打印** → 家族压根没走到那一步
- `IOAccelDisplayPipeUserClient2` 已创建 → 卡点在"接口/工厂"这一层，不在内核对象层

### 0.2 缺的东西可以逐字对照

```
AppleIntelICLGraphics.kext/Contents/Info.plist：
    IOCFPlugInTypes => { "ACCF0000-0000-0000-0000-000a2789904e" => "IOAccelerator2D.plugin" }
AppleIntelKBLGraphics.kext/Contents/Info.plist：
    IOCFPlugInTypes => { "ACCF0000-0000-0000-0000-000a2789904e" => "IOAccelerator2D.plugin" }

XeGfxAccel.kext/Contents/Info.plist：
    grep -c IOCFPlugInTypes  →  0        ← 我们一个都没有
```

而插件本体是**系统自带**的，不需要我们从源码编：

```
/System/Library/Extensions/IOAccelerator2D.plugin/Contents/MacOS/IOAccelerator2D   ← 存在
```

> 这条也解释了为什么 `~/src/aw/patches/` 里 22 个补丁**没有任何一个**提到 `IOCFPlugInTypes`：
> 上游作者的机器上可能从未走到 IOP 这条合成路径，这个键是 IOP 专用的一环。

## 1. 前置状态与预算

```
当前（21:38 实测）：phase=%00 trial=%00 expose=%00 fail=%01 starts=%01
                    core/accel/display 未加载；WS 204 存活；3120×2080；无新 panic
XeGfxAccel 签名：adhoc（改 plist 后必须重签 adhoc）
预算：starts 1/3，本关只进 1 次 S3。
```

**硬约束（A-32 实测，必须遵守）：**

| 事实 | 含义 |
| --- | --- |
| `XeGfxDisplayNub` **只在 bootarm 路径发布** | 手工 `debug.xegfx_stage=7` 永远进不了 S3（nub=0） |
| `bootarm` + 手工 `stage` = **stages 双跑** → `stage4 -19` | **只准用 bootarm，不准再手工写 `debug.xegfx_stage`** |
| 自启脚本 `/var/db/xegfx-boot/disabled` 存在 | bootarm 不会自动消费，**必须手工 `kmutil load core`** |

## 2. 改 plist（唯一改动）

```bash
K=/Library/Extensions/XeGfxAccel.kext
L=~/xegfx-log/A-33; mkdir -p $L

# 2.1 备份（plist 与 kext 各一份）
sudo cp -p $K/Contents/Info.plist $L/Info.plist.before
sudo cp -R $K $L/XeGfxAccel.kext.before
cp -p /Library/KernelCollections/AuxiliaryKernelExtensions.kc $L/aux-before-a33.kc

# 2.2 加 IOCFPlugInTypes（用 PlistBuddy；这里只有字符串，不涉及 data 类型）
sudo /usr/libexec/PlistBuddy -c "Add :IOCFPlugInTypes dict" $K/Contents/Info.plist 2>/dev/null || true
sudo /usr/libexec/PlistBuddy \
  -c "Add :IOCFPlugInTypes:ACCF0000-0000-0000-0000-000a2789904e string IOAccelerator2D.plugin" \
  $K/Contents/Info.plist

# 2.3 立即核对（键名必须逐字一致，含大小写与连字符）
plutil -p $K/Contents/Info.plist | grep -A3 IOCFPlugInTypes
```

**期望输出：**

```
  "IOCFPlugInTypes" => {
    "ACCF0000-0000-0000-0000-000a2789904e" => "IOAccelerator2D.plugin"
  }
```

> 若 `Add` 报 "Entry Already Exists"，说明已有同名键 —— 先 `Print` 出来贴到报告里，**不要**用 `Delete` 覆盖。
> 若键名写错（例如少一个 0），`plutil -p` 立刻能看出来；**这一步不通过就不要往下走**。

## 3. 重签（改 plist 必然破坏封印）

```bash
sudo codesign -f -s - /Library/Extensions/XeGfxAccel.kext
codesign -dv /Library/Extensions/XeGfxAccel.kext 2>&1 | grep -E "Signature|Identifier"
codesign --verify --verbose=2 /Library/Extensions/XeGfxAccel.kext 2>&1 | tail -3
```

**门 1：`Signature=adhoc`，且 `--verify` 不报错。**
（`--verify` 若报 `a sealed resource is missing or invalid`，说明还有残留的 `_CodeSignature`：
`sudo rm -rf $K/Contents/_CodeSignature && sudo codesign -f -s - $K` 再验一次。）

## 4. 重建 AuxKC（`-B/-S` 必须绝对路径）

```bash
sudo /usr/bin/kmutil create -n aux --volume-root / --allow-missing-kdk \
     -B /System/Library/KernelCollections/BootKernelExtensions.kc \
     -S /System/Library/KernelCollections/SystemKernelExtensions.kc \
     --repository /Library/Extensions -A /tmp/aux-a33.kc -z 2>&1 | tail -5
sudo cp -f /tmp/aux-a33.kc /Library/KernelCollections/AuxiliaryKernelExtensions.kc

# 逐条核 id（"rebuild done" 不可信）
sudo /usr/bin/kmutil inspect -A /Library/KernelCollections/AuxiliaryKernelExtensions.kc -M --no-header \
  | awk 'NF{print $1}' | sort > $L/ids.txt
for id in org.watchthelight.IGPUConsoleRange org.watchthelight.XeGfx \
          org.watchthelight.XeGfxAccel org.watchthelight.XeGfxDisplay \
          org.watchthelight.XeGfxIntelFB org.watchthelight.XeGfxAGDC; do
  grep -qx "$id" $L/ids.txt && echo "OK   $id" || echo "MISS $id"
done
```

**门 2：六个 id 全 OK，`IGPUConsoleRange` 必须在。** 缺任何一个 → 停手，装回 `$L/aux-before-a33.kc`，**不要重启**。

## 5. 重启，然后按 bootarm 路径进 S3

```bash
sudo reboot
```

回来后（等 SSH 可用）：

```bash
# 5.1 门（bootarm 是唯一入口）
sudo nvram xegfx-disp-bootarm=%01
sudo nvram xegfx-disp-phase=%02 xegfx-disp-trial=%01 xegfx-disp-expose=%01 xegfx-disp-fail=%00
sudo touch /var/db/xegfx/armed
sudo nvram -p | grep xegfx

# 5.2 【关键】手工 load core —— bootarm 会自己排 stages 1..7
#     绝对不要写 debug.xegfx_stage，否则双跑 → stage4 -19
sudo log stream --predicate 'eventMessage CONTAINS "XEGFX" OR eventMessage CONTAINS "M3d" OR eventMessage CONTAINS "AGDC" OR eventMessage CONTAINS "IOPresentment" OR eventMessage CONTAINS "NMXAccel" OR process == "WindowServer"' > $L/stream.log 2>&1 &
sleep 2
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfx
sleep 30

sudo sysctl -b debug.xegfx_results | od -A n -t d4            # 期望 0 1 1 1 1 1 1 1
sudo log show --last 2m --predicate 'eventMessage CONTAINS "M4a core ready"' 2>/dev/null | tail -2
sudo ioreg -l -w0 2>/dev/null | grep -c XeGfxDisplayNub        # 期望 ≥1
```

**门 3：`results` 全 1 且 `M4a core ready` 且 nub ≥1。** 不过就停手（此时屏幕应仍正常）。

```bash
# 5.3 accel → display
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfxAccel; echo "accel rc=$?"
sleep 3
sudo ioreg -l -w0 2>/dev/null | grep -c "class NMXAccel"

sudo /usr/bin/kmutil load -b org.watchthelight.XeGfxDisplay; echo "display rc=$?"
for i in $(seq 1 60); do
  ioreg -l -w0 -c XeGfxFramebuffer 2>/dev/null | grep -q '"XeGfxFbRegistered" = Yes' && { echo "FB @${i}s"; break; }
  sleep 1
done
for i in $(seq 1 30); do
  n=$(sudo ioreg -l -w0 2>/dev/null | grep -c '"XeGfxAccelPresent" = Yes'); [ "$n" -ge 1 ] && { echo "AccelPresent @${i}s"; break; }; sleep 1
done
for i in $(seq 1 10); do
  sudo sysctl -w debug.xegfx_agdc=1 >/dev/null 2>&1; sleep 1
  s=$(sudo sysctl -n debug.xegfx_agdc 2>/dev/null); echo "agdc $i -> $s"; [ "$s" = "1" ] && break
done
sudo sysctl debug.xegfx_agdc_fbmap
```

**门 4：FB registered + AccelPresent + agdc=1。**

## 6. 本关的判决点：`IOAccelDisplayPipe` 能不能建起来

```bash
sudo launchctl kickstart -k system/com.apple.WindowServer
sleep 20

echo "=== A) 插件工厂错误还在不在（要在 = 修好）==="
grep -c "has no IOCFPlugInTypes" $L/stream.log
grep -c "Unable to create IOAccelDisplayPipe" $L/stream.log

echo "=== B) 好消息的两个标志（出现 = 修好）==="
grep -E "newDisplayPipe ->|initFramebufferResource" $L/stream.log | tail -5

echo "=== C) IOP 设备表（pipe 相关）==="
grep -E "IOPresentment|agdc 0x|accel 0x|pipe" $L/stream.log | tail -12

echo "=== D) 断言前那句 ==="
grep -c "transient surface .* not found" $L/stream.log

echo "=== E) WS ==="
ps -o etime=,pid= -p "$(pgrep -x WindowServer)"
sudo log show --last 3m --predicate 'process == "WindowServer"' 2>/dev/null | grep -c "SIGABRT"
```

判读：

| 现象 | 结论 | 下一步 |
| --- | --- | --- |
| `has no IOCFPlugInTypes` = **0**，且出现 `newDisplayPipe ->` / `initFramebufferResource` | **工厂找到了，pipe 建起来了** | 进 §7 判据 |
| `has no IOCFPlugInTypes` = 0，但**仍** `Unable to create IOAccelDisplayPipe` | 工厂找到了，但插件拒绝了我们的服务 | 停手报 `0x2002` 的新值 + `IOAccelerator2D` 相关日志 |
| 两个都还是 1 | plist 没生效（KC 没吸收 / 键名错） | 停手，贴 `kmutil inspect` 与 `plutil -p` |

## 9. 铁律（本轮有效）

1. `kmutil` 在 `/usr/bin`；`kmutil create` 的 `-B/-S` **必须绝对路径**。
2. 新入 KC 的 kext 变更**必须重启**才生效（`Code=28`）。
3. **S3 只走 bootarm**：`xegfx-disp-bootarm=%01` + `phase=%02`，然后 `kmutil load core`；
   **绝不**同时写 `debug.xegfx_stage`（双跑 → `stage4 -19`，A-30 已证）。
4. `armed` 之后 120 s 内不重启。
5. 改 kext 的 Info.plist 后**必须重签**（adhoc），否则 KC 会拒。
6. `sample`/日志必须在进程存活时抓；`ReportCrash` 会因频率限制丢弃 `.ips`（`Log limit exceeded`）。
7. 一次一个变量：本关只加 `IOCFPlugInTypes`。**不要**顺手加 `IOGLBundleName` / `IODVDBundleName` /
   `IOGVABGRAEnc`（那是 Metal/GL 驱动声明，与本关无关）。
