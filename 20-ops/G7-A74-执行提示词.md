# Gate 7 · A-74 执行提示词：零拷贝翻转三件套（pitch 闸门 + per-frame marks + WS no-wait）

> 目标：**把每帧 24.8ms 的阻塞拆掉**（accel 事务 9.4ms + fence 等待 15.4ms，A-73 实测）。
> 手段是 ArrowWhatever 已验证的三件套，**按三个相位落地，每相有门，门不过不进下一相**：
> ① accel 零拷贝翻转（修 pitch 闸门 + 补齐 arm→latch 完整链）；② per-frame marks（替换"等整个 GT 空闲"）；
> ③ WS no-wait（commit 只等 scheduled）。
> 前人成果：ArrowWhatever 同类改动 **15 → 60 fps**（2560×1600@60Hz）。
>
> **本关开始动显示路径，有整机冻结风险（A-49 前科：WS 卡死到断电）。测试时段使用者必须在机器旁。**
> 必读：`20-ops/G7-120fps-研究.md`、`G7-A72报告.md`、`G7-A73报告.md`、
> `20-ops/AI-远程连接说明.md`（规矩②）、`20-ops/AI-远程调试作业说明.md`。

---

## 0. 背景（一分钟版）

- 帧预算（A-73，拖动 55ms/帧 @18fps）：9.4 accel 事务（vblank 4.9 + 拷贝 3.75）+ **15.4 fence 等待**
  （`commitAndWaitUntilSubmitted → waitUntilCompleted`，一帧 3.4 次提交、均值 4.5ms、长尾 17ms）+
  23.5 WS 自身 CPU + 6.4 节奏/杂项。
- 前人（ArrowWhatever，基点恰与我们装机 accel 同一棵 `5a19a73f` 树）的三件套：
  1. **零拷贝翻转**：GGTT flip slot + worker 在 vblank 写 `PLANE_SURF`，WS 不再同步等事务；
  2. **per-frame marks**：插件 commit 时把本帧 surface 标 pending、GPU 完成标 ready，
     **worker 只等本帧自己的标记**（不再等整个 GT 空闲——这正是我们 A-53/A-54 flip 变慢的根因）；
  3. **WS no-wait**：`commitAndWaitUntilSubmitted` 只等 scheduled，排序交给 accel worker。
- 我们的既有地形（这几轮换来的，省你重新踩坑）：
  - **A-46**：EFI 已有 `xegfxaccelboot=1`，bootArm 六步 6/6、defer armed，但 flip 从不运行——
    卡在 `performTransaction` 的 `q.pitch == P` 闸门（3120 宽面板：CA 行距 12544 ≠ 扫描 12480，
    上游 issue #14）。
  - **A-47**：`nvAccelXeFlipArm` 内写 `NV_PLANE_STRIDE_A 0x70188` 的代码成活过（画面正常）。
  - **A-49**：只放宽闸门（不写 stride）→ 帧被 defer 分支"认领"后既无 flip 也无拷贝 → WS 冻结两次。
    **教训：认领与上屏之间必须闭环，否则就是冻屏。**
  - **A-54b**：单独开 no-wait 更慢（11 vs 14）——没有内核侧排序配对时 no-wait 是自杀。
  - A-72/A-73 已留好仪器：`fps-probe.sh`、`debug.xegfxaccel_iop_tl`、`/private/tmp/nvmtl-ws-prof.log`。

## 3. Phase 1 · accel 零拷贝翻转（pitch 闸门 + arm→latch 闭环）

### 3.1 改什么（都在 accel，插件不动）

对照 0009 + 0024，在现有 K9b/bootArm/`nvAccelXeFlipArm` 机制上补齐：

1. **pitch 闸门放宽**（issue #14 方案 1）：`q.pitch == P` → 允许
   `P % 64 == 0 && P / 64 <= 0x7FF`（3120 宽时 P=12544 合法）；
2. **arm 时同步写平面**：写 `PLANE_SURF` 的同时写 `PLANE_STRIDE = P/64`（A-47 已证明这段代码地形可活），
   `!latched` 路径两者一起还原；
3. **认领闭环**（A-49 的死因）：defer 分支认领的帧**必须**要么 flip 上屏、要么失败回落拷贝路径——
   照 0024 的 worker 写法：取出 → 等待（Phase 1 先用现有 GT-空闲/快照后备）→ 写 SURF → latch → 通知；
   **绝不允许"认领后既不 flip 也不拷贝"的中间态**；
4. **超时照样 arm + `idle_forced` 计数**（0024 的逃生口）：GPU 忙超过 `iop_xe_idle_ms`（默认 120ms）
   也照样上屏，defer 不因连续失败被永久关闭；
5. 新计数器（照 0026/0027 的名字，方便对照）：`iop_xe_flips`（已有）、`markonly_flips`、
   `defer_max_depth`、`idle_forced`、`mark_timeouts`、`flip_latch_last_us`。

### 3.2 门 1（全过才进 Phase 2）

| # | 检查 | 期望 |
| --- | --- |
| 1 | 安全模式回归 | 开关全关时行为= A-73 基线（拷贝路径、事务 p50≈9.4ms、fps 18±2） |
| 2 | flip 运行 | 开 flip 后 `iop_xe_flips` 持续增长、`iop_fail=0`、无 `defer 永久关闭` |
| 3 | 画面 | 用户目视：拖动无花屏、无"上一帧残留"（A-68 的双缓冲教训：换面时机错=更糟的撕裂） |
| 4 | 事务形态 | `iop_tl` 里 WS 侧事务耗时应跌到 **<1ms**（认领即返回，拷贝段消失） |
| 5 | 帧率 | 拖动中位 **≥ 20**（A-53 同期是 23 峰 60；若 <15 视为未达标，先查 worker 等待） |
| 6 | 稳定性 | 连续拖动 3×25s 无冻结、无新 panic |

**Phase 1 预期**：fence 等待暂不会降（worker 还在等 GT 空闲，可能拖 GPU 后腿），
重点是"事务不再阻塞 WS"+画面正确。帧率涨多少都不意外，跌破 15 就是失败。

## 4. Phase 2 · per-frame marks（插件 + accel 配对）

### 4.1 改什么

对照 0026（marks 部分）：

1. **插件**：commit 时把本帧的合成 surface 标记 pending（落进 accel 可读的共享结构/哨兵，
   照 0026 的机制，DRM client selector 1 那套的对应物）；GPU 完成本帧工作后标 ready；
2. **accel worker**：等待条件从"GT 空闲/快照"换成"**本帧 surface 的 ready 标记**"，
   GT 空闲轮询降级为后备；
3. 超时兜底沿用 Phase 1 的 `idle_forced`。

### 4.2 门 2

| # | 检查 | 期望 |
| --- | --- | --- |
| 1 | marks 生效 | `markonly_flips` 占比高（>80%），`mark_timeouts` 每分钟 < 10 |
| 2 | worker 延迟 | 取出→写 SURF 的 p50 **≤ 6ms**（ArrowWhatever 同段 5.4ms @2MP；我们 6.49MP 放宽到 6ms） |
| 3 | 帧率 | 拖动中位 **≥ 25** |
| 4 | 稳定性 | 同门 1 第 6 条 |

## 5. Phase 3 · WS no-wait（最后开，最危险）

### 5.1 改什么

对照 0026 no-wait 部分：`commitAndWaitUntilSubmitted` 只等 scheduled
（哨兵文件 `/private/tmp/nvmtl-ws-nowait` 存在时启用，照 A-54b 的开关形态——**默认关**）。
可选加分项：WS 的 Vulkan 队列 `VK_KHR_global_priority` = HIGH（若本 ANV 构建支持；
不支持就记"不支持"，不许自己造）。

### 5.2 门 3（本关成功线）

| # | 检查 | 期望 |
| --- | --- | --- |
| 1 | fence 等待坍缩 | `ws-prof.log` 的每帧 `wait_ms` 从 15.4ms 降到 **≤ 5ms**（只剩 scheduled 等待） |
| 2 | 帧率 | 拖动中位 **≥ 30**（研究文档的按比例预期下限） |
| 3 | 画面 | 无撕裂恶化、无残帧（有则记 A/B 对比，判"收益换瑕疵"是否可接受——**由使用者拍板**） |
| 4 | 稳定性 | 连续 3 轮 + 30 分钟日常使用无冻结无 panic |
