## 2. 与 1031 计划的偏差（主 agent 已定，按本文执行）

历史记录（`D:/_XEGFX-archive-20261030/07-stage5-6-7-通过-2026-10-30.md`）已经证明了三件事，
所以 Gate 1 不能照计划原文那样一次做完，必须拆成两个变量：

**偏差 1：拆成 A-01（原版）+ A-02（补丁）**
计划写「先按原版测；只有复现才打补丁」。问题是这个"复现"10-30 已经做过并且有反汇编级定位 ——
重测一遍仍有价值（确认当前环境一致），但它只能证明"原版到不了 5"，不能当 Gate 1 通过。

**偏差 2：原版 stage 5 不是 `-19`，而是"根本不跑"**
源码里 stage 循环是 `if (rc < 0) break;`，而 stage 4 固定返回 `-28`（显示归属冲突，结构性，非故障）。
所以原版必然停在 stage 4，**5/6/7 连执行都不会执行**。
A-01 的期望值是 `results = 0 1 1 1 -28 0 0 0`，不是 `-19`。
（历史里那个 `-19` 是更早的 0.0.44/中间版本，别拿它当期望值对。）

**偏差 3：补丁是 4 处，不是 6 处**
归档脚本 `D:/_XEGFX-archive-20261030/patch-xegfx.py` 只有 4 个偏移：
```
0x24391e  0f88ae040000 -> 6×90   stage 循环 break -> 继续跑
0x14167a  e8c19af2ff   -> 5×90   xg_i915_state  的 pci_dev_put
0x141ba6  e89595f2ff   -> 5×90   xg_i915_exec   的 pci_dev_put
0x141ff6  e84591f2ff   -> 5×90   xg_i915_store  的 pci_dev_put
```
计划里说的另外 2 处 `idr_preload`（`0x6edf0` call `xg_sched_pin` → NOP5、`0x6ef36` jmp → `c3`+4×NOP）
是**加速器走 DRM 客户端时**才会触发 panic 的补丁，属于 Gate 4 的事。
**本关只打这 4 处，不许为了"凑够 6 处"自己找偏移、自己发明补丁。**

**另外：stage 7 不属于本关。** `results[7]=1`（nmxgpu-claimed）需要 `XeGfxAccel` 在场，
那是 Gate 4 装加速器之后才可能。本关到 stage 6 为止。

## 3. 铁律

- **A-01 期间 XeGfx 二进制必须一个字节都不改**（改了就失去"原版可复现"这个基线）。
- 一次开机只改一个变量：A-01 装原版 → 重启 → 测；A-02 打补丁 → 重启 → 测。**不许合并。**
- 重建 AuxKC 只用：`sudo kmutil install --volume-root / --allow-missing-kdk -v`
  （无 KDK；不许 `--update-all`，不许 `kmutil create`）。
- 拷 kext 后**必须** `chown root:wheel` + `chmod -R 755`。
  `cp -a` 会把属主带成 `change48:staff`，`kmutil` 会**静默跳过**该 kext —— 历史踩过。
- 不许碰 `IGPUConsoleRange` / `HighPoint*`；不许改 boot-args；不许改 U 盘 `D:\EFI`。
- 不许 `softwareupdate`；不许动显示寄存器（那是 Gate 3）。
- 每次重启前 `touch /var/db/xegfx/armed`（护栏据此判断上一轮是否活着）。
- 遇到计划外现象：停手、留证、报告。**不要自己发挥。**

## 4. A-01：装原版（唯一变量 = 装入官方 core）

### 4.1 传包并校验

Windows 侧：
```bash
cd /d/XEGFX-MIGRATE/00-official/unpacked
sha256sum XeGfx.kext/Contents/MacOS/XeGfx          # 必须 = 3fa0efb8…18e4
tar czf /tmp/XeGfx.kext.tgz XeGfx.kext
scp -i ~/.ssh/id_xegfx_remote /tmp/XeGfx.kext.tgz change48@192.168.1.102:/tmp/
```
目标机：
```bash
rm -rf /tmp/xegfx-g1 && mkdir -p /tmp/xegfx-g1
tar xzf /tmp/XeGfx.kext.tgz -C /tmp/xegfx-g1
shasum -a 256 /tmp/xegfx-g1/XeGfx.kext/Contents/MacOS/XeGfx   # 必须与上面同一个值
```
**两次 sha256 不一致就停，别往下走。**

### 4.2 落盘 + 权限规整

```bash
sudo rm -rf /Library/Extensions/XeGfx.kext          # 只删这一个，别用通配
sudo cp -R /tmp/xegfx-g1/XeGfx.kext /Library/Extensions/XeGfx.kext
sudo find /Library/Extensions/XeGfx.kext -name '._*' -delete
sudo xattr -cr /Library/Extensions/XeGfx.kext
sudo chown -R root:wheel /Library/Extensions/XeGfx.kext
sudo chmod -R 755 /Library/Extensions/XeGfx.kext
# 落地后必须再校验一次，确认搬运动作没改字节
shasum -a 256 /Library/Extensions/XeGfx.kext/Contents/MacOS/XeGfx
sudo /usr/libexec/PlistBuddy -c "Print :CFBundleIdentifier" /Library/Extensions/XeGfx.kext/Contents/Info.plist
sudo /usr/libexec/PlistBuddy -c "Print :CFBundleVersion"    /Library/Extensions/XeGfx.kext/Contents/Info.plist
```
期望 bundle id = `org.watchthelight.XeGfx`，版本号含 `0.0.46`。

### 4.3 重建 AuxKC 并**先校验再重启**

```bash
sudo kmutil install --volume-root / --allow-missing-kdk -v
sudo kmutil inspect 2>/dev/null | grep -A20 "auxiliary kext"
```
**必须同时看到四个 id**：`org.watchthelight.XeGfx`、`org.watchthelight.IGPUConsoleRange`、
`com.highpoint-tech.kext.HighPointRR`、`com.highpoint-tech.kext.HighPointIOP`。
缺任何一个 → **不许重启**，停手报告。

### 4.4 重启并加载

```bash
touch /var/db/xegfx/armed
sudo reboot
```
≤180 s 内 SSH 回来（每 10 s 探一次）。回来之后：
```bash
sudo kmutil load -b org.watchthelight.XeGfx -v
sudo kmutil showloaded | grep -i xegfx
sudo sysctl -w debug.xegfx_wdog=60
sudo sysctl -a | grep -c debug.xegfx
```
`showloaded` 要有 `0.0.46` 那一行；`sysctl` 计数期望 ≥ 8。

### 4.5 推 stage 1 → 4（一步一步，别一步到底）

```bash
sudo sysctl -w debug.xegfx_stage=1 ; sleep 8
sudo sysctl -b debug.xegfx_results | od -A n -t d4
sudo sysctl -w debug.xegfx_stage=4 ; sleep 15
sudo sysctl -b debug.xegfx_results | od -A n -t d4
sudo sysctl -b debug.xegfx_log 2>/dev/null | tr -d '\0' | tail -60
```

**A-01 期望值**（这就是本关要验证的核心预测）：

| 结果 | 含义 |
| --- | --- |
| `0 1 1 1 -28 0 0 0` | **符合预期**：stage 1–3 通过，stage 4 = -28（显示归属冲突，已知/接受），循环在 -28 处 break，5–7 未运行 |
| `0 1 1 1 -28 -19 …` | 也接受，说明 break 之后还有别的路径跑到了 5，记下来即可 |
| stage 4 不是 -28（比如是 1） | **变量变了**，停手：说明显示归属已不冲突，本文的假设要重估 |
| stage 1/2/3 有任何一个不是 1 | 停手，留证，报告（GuC 固件/固件路径问题） |

### 4.6 存证

`~/xegfx-log/A-01/` 下写：`results`（od 那行原文）、`probe`（`ioreg -l -w0 -r -c XeGfxResident | grep -A40 XeGfxProbe`）、
`guc`（`ioreg -l -w0 -r -c XeGfxGt`）、`loaded`（`kmutil showloaded | grep -i xegfx`）、
`dmesg`（`sudo log show --last 10m --predicate 'senderImagePath CONTAINS "XeGfx"' | tail -200`）、
`screen.txt`（`system_profiler SPDisplaysDataType` + `pgrep -x WindowServer`）。

## 5. A-02：打 4 处补丁（唯一变量 = 4 个 NOP）

只有在 A-01 得到 `0 1 1 1 -28 …` 之后才做。**A-01 不通过就别进 A-02。**

```bash
scp -i ~/.ssh/id_xegfx_remote "D:/_XEGFX-archive-20261030/patch-xegfx.py" change48@192.168.1.102:/tmp/
# 1) 先备份原版二进制
mkdir -p ~/xegfx-log/A-02
sudo cp -p /Library/Extensions/XeGfx.kext/Contents/MacOS/XeGfx ~/xegfx-log/A-02/XeGfx.before
# 2) 干跑确认 4 处全部 ok（不写盘）
sudo python3 /tmp/patch-xegfx.py /Library/Extensions/XeGfx.kext/Contents/MacOS/XeGfx
#    期望四行 "ok ..."，没有 MISMATCH；有 MISMATCH 立即停（说明不是同一版二进制）
# 3) 真打
sudo python3 /tmp/patch-xegfx.py /Library/Extensions/XeGfx.kext/Contents/MacOS/XeGfx --apply
# 4) 重新 adhoc 签名（改过字节必须重签，否则 kmutil 拒收）
sudo codesign --force --sign - /Library/Extensions/XeGfx.kext
sudo codesign -v /Library/Extensions/XeGfx.kext && echo SIGN-OK
# 5) 重建 AuxKC + 校验四个 id（同 4.3）
sudo kmutil install --volume-root / --allow-missing-kdk -v
sudo kmutil inspect 2>/dev/null | grep -A20 "auxiliary kext"
# 6) arm + 重启 + 加载 + 推 stage
touch /var/db/xegfx/armed ; sudo reboot
```
回来之后：
```bash
sudo kmutil load -b org.watchthelight.XeGfx -v
sudo sysctl -w debug.xegfx_wdog=60
sudo sysctl -w debug.xegfx_stage=7 ; sleep 25
sudo sysctl -b debug.xegfx_results | od -A n -t d4
```

**A-02 期望值**

| 槽位 | 期望 | 说明 |
| --- | --- | --- |
| s1 s2 s3 | `1 1 1` | 与 A-01 同 |
| s4 | `-28` | 结构性冲突，接受，Gate 3 才处理 |
| **s5** | `1` | render/blit/compute 三个引擎各跑一次上下文请求，`err=0` |
| **s6** | `1` | GPU 写内存、CPU 读回，`ok=3` |
| s7 | `0` 或负数 | **正常**：claim 要 `XeGfxAccel`，本关没装 |

s5/s6 为 1 才算 Gate 1 通过。s7 不是 1 **不算失败**。

存证到 `~/xegfx-log/A-02/`：`results`、`stage5`（`ioreg -l -w0 -r -c XeGfxExec`）、
`stage6`（`ioreg -l -w0 -r -c XeGfxStore`）、`spin`（`sysctl debug.xegfx_spin`）、
`patch.txt`（打补丁的完整输出）、`XeGfx.before` 与新二进制的 sha256 对比。

## 6. 停机条件

| 现象 | 处置 |
| --- | --- |
| sha256 前后不一致 | 停，别装 |
| AuxKC 缺四个 id 之一 | 停，**不重启** |
| `kmutil load` 返回 28（requires reboot） | 正常，重启后重试一次 |
| **加载/推 stage 时机器卡死**（SSH 断、屏幕冻结） | 等 60 s；仍不通 → **断电重启一次**。重启后应恢复 1080p，因为 XeGfx 不自动抢占。**不要立刻重复 load**，先取 panic/日志证据 |
| 重启后起不来（SSH 180 s 不通） | 护栏会在下一次开机 attempts=2 时自动回滚。若回滚后仍不通 → 报告"需要 U 盘 -x 救援"，**别自己改 U 盘** |
| 出现新的 panic 文件 | 停，把 panic 前 200 行和 `~/xegfx-log/<ID>/` 一起交上来 |

**护栏的能力边界（务必理解）**：它只保证"**开机**起不来"能自动回滚。
"加载 kext 之后 live 卡死"不在它覆盖范围内 —— 那种情况重启即可恢复，回滚要手动跑
`sudo /usr/local/bin/xegfx-rollback.sh`。

## 验收锚点（主 agent 独立跑）

1. `shasum -a 256 /Library/Extensions/XeGfx.kext/Contents/MacOS/XeGfx`
   - A-01 阶段必须 = `3fa0efb8…18e4`（原版未改）

3. `sudo sysctl -b debug.xegfx_results | od -A n -t d4` → 第 5、6 项均为 1。
4. `ioreg -l -w0 -r -c XeGfxGt` 里 `guc-fw-status=10`。
5. 无本关期间新增 panic；屏幕仍 1920×1080、WindowServer 在跑。
6. `/var/db/xegfx/armed` 已不存在、`attempts` 为 0（护栏正常收尾）。
