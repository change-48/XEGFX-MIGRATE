# Gate 4 · A-29 执行提示词：让 AGDC 认得出 KMS framebuffer（一行宏）

> 目标：让 `XeGfxAGDC` 在 S3 接管态下真的起来，使 IOPresentment 拿到 AGDC，
> 从而把 WindowServer 从 `CompositorSW` + legacy surface 切到 IOP 呈现路径，
> 消掉 `CA::OGL::Context::push_surface` 断言。
>
> 前置状态：机器处于干净可用态（`phase=0 / trial=0 / fail=1`，只有 `XeGfxIntelFB` 加载，
> 3120×2080 正常，WS 存活）。**本关全程不重启**（除停机条件触发）。

---

## 0. 结论与依据（先说清为什么改这一个字）

### 0.1 A-28 的前提已被证伪（记录，不再回头）

`open() RELEASED (opens=1) -- aperture 0x0/0` 不是"CA 拿到空 aperture"。
`fAperturePhys/fApertureLen` 只在 `getApertureRange()` 内（`XeGfxDisplay.cpp:1125/1145`）赋值，
第一次 `open()` 时**还没有任何人调用过它**，所以打印 0/0 是必然。

→ **不要改 `open()`。** 那条路已作废。

### 0.2 真正的断裂点（源码级，本关要修的）

```
S3 的 framebuffer 类：  XeGfxIntelKMSFramebuffer : XeGfxFramebuffer : IOFramebuffer

kexts/NVRMAGDC/nvrm-agdc.cpp:24
    #define AGDC_FB_CLASS     "IONDRVFramebuffer"

nvdaAgdcTargets():
    IOService *f = IOService::copyMatchingService(serviceMatching(AGDC_FB_CLASS));
    → 匹配不到任何节点 → *fb = nullptr
nvdaAgdcWorkBody():
    if (!pci || !fb) { gAgdcState = -1; FBLOG("AGDC: no PCI device or no framebuffer yet"); return; }
```

`XeGfxFramebuffer` **不是** `IONDRVFramebuffer` 的子类，所以 `AGDC_FB_CLASS` 永远匹配不到 S3 的 framebuffer。

### 0.3 这条链的终点就是那个断言（上游自己的文字）

- `0018` 头部：
  > vendor mask = 0 → `UseIOPresentment()` 静默清掉 useIOP → legacy `CGXDisplayDevice` surface +
  > CompositorSW → 首个 flatten layer 断言在 `CA::OGL::Context::push_surface`。
- `0017` 头部：
  > AGDC stayed down → **IOPresentment could not build its device map** → WindowServer fell back to the legacy surface。

### 0.4 现场硬证据（A-28 的 `cap/stream.log`）

```
gpu 0x3a7c       agdc 0x000000000        ← IOP 自己的诊断行：AGDC handle 为空
(IOPresentment) Error: Unable to get AGDC information.  Return code: 0x10000003
(IOPresentment) Error: Unable to locate service dependencies
(IOPresentment) Error: Unable to acquire map
19:03:03.608 (QuartzCore) [com.apple.coreanimation:OGL] context(2) transient surface 0x... not found
19:03:04     WS 2152 SIGABRT
```

### 0.5 为什么 AGDC 现在根本不存在

`/Library/Extensions` 里**没有** `XeGfxAGDC.kext`；`sysctl debug.xegfx_agdc` → `unknown oid`。
预编产物在 `~/src/NvGfx-build/kexts/XeGfxAGDC/XeGfxAGDC.kext`（0.1.1，10-30 16:03，含 "no framebuffer yet" 重试文案）。

**所以本关两件事：改一个宏（让它认得出新类）+ 把这个 kext 装上并 arm。**

### 0.6 为什么放宽匹配类不会误伤

`nvdaAgdcScan()` 内部有这一句：

```c
if (p != pci) { other++; SCANLOG("framebuffer id %#llx is under another PCI device: not ours to report", rid); continue; }
```

只认**自己那块 IOPCIDevice** 底下的 framebuffer，别的 GPU 会被计进 `other` 并排除。

## 1. 唯一改动（一行宏，不重构）

文件：`~/src/NvGfx-xe-2.6.2/kexts/NVRMAGDC/nvrm-agdc.cpp`

第 **24** 行（`#ifdef NMX_XEGFX` 分支内，紧邻 `#define AGDC_VENDOR "Intel"`）：

```c
#define AGDC_FB_CLASS     "IONDRVFramebuffer"
```

改成：

```c
/* NMX_XEGFX: the KMS adapter (kexts/XeGfxDisplay) publishes XeGfxFramebuffer
 * (XeGfxIntelKMSFramebuffer : XeGfxFramebuffer : IOFramebuffer).  It is NOT an
 * IONDRVFramebuffer subclass, so the historical class never matched it: AGDC
 * could not come up in S3, IOPresentment had no AGDC ("agdc 0x000000000"),
 * useIOP was cleared and WindowServer fell back to the legacy surface, which
 * asserts in CA::OGL::Context::push_surface on the first flattened layer. */
#define AGDC_FB_CLASS     "XeGfxFramebuffer"
```

**不要动第 69 行**（那是 `#else` 的 NVDA 分支，`"NVRMNVDAFramebuffer"`，与本关无关）。
**不要动 `AGDC_VENDOR_ID`（0x8086）**，它是对的。

改完自检：

```bash
grep -n "define AGDC_FB_CLASS\|define AGDC_VENDOR_ID\|define AGDC_VENDOR " \
  ~/src/NvGfx-xe-2.6.2/kexts/NVRMAGDC/nvrm-agdc.cpp
# 期望：24 行 = "XeGfxFramebuffer"，26 行 = 0x8086，69 行仍是 "NVRMNVDAFramebuffer"
```

## 4. 运行时装载 + 按顺序 arm（本关核心，别改顺序）

> `XeGfxAGDCLoader` 的 provider 是 `IOResources`，所以**不需要重启**就能 load。

### 4.1 先证明 AGDC kext 能活

```bash
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfxAGDC
sleep 2
sudo sysctl debug.xegfx_agdc          # 期望读到 0 = loaded, idle
sudo log show --last 2m --predicate 'eventMessage CONTAINS "AGDC"' 2>/dev/null | grep -i "loaded; idle" | tail -2
```

若 `unknown oid`：kext 没起来 → 停手报 `kextstat | grep -i agdc` 与 `log show` 结果。

### 4.2 进 S3（不重启），等 framebuffer 真的发布

```bash
sudo nvram xegfx-disp-phase=%02 xegfx-disp-trial=%01 xegfx-disp-expose=%01 xegfx-disp-fail=%00
sudo touch /var/db/xegfx/armed
sudo /usr/bin/kmutil load -b org.watchthelight.XeGfx

# 等 FB 就绪（最多 60 s）
for i in $(seq 1 60); do
  ioreg -l -w0 -c XeGfxFramebuffer 2>/dev/null | grep -q '"XeGfxFbReady" = Yes' && { echo "FB ready @${i}s"; break; }
  sleep 1
done
ioreg -l -w0 -c XeGfxFramebuffer 2>/dev/null \
  | grep -oE '"(XeGfxFbOpened|XeGfxFbReady|XeGfxFbModeReady|XeGfxFbPresented|XeGfxAperturePhys)" = [A-Za-z0-9]+' | head
```

**四条必须全是 `Yes`**（A-27 的接管态基线）。缺任何一条 → 停手报告，不要继续 arm。

### 4.3 arm AGDC（必须有 FB 才会成功；单次写是 one-shot，失败就重写）

```bash
for i in $(seq 1 10); do
  sudo sysctl -w debug.xegfx_agdc=1 >/dev/null 2>&1
  sleep 1
  s=$(sudo sysctl -n debug.xegfx_agdc 2>/dev/null)
  echo "arm attempt $i -> state=$s"
  [ "$s" = "1" ] && break
done
echo "--- fbmap ---"; sudo sysctl debug.xegfx_agdc_fbmap
echo "--- cmds ---";  sudo sysctl debug.xegfx_agdc_cmds
echo "--- log ---";   sudo log show --last 3m --predicate 'eventMessage CONTAINS "AGDC"' 2>/dev/null \
                        | grep -E "AGDC: (UP|slot table|no PCI)" | tail -5
```

判读：

| 现象 | 含义 | 动作 |
| --- | --- | --- |
| `state=1` + `slot table n=1 [0]id …` | **AGDC 起来了，且认到了 KMS framebuffer** | 继续 4.4 |
| `state=-1` + `no PCI device or no framebuffer yet` | 还是没匹配到 | 报 `ioreg -c XeGfxFramebuffer` 与 `ioreg -c XeGfxIntelKMSFramebuffer` 的计数，停手 |
| `state=-4` + `attach(...) failed` | PCI 设备不接受第二个 client | 停手，报原文 |
| `state=-5` | `AppleGraphicsDeviceControl::start` 失败 | 停手，报原文 |

### 4.4（可选，单独一步）补 K5

```bash
sudo sysctl -w debug.xegfx_agdc_k5=1
sleep 1
sudo sysctl debug.xegfx_agdc_k5_link debug.xegfx_agdc_k5_caps debug.xegfx_agdc_k5_why
```

**先把 4.4 的结果记下来，再去 4.5** —— 若 4.5 之后 WS 活了，要能分清是 AGDC 单独起作用还是 K5 也必需。

### 4.5 重启 WindowServer 并观察（60 秒判定窗口）

```bash
mkdir -p ~/xegfx-log/A-29
sudo log stream --predicate 'process == "WindowServer" OR eventMessage CONTAINS "IOPresentment" OR eventMessage CONTAINS "AGDC"' \
     > ~/xegfx-log/A-29/stream.log 2>&1 &
LP=$!
sleep 2
sudo launchctl kickstart -k system/com.apple.WindowServer
sleep 60
OLD=$(pgrep -x WindowServer); echo "WS pid=$OLD"
ps -o etime=,pid= -p "$OLD" 2>/dev/null
```

60 秒到点立刻判：

```bash
# 存活与重启次数
ps -o etime= -p $(pgrep -x WindowServer) 2>/dev/null
sudo log show --last 3m --predicate 'process == "WindowServer"' 2>/dev/null | grep -c "SIGABRT\|__assert_rtn" || true

# IOP 有没有拿到 AGDC（这一行是分水岭）
grep -E "agdc 0x" ~/xegfx-log/A-29/stream.log | tail -3
grep -E "transient surface .* not found" ~/xegfx-log/A-29/stream.log | tail -3
grep -E "A-?[Gg][Dd][Cc]" ~/xegfx-log/A-29/stream.log | head -5

# 若 WS 稳定存活，才采样（活不到 60 s 时任何计数都不算证据）
sudo sample $(pgrep -x WindowServer) 2 -file ~/xegfx-log/A-29/ws-sample.txt >/dev/null 2>&1
grep -cE "CA::OGL::SW|scanline|draw_polygon" ~/xegfx-log/A-29/ws-sample.txt
grep -cE "CA::MTL|MTLCommandBuffer|IOGPU|NVMTL|MetalContext" ~/xegfx-log/A-29/ws-sample.txt
```

## 6. 停机条件（照做，不要自由发挥）

1. **WS 活不到 60 秒、且仍在 crash-loop** → 立刻 `sudo shutdown -r now`。
   **不要让 watchdogd 到 120 s** —— 那会 panic（A-27 已吃过一次，把重编日志吃成 0 字节）。
2. 起来后**屏幕黑/花** → 立即重启；重启前先把 `stream.log` 与 `ioreg` 存到 `~/xegfx-log/A-29/`。
3. 第 6 条拿不到 `state=1` → **不要**为了凑成功去改 `AGDC_VENDOR_ID`、不要去改 `XeGfxDisplay` 的类名、不要改探针分。
4. 任何 `kmutil` 步骤后 `IGPUConsoleRange` 丢失 → 立刻回滚 AuxKC（`/Library/KernelCollections/AuxiliaryKernelExtensions.kc` 的备份），**不要重启**。

回滚（本关不涉及持久配置，除了 nvram）：

```bash
sudo nvram -d xegfx-disp-phase -d xegfx-disp-trial -d xegfx-disp-expose -d xegfx-disp-fail 2>/dev/null
sudo nvram xegfx-disp-phase=%00 xegfx-disp-trial=%00 xegfx-disp-expose=%00 xegfx-disp-fail=%01
sudo rm -f /var/db/xegfx/armed
```

源码回滚：把那一行宏改回 `"IONDRVFramebuffer"` 即可（无其他改动）。

## 7. 铁律（今天用血换的，全部适用）

1. 装 kext 用 `kmutil create -z`；**绝不** `launchctl kickstart -k kernelmanagerd` / `syspolicyd`（曾 panic）。
2. **`kmutil` 在 `/usr/bin`**，`/usr/sbin/kmutil` 不存在。
3. `kmutil` 打印 `rebuild done` 不可信 —— 唯一判据是 `kmutil inspect` 逐条 id 都在。
4. **不要在 boot 阶段推 stage 7 / accelfb**（A-25b 证伪：WS `push_surface` 断言 + 登录回环）。
5. `powermetrics` 的列是 `CPU ms/s`，**不是百分比**。
6. macOS 没有 `timeout` 命令（无 coreutils）；后台跑用 `( cmd > out 2>&1 & )`。
7. 掐本地 `ssh` **不会**杀掉远端循环；远端循环必须 `pkill -9 -f <标记>` 收尾，否则客户端名额耗尽，
   `IOServiceOpen` 要等 15 s 才返回 `0xe00002bc`，只能重启清。
8. `armed` 之后 120 s 内不要重启（护栏会判成"没活过来"并触发回滚）。
9. **判"是否软件合成"必须动画面采样**，静止桌面上两边都是 0，无判别力。
10. WS 活不到 60 s 时，`sample` 的任何绝对计数都不算证据（A-27 的 SW=89 就是假信号）。
11. 一次一个变量：4.4 的 K5 单独记，4.5 的结论才能归因。
