# Gate 7 · A-85 执行提示词：从 39.6fps 到 60 —— 拆 WS 侧的 20.7ms，并修掉 marks 间歇停摆

> 现状（A-84 落袋）：flip=1 开机默认，拖动 **p50 25.2ms = 39.6fps**（p90 41.6 / max 66），
> GPU 拖动 1625MHz（max 2150）、拷贝路径只有 800MHz。
> **60fps = 16.68ms = 2 个 vblank，还差 8.5ms。**
>
> 靶子已经定位（A-84 §3.4）：不在 `arm→latch`（4.53ms，且 E2 已证结构性不可用），
> 而在 **`performTransaction` 之外那 ~20.7ms**：A-82b §3.3 指到 **NVMTL 的三把锁**与
> **`CA::Render::Fence::resolve_batches`**。
> 同时 A-84 §5.1 留了一个旧症：**marks 通道间歇停摆**（`last_mark_age_ns` 读到秒级），
> 它既是残影的来源，也可能是那 20.7ms 里的一段等待。
>
> 本关目标：**把 20.7ms 拆开并砍掉 8.5ms**。三件事按序：
> ① 精确复测（flip=1 态下的新画像）；② 修 marks 停摆（顺带修残影）；③ 打最大那一块。
>
> 必读：`G7-A84报告.md`、`G7-A82b-诊断-占用率与时钟.md`、`G7-A77报告.md` §1（旧的 busy 表，已过时）。

## 3. P2 · 修 marks 通道间歇停摆（也修残影）

### 3.1 现象与已知

- `debug.xegfxaccel_surface_marks_dump` 里 `last_mark_age_ns` 多次读到 **秒级**（A-84 §5.1）；
- `surface_gpu_timeouts=134`；
- 停摆时 worker 从「等本帧 mark」回落「等整个 GT 空闲」，**失去"这块面装着本帧内容"的证据** → 残影；
- 残影在拷贝路径同样存在 ⇒ 是握手旧症，不是 flip 引入。

### 3.2 当前插件的真实状态（先确认，别照着 A-75 的假设做）

**A-80 版插件（现在装的）**：有 page-off + `nvmtl_internal_cb`，但 `surface_gpu_marks` 在
A-84 报告里被读成 0 —— **需要先确认它到底发不发 marks**（A-75 的插件发，A-80 插件可能没带那段）：

```bash
sudo sysctl -n debug.xegfxaccel_surface_marks_dump | head -5
sudo sysctl -n debug.xegfxaccel_surface_gpu_marks debug.xegfxaccel_surface_gpu_timeouts
grep -c "nvmtl_ws_mark_pending\|nvmtl_ws_mark_ready" <插件源码>   # 源码里有没有
```

### 3.3 三条可能的根因（按代码事实判，不猜）

| 可能 | 判据 | 修法 |
| --- | --- | --- |
| **A. 插件根本没发 marks**（A-80 版没有这段） | 源码 grep 计数为 0，`surface_gpu_marks` 恒 0 | 把 A-75/A-76 的 `nvmtl_ws_mark_pending/_ready` + XGDR 回落移植回来（A-81 已证这套能跑通） |
| B. 发了但 ready 丢（hold 泄漏） | `marks` 增长但 `waits` 远大于 `marks`，`timeouts` 增长 | 查 `nvmtl_internal_cb`（A-79 P1）是否误伤；查 internal cb 的 hold 是否被跳过登记却没跳过释放 |
| C. WS 某些帧确实不给某些面打标 | 停摆发生在特定 sid / 特定负载 | 记录停摆时的 sid 序列，判定是否与 page-off 的 demote 重叠 |

**门 P2**：`last_mark_age_ns` 在拖动中**稳定在 ms 级**（不再出现秒级）、`surface_gpu_timeouts` 不再增长、
**使用者目视残影消失或显著减轻**。

## 4. P3 · 打 P1 表里最大的那一块（本关冲 60 的主力）

按 P1 的结论选路（**只做最大的一块，别铺开**）：

| 若最大块是 | 动作 | 预期 |
| --- | --- | --- |
| **`CA::Render::Fence::resolve_batches` >3ms** | 查它等的是哪批 fence：若是 NVMTL 每次 submit 后的 wait，把 no-wait 哨兵确认在位（`/private/tmp/nvmtl-ws-nowait` 开机自建）、并统计每帧 submit 次数（A-73 是 3.4 次/帧，若能压到 1–2 次就是大赢） | 每次 submit 的 fence 解析成本 × 次数 ↓ |
| **NVMTL 三把锁 >4ms** | 找出争用者（同进程多线程？WS 的 render/update 线程），看能否把锁粒度放宽/改为无锁读（**只允许改插件，不改 accel**） | 锁等待 ↓ |
| **CA 自身绘制 >8ms** | 唯一零风险筹码：`reduceTransparency`（A-82 实测玻璃 +78%，你上次否决了观感）。**这次作为"到 60 的交换条件"重新摆到桌面上**，由使用者当面看两个画面定档 | 直接跨档 |
| **GPU 合成仍 >6ms** | Tile4 线（已冻结，黑屏未解）或 CCS | 见 A-83 换血 |

**门 P3（本关成功线）**：拖动 p50 **≤16.9ms（≥59fps）**；p90 ≤20ms；
画面（使用者目视 + 截屏 + 神奇效果）正常；30 分钟无 panic、无 WS 报告。
